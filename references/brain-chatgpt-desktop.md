# 外部 Brain 桌面通道｜可选兼容

仅在本次明确选择外部聊天并授权发送时使用；默认由当前 agent 完成前期。此页不提供个人默认模型、历史授权或已验证可用的桌面连接器。先读 [兼容工作流](upfront-workflow.md)。

## 准备与发送

1. 核实当前应用、模型、可用工具及允许范围。优先使用获准的 UI 工具；`scripts/chatgpt_ui.py` 只是可选历史辅助。工具或系统拒绝的操作不得改用 Python、Quartz、osascript 等途径绕过。登录、验证码及系统授权由用户处理。
2. 按实际项目填写 `project-request.json`，显式声明 legacy 模式，再由 `preproduction.py prepare` 生成消息。发送完整规则、请求与记录格式，只附必要项目资料，不夹带凭证和无关隐私。
3. 根据当前 UI 观察选择本次约定的模型与思考配置，确认附件上传完成、正文完整，再发送一次。记录会话、请求和调用次数；发送状态不明先查原对话，不重复发送。坐标、菜单、屏幕比例和剪贴板行为必须当场核实。

## 取回与续收

- 长包可请求一个 UTF-8 JSON 文件：同一 schema、`status=COMPLETE`、完整 manifest 和 records，回复中列文件名、记录数及 `execution_blockers`。下载不可用或文件不合格时，使用原 PARTIAL 分块流程。
- 等待时按当前工具能力检查是否仍在输出，不把空白、停止键变化或单次截图独自当成完成证据。用户正在使用前台时不抢焦点；取回须遵守当前工具允许范围。
- 保存下载文件或完整复制文本后运行 `assemble / validate`。保留原始响应；可在副本中删除已明确识别的 UI 附件引用标记，并记录处理，不能重写正文或猜补 JSON。
- PARTIAL 按实际 manifest 计算缺失 ID，用续收模板继续同一计划；格式错误、漏项或方案冲突使用修复模板，均计入原调用预算。修订记录按 [前期交接](brain-handoff.md) 合并为同一 revision，重新校验全包。
- 额度不足或约定配置不可用时保存已收块与待收项；未经授权不静默换模型、降低配置或另开收费通道。收到 COMPLETE 仍须确认记录齐全、解析成功；不代表生成或验收通过。
