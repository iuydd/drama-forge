# 视频提示词：Seedance 2.0 / 2.5 方言

只在用户把视频模型指定为 Seedance、并写进 `drama.json`（`video_dialect: "seedance-2.0"` 或 `"seedance-2.5"`，`profiles.video` 是账号里开通的 Endpoint/模型 ID）后使用（SKILL.md 硬约束 1b）。用户没指定就不走本文件，也不因为"Seedance 支持更长时长"自行换模型。内容原则仍按 [video-prompts-general.md](video-prompts-general.md)；一镜一人、接触同框、长镜头合并、节奏下限、视线、台词逐字、画面不出字这些硬规则和 H3 一样有效，本文只管 Seedance 的写法差异。接口参数与提交见 [providers.md](providers.md) §3。

## 1. 先确认的三件事

- **版本**：2.0 和 2.5 的时间写法、时长上限、任务类型都不同，名字相近也不能混用；决策记录写清用的是哪一版、Endpoint ID 是什么。
- **正文语言**：Seedance 用中文自然指令写正文（`prompt_lang` 设 `zh`），结构字段不像 H3 那样用英文。台词仍是剧本语言原文，不翻译。
- **生成方式**：本流程默认起始帧图生视频（起始帧 + 可选身份图/底板）；Seedance 的首帧、尾帧、参考图、参考视频、参考音频都放进同一个 `content` 数组，靠 `role` 区分。首尾帧能不能与其他参考混用按接口实测，不套用 H3 的互斥规则。

## 2. 两个版本的共同写法

**正文顺序**：主体 + 动作细节 + 场景 + 光色 + 运镜 + 画风 + 约束。起始帧已经给了的外貌、服装、场景装修不复述，只写这一镜的变化、必须保留的质感和容易漂移的锚点（video-prompts-general §2）。画风句按 [styles.md](styles.md) §1 选定的画风写中文版（例如"日式赛璐璐动画风格，线宽恒定、平涂色块"），全剧一句。

**素材绑定**：正文用 `@图片1`、`@视频1`、`@音频1` 指向本次任务实际送出的素材，编号按同类素材在 `content` 里的顺序递增（首帧、尾帧也各占一个图片序号，不跳号）。**每次提到这个素材都带上绑定和职责**：`@图片1 的女主`、`参考 @视频1 的运镜`，不能只在开头列一遍清单——只绑第一次、后文用裸名字，模型会把带绑定和不带绑定的提及读成两个人。一个素材只负责一件事（身份、地理或起始构图），写明它不控制什么。

**对白**：每句可辨台词整体写进花括号：`{夏树用日语说："逐字台词"}`，中文台词不加语言前缀，非中文台词在台词前写明语言（与 `dialogue_lang` 一致，G44 的精神）。同一句花括号台词在正文只出现一次，紧跟在说话人的可见动作后面；视觉描述里只写"口型同步"，不再抄台词。说话方式按 `dialogue[].emotion` 写在花括号外（`压低声音、慢慢地`）。

**声音**：每个音效事件写 `<声音>`，例如 `<纸页被推过桌面的沙沙声>`；配乐写 `（音乐）`，本流程配乐归剪辑层，所以正文写"全程无背景音乐"，不写 `（音乐）`。上游已经限定只有剧本台词时，在声音部分末尾合并写一次："对白直接从剧本首字开始；不生成额外人声、语气词或重复对白"。无台词镜写"全程无人说话"，否则模型会自己补人声。

**字幕与文字**：本流程画面不出字（硬约束 4），每条正文都写"全程无字幕、无对白文字叠加、画面中没有可读文字"，并且正文里不出现 `【】`（`【字幕】` 是开字幕的指令）。

**运镜**：写成中文自然句，含方向、幅度和速度（"镜头缓慢小幅推近到她手里的卡片"）；H3 的运镜词表和 Hailuo 的方括号指令都不属于 Seedance。锁定机位也要写出来（景别、机位高度、保持多久）。

**不采用的社区写法**：每段都加"同一角色，服装一致，发型不变""4K 高清，面部稳定"之类固定尾缀没有用，身份靠起始帧、身份图和锁面（`locks[].phrase`）承担。

## 3. 2.0 的差异

- 单镜直接按动作先后写。官方说明 2.0 响应"镜头1：""镜头2："序号、**不响应时间戳**；社区模板常见的 `0-3秒：` 写法与官方冲突，不用——照外部模板改写时把时间段改成动作先后顺序。
- 普通参考写"参考 @视频1 的运镜"；接着上一段实际结果生成时写"向后延长 @视频1"，同时用 `@图片1` 指向从该视频抽出的实际尾帧，说明它只是新段开场的可见状态（§5）。
- 手动时长 4–15 整数秒；`duration: -1` 让模型在 4–15 秒内自选，本流程固定镜长，不用 -1。

## 4. 2.5 的差异：时间段、任务类型、首尾帧

**时间段**：2.5 支持整数秒时间段写法 `[0:00–0:03]`，段与段不重叠、不留空，最后一段的终点等于镜长（general §4 的分段算术）。时间段只是先后提示，不保证动作准时落点；动作时间仍以审片实测为准（quality-contract）。

**任务类型**（写进 `shots.json` 本镜的 `seedance_task`，默认 `reference`；这是创作决定，不由脚本从关键词猜）：

| 任务类型 | 正文怎么写 | 接口硬条件 |
|---|---|---|
| `reference` | "参考 @视频1 的运镜/动作"或写清每个素材的职责；基于素材生成新视频 | — |
| `edit` | 直接点名 @视频1，写"保留 A、B，只修改 C"，不写成"参考它生成另一段" | `ratio: adaptive`、`duration: -1`、必须有参考视频 |
| `extend` | "在 @视频1 的基础上续写 N 秒"，再从输入视频的实际终点写唯一动作和新终点 | `ratio: adaptive`、必须有参考视频 |

正文写的是编辑、任务却标成参考（或反过来），2.5 会按语义复判并报任务类型不匹配。`edit` 时长 -1 表示保持原片时长，换更长的台词不会自动延长，放不下就回分镜；`extend` 的时长只算新增片段。

**首尾帧**：2.5 有 `first_frame`、`last_frame` 两个位置，各收一张。终点状态重要（落点精确的接触、物件落在指定位置）时可以加尾帧锁落点，尾帧按本镜 `end_state` 出图；但尾帧只说明"到哪"，中途观众必须看到的动作不能只靠插值兑现——那种动作要写清顺序，或挪到某一端，或拆镜（general §7c）。审片时终点对照 `end_state`，不对照尾帧。

**音色参考**：接口支持 `reference_audio` 时可以挂已授权的角色参考音频约束音色；参考音频来源、授权写进 `配音/参考/<角色>/README.md`，生成后听审确认，不因正文提到音频就当作已经绑定。

## 5. 从上一段实际结果续接

同一场、时间连续、地点与参考图链不变的相邻镜，用户若决定走续接（写进决策记录），下一镜同时绑定两项**真实**输入：上一镜实际生成的视频（承接动作速度、表演、运镜、声音空间）和从这段视频直接抽出的尾帧（固定下一镜第一帧的姿态、双手、持物、光线、构图）。二者缺一不可，不能用计划尾帧、起始帧提示词或文字描述冒充。

- 上一镜还没生成或没通过审片时，下一镜在 `shots.json` 标 `continuation_pending: true`，保留正文草案，不提交，不降级成独立生成。
- 续接不产生新的起点权威：下一镜的起点仍是 shots.json 的 `boundary.start`；实际尾帧与它冲突时先处理上一镜（重拍或改取用区间），不把漂移带进下一镜继续放大。
- 续接触发字样（2.0 的"向后延长 @视频1"、2.5 的"在 @视频1 的基础上续写"）按原字逐字写，不同义替换，不放进台词花括号里；字样只声明路由，起点、动作、终点照样要写全。
- 跨场、跨时间、换底板时重新起链。

## 6. 时长

- 2.0：4–15 整数秒；2.5：4–30 整数秒。本流程每镜秒数由 `shots.json` 的 `seconds` 决定，上限仍取 `drama.json` 的 `shot_seconds.max`；用户把 `shot_seconds.max` 提到 15 以上才能用 2.5 的长时长，长镜头合并规则（storyboard-keyframes §7b）不变。
- 30 秒容量不代表长台词自动恢复自然语速，对白仍按 video-prompts-h3 §3 的发声窗口算（语速用 `speech_rates`，首批 ASR 后校准）。
- 一次生成只装 `shots.json` 里的一个镜头，不把几个镜头打包成一次多镜生成：本流程的审片、取用区间和剪辑都按镜头记账（review.json、cut_order），打包后无法逐镜审片和重拍。
- 接口返回的 `duration` 是按帧数向下取整的近似值，时长以 `ffprobe` 实测为准。

## 7. 与本流程机械门的关系

`shots_tool.py` 的 G09、G10、G17、G44 目前按 H3 的 `<d>[语种] …</d>` 标记查台词，`produce.py` 只对接 H3 中转。用 Seedance 前先确认门脚本已支持这种方言；未支持时 G09/G44 会对花括号台词报错，这是门脚本缺口，不是正文错误——记入决策记录，改用人工逐字核对台词（剧本原句与花括号内逐字相等），不能靠把台词改写成 `<d>` 格式去消门。提交走 `providers.py`（[providers.md](providers.md)），仍守串行、先入账后轮询、POST 不自动重发。

## 8. 自检

1. 版本、Endpoint、任务类型都来自用户指定和决策记录，不是自选。
2. 每个 `@图片N`/`@视频N` 编号与实际送出顺序一致，每次提及都带绑定和职责。
3. 每句台词在花括号里逐字等于剧本，只出现一次；非中文台词写了语言。
4. 写了"全程无字幕、无对白文字叠加、画面中没有可读文字""全程无背景音乐"，正文没有 `【】`。
5. 2.0 没用时间戳；2.5 的时间段不重叠不留空、终点等于镜长。
6. `edit`/`extend` 的比例、时长和参考视频满足接口硬条件；续接两项真实输入都在，或标了 `continuation_pending`。
7. 一镜一人、视线、节奏下限、一镜一个主变化照 H3 的同一套规则过一遍。
