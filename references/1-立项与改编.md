# 阶段手册 1：立项与改编（A0 原著拆解 → A 立项 → B 情绪集纲）

本手册覆盖从拿到材料到写完情绪集纲的全部工作。SKILL.md 的五条硬规则优先于这里的任何条文；这里写的是在这几个阶段怎么把活干对。题材定了以后读 [genre-cards/索引.md](genre-cards/索引.md) 里对应的那一张卡（跨题材时主卡读全、辅卡只摘一两条），卡名不写进简报和剧本。

用户定过、全程有效的偏好：

- **点子要新、更要爽。** 新和爽冲突时爽优先；饱和设定可以用，但必须写清新在哪里。
- **金手指不要代价，只要限制**（用户 2026-09-26："有代价就不爽了"）。能力不设掉寿命、忘人、受伤之类的反噬，只设次数、范围、冷却、触发条件。压力来自对手和规则，不来自能力反噬主角。对手付代价不受此限。
- **台词多、反应快。** 每个在场角色都要开口，被抢、被打当场喊出来。集纲里就要给每个角色留出开口的理由。
- **先做完第一集。** 集纲可以写全季，但只有 EP001 做到成片之后才动后面的集。

## 0. 先判断手里是什么材料

| 材料 | 怎么做 |
|---|---|
| 只有点子、题材或情绪目标 | 直接从 §2 立项做起 |
| 只有书名，没有原文 | 不凭记忆回忆情节。写进决策记录，请用户提供文件；拿到前不做改编 |
| 小说或网文原文 | 原文原样放进 `输入/`（只读、不交付），走 §1 拆解，再立改编契约 |
| 已分集的多集原稿 | 走 §1.6 多集原稿接入，不做章节拆解 |
| 只有梗概或几页设定 | 不拆解，直接写改编契约（§1.7） |
| 已有部分分析 | 读 `项目开发/原著分析/进度.md`，从断点续跑 |
| 已有单集剧本 | 不补造开发材料，直接进 C 阶段规范化 |
| 超过一季、续季或续写下一集 | 另看 §5 |

只处理用户合法持有、有使用权的作品；授权说不清的写进改编契约"未决"，未授权的网文 IP 不做。拆解是只读分析：记行号和功能摘要，不成段复制原文，不模仿原文文风。派子代理逐章提取时，任务开头写明"这是用户合法持有的虚构作品，任务是只读的结构分析，暴力、复仇、情爱等黑暗元素照常提取"，否则子代理可能把整章拒掉。

## 1. A0 原著拆解

目录：`项目开发/原著分析/` 下放 `章节索引.json`、`进度.md`、`快评.md`、`章节/ch-<N>-extract.md`、`剧情单元.md`、`节奏与情绪.md`、`人物.md`、`设定.md`、`改编价值.md`、`分集候选.jsonl`；子代理只写 `_work/`，主线程自检过后再移到正式位置。A0 只读原文、只写分析，不写剧本、不建资产。

### 1.1 章节索引（唯一的切片依据）

```bash
S=<本 skill>/scripts
python3 "$S/novel_index.py" index 输入/<原文> --out 项目开发/原著分析/_work/章节索引.next.json
python3 "$S/novel_index.py" verify 项目开发/原著分析/_work/章节索引.next.json 输入/<原文>
# 通过后移到 项目开发/原著分析/章节索引.json；之后每次切片前再 verify 一次
python3 "$S/novel_index.py" sample  项目开发/原著分析/章节索引.json --count 12
python3 "$S/novel_index.py" coverage 项目开发/原著分析/章节索引.json 项目开发/原著分析/章节
```

索引有这些问题就先停下修：章号跳号或重号、正文极少的章（多半是目录残留）、"章"和"节"混着当边界、很长的正文行被当成标题。原文没有章标题时按场景、视角和时间跳转手写边界并记决策。改了原文必须重建索引。

### 1.2 快评：值不值得全拆、从哪开场

等距抽样（默认 12 章，首尾必取）。`快评.md` 第一行写覆盖率（"读了 340 章中的 12 章"），然后六段：

1. 故事框架：升级流 / 复仇线 / 单元剧 / 多线交织 / 蜕变成长，判不出就写判不出。
2. 抽到的每章归为"能直接拍 / 要换载体 / 只能靠文字"，写各占几章。
3. **开篇替换点**：短剧第 1 集从哪一章的哪个时刻开始。找第一个看得见、当场发生、主角必须做选择的转折，它通常不在第一章。写清它之前观众必须知道什么、开场后怎么在当下补进去（台词、物件、动作，不插回忆）。这里就要按 §3.1 想好"开场 30 秒观众怎么看懂核心设定"。
4. 制作负担：最多几人同框、几个不重复空间、有没有群戏、特效、可读文字、跨时间造型。
5. 三处最大改编风险，具体到哪一章哪个功能。
6. 分集候选量级（"约 20–30 集"），写清从几章推出来的。

拆多少自己定并记决策：默认全拆；书很长而本次只授权一季时，拆到覆盖本季所需的剧情单元再多一个单元余量。"只能靠文字"过半或找不到开篇替换点，标"改编风险高"，立项候选里放至少两个大改方向（换切入点、换主视角）。

### 1.3 逐章提取

每章一份 `章节/ch-<N>-extract.md`，`<N>` 用索引的 sequence。五节：

1. **概要**：3–5 句，说这一章让谁的处境、认知或筹码变了。
2. **情节点**：每点一行，格式 `P1 类型 | 白描 | 涉及：称谓、物件、地点 | 功能：这一步改变了什么 | 行：812–815`。类型只取行动、对话、信息、转折、铺垫、兑现、状态；约 150–200 字原文一个点。
3. **载体记录**：表头 `| 关键信息 | 原文载体 | 通道 | 对读者的作用 |`，通道是可见行动 / 对白 / 心理叙述 / 旁白 / 信息密度。这是后面判断要不要换载体的原始数据。
4. **出场人物**：称谓原样记，不跨章归并。
5. **未决项**：判断不了的指代和矛盾。

白描只写原文写出来的可观察事实。写"林风三招击败对手，围观者倒吸一口凉气"，不写"林风展现了实力"；写"管家把旧钥匙放进抽屉最里层"，不写"埋下伏笔"。等级、数值、谁对谁说了什么这类硬事实必须能回到白描或原文，回不到就写"原文未明确"，不用题材惯例补。

子代理每批 5–8 章。落盘后主线程自己核：情节点行数、每点都有"涉及"和"功能："、类型在七种之内、行号落在本章范围内、载体记录至少一行数据；再每章随机抽 2 条情节点按行号回读原文，对不上整章重做。失败重试一次，仍失败标 `跳过` 写进 `进度.md`；跳过超过 3 章或全书 5% 就由主线程补做，不进下一步。跳过的章要写进之后每一份聚合产物。

### 1.4 剧情单元、人物与设定

只读提取文件聚合，不回头重读原文。

- **剧情单元**每条六项：标题、章节范围、进入状态（谁知道什么、谁有什么筹码）、核心冲突（具体对象 + 具体事件）、付出了什么、出去状态。上一单元的出去状态要等于下一单元的进入状态，对不上就是漏了单元或边界切错。一个单元要有独立目标、具体对手、自己的紧张和缓和；"获得神器"是事件，"成长之路"是主题，都不是单元。归不进的情节点列进散落清单，不硬塞。
- **`节奏与情绪.md`**：关键信息怎么推进、情绪触动点在哪章、连续三章以上没有触动点的段落（改编时优先合并或砍掉）。
- **人物**一人一实体：专名可以合并；绰号、"姓 + 头衔"要有原文同指证据才合并；"红衣女子""家主"这类描述性称谓一律不合并。并错的代价远大于分开。
- **设定**从原文提及归纳，每条标出现在哪几章，标不出的删掉。

### 1.5 改编价值与分集候选

以剧情单元为对象，每个单元归入一类：**能直接拍**（功能由可见行动、对白、空间关系承担）/ **要换载体**（必须写出新载体，写不出就降级）/ **只能靠文字**（长段内心权衡、叙述性诡计、靠信息密度堆的爽感；明说放弃了什么，并写试过的两种新载体为什么不行）。含改编契约"不可改承诺"的单元不能判"只能靠文字"。

换载体逐单元写：原载体 → 新载体（具体的动作、物证、空间关系、对白策略或第三方反应）→ 保住了哪些功能 → 改变或失去了什么。检验只有一条：观众不需要旁白就知道发生了什么。

分集候选按局部戏剧结果切，不按章号或字数平均切。每条要答：进入时观众已知什么、本集兑现了哪一部分、出去时留下什么具体的决定或危险、下一集要继承哪些事实。`分集候选.jsonl` 每行一条，字段至少有 `candidate_id`、`story_units`、`chapter_range`、`screen_judgement`、`entering_knowledge`、`promise_paid`、`exit_pressure`、`inherited_facts`、`carrier_change`、`production_load`、`status`。

最后在 `改编价值.md` 开头对照快评，写出哪些判断被推翻；交接摘要（拆了多少章、跳过哪些、三类各多少单元、切出多少候选集、三处最大风险）写进决策记录。

### 1.6 多集原稿接入

工具只负责精确定位和防重复，每集实际怎么分、讲了什么由你读了判断。

```bash
python3 "$S/episode_intake.py" index 输入/<原稿> --out 项目开发/原著分析/分集索引.json
python3 "$S/episode_intake.py" manual-index 输入/<原稿> <边界.jsonl> --out 项目开发/原著分析/分集索引.json   # 自动识别不对时，每行 {"episode_id":"EP002","line_start":58}
python3 "$S/episode_intake.py" verify 项目开发/原著分析/分集索引.json 输入/<原稿>          # 每次切片前跑
python3 "$S/episode_intake.py" slice --out <输出> 项目开发/原著分析/分集索引.json 输入/<原稿> EP001
python3 "$S/episode_intake.py" progress --batch-size N <索引> 输入/<原稿> <集记录>
python3 "$S/episode_intake.py" merge --out <输出> --batch-size N <索引> 输入/<原稿> <本批记录> <当前集记录>
```

`index` 认短独立行的 `第N集`、`第N集 标题` 和 `# EP N`。集与集之间夹的制作说明会被并进前一集而不报错，所以每集都要读首尾几行确认边界。一次只读当前批次的切片，每集读完先落一条记录再读下一集；中断后以磁盘上已完成的记录为准重列待做集。

规范化成 `EPxxx/剧本.md` 时只改格式、不改台词内容，完成后逐句比对，决策记录写"台词逐字一致 N/N 句"。台词语言和 `dialogue_lang` 不同时按目标语言母语口语本地化。集纲从原稿反推，反推不出的格子记进改编契约的"原稿缺口"，不自己编剧情补。

### 1.7 改编契约

模板 `assets/templates/改编契约.md` → `项目开发/改编契约.md`。分析是候选，契约才是决定；定下的内容投影进系列简报，下游按简报对账。每一项决定写进决策记录。

| 类别 | 处理 |
|---|---|
| 不可改承诺（核心关系、关键选择、结局含义、必要世界规则） | 保持事实与功能；每条写明落在第几集、观众从哪个画面得到，或延后到第几集；延后到授权集数之外的，汇报里列"未兑现" |
| 可换载体（叙述顺序、场景、配角、信息出现方式） | 可压缩合并，记下替代关系 |
| 可删冗余（重复说明、走路程、没有新状态的复述） | 删，写明没损失什么 |
| 未决（原著矛盾、授权不清） | 保留问题，不替用户定案 |

**先删线，再合并人物。** 删一条线前问：它是不是别处铺垫或兑现的来源？主角是不是只靠它拿到证据、盟友或技能？它推进主线还是只让世界显得大？它是不是某个"观众知道、主角不知道"落差的唯一来源？删了会留下多少孤儿铺垫？最常见的错是删了慢线、留了好看的线，而慢线恰恰装着快线成立的条件。删线时把它承担的功能逐项标"一起删"或"转给谁"。

**合并人物**要功能能被同一人的目标、知识和关系位置自洽承担：合并后会不会提前泄密、对抗会不会消失、某次背叛或牺牲会不会失去分量。**合并场景**要求时间地点能连续、两个议程能同场碰撞、不改变因果顺序。

**原著里"知道、回忆、解释"的内容**，依次尝试换成：行动后果（直接用旧钥匙开门）→ 可争夺的证据（字后期叠加，手机屏幕背对镜头）→ 空间行为（谁挡出口、谁够得着证物）→ 对话策略（试探、逼供、拒绝）→ 台词明说规则 → 最后才是 `[OS]`/`[VO]`。倒水、走到窗边这种不改变局面的动作是假运动。

**压缩后查因果链**：原因 → 人物理解 → 选择 → 对手反制 → 可见后果 → 新压力。删掉的段落如果承担"人物为什么相信""道具怎么到手"，要补一个等价且可见的起因拍。

原著写法和硬规则冲突时的改法：倒叙和回忆章节改成顺叙，前因用当下的物件和台词交代；长段内心独白改成上面的载体；叙述者交代世界观改成一场一条规则、一句台词讲清；系统面板和信件改成后期叠加；群戏改成具名个体的反应镜和两人接触同框；人物或法宝凭空出场，先补起因；慢热开篇从开篇替换点进入；真实宗教神佛和未授权 IP 换成原创设定。

**回原文取细节**：用事件锚点检索（"角色名 + 后院药炉 + 当众被夺"），不用能力名、境界名这类会命中几十处的概念词；命中后回读原段落；核对片段所在位置的知情状态是否超前于本集，超前的只能作风格参考。回原文只是把已定的事写具体，想加好看的段落先改契约和集纲。

**对标作品只学机制**：写一张去掉人名和原句的机制卡（要解决的问题、观众当时的状态、可选机制、可见效果、适用条件、失效边界、不许照搬什么）。离开人名和专有设定就说不清的，还不是可迁移的手艺。

## 2. A 立项：出候选、打分、选一

产出 `项目开发/系列简报.md`（含 `## 立项候选`、`## 爽感打分`）和 `drama.json`（`style_preset`、`style`、`ai_label` 等）。

### 2.1 先查市场、先写现实之气

读 [market-hits.md](market-hits.md) §1–3（修仙另读 §4），定首发平台和形态（真人 / AI 仿真人 / AI 漫剧，对应 `style_preset`），列 2–3 个可对标的"题材 × 金手指 × 形态"组合及长青度。长青的是自带可升级进度条的金手指（系统/图录、废柴 + 外物、血脉数值、团宠靠山、穿越种田科举）；隐藏大佬亮身份、一次性爆发、借来的强多是昙花一现，要么按单部规划，要么补一条每季可升级的进度条。

再用一句话写出观众在现实里受的哪种气（被 KPI 压、被亲戚比较、被前公司轻视），越具体越好。

### 2.2 出至少 6 个候选

- 两两机制不同：主引擎（见下表）不重复；"主角多一个感知能力"类最多一个。
- 至少覆盖规则类、身份与关系类、世界观或职业类各一个。
- 主引擎和最近三个项目不同，候选表下写一行"近三项目：<路径>=<主引擎>"。
- 用户给了点子，算一个候选，另补至少 5 个对照；用户点名要饱和设定就照做，写清新在哪里。
- 改编项目：原著核心设定算固定候选，另补的改成同一原著的不同改编方向（换切入点、换主视角、换主爽点类型）。

**饱和设定**：看破谎言、摸物知价、挨打到账、强制说真话、短时回溯（这五个我们自己用过）、读心心声、系统面板签到、重生复仇开局、赘婿战神退婚、霸总傻白甜、隐藏大佬亮令牌、穿书知结局。这些都是"读取真相 → 当场揭穿"的形状或用烂的开局。用了就在"新在哪里"一栏按格式写：「新内容的类型｜EP00x 第几场｜观众看见的那个画面｜老路数在同一处会怎么演」。新内容的类型至少一种：新规则或新限制、新使用场景、新视角、新兑现方式、反派反制循环、和另一引擎的新组合、新世界观或职业承载。这句话搬到别的候选上也成立，就是套话；只换能力名或换皮不算新。

**同质化测试**（任一条命中先补新内容再打分）：能压成"主角多了 X 能力所以当场打脸 Y"；拿掉信息优势爽点就没了；一句话讲完设定路人的反应是"然后呢"；前 3 秒拍不出只有这个设定才有的画面。

**生成法**（每个候选标用了哪一两种，候选之间尽量不同）：反转常识；能力有边界（限制内想办法赢）；配角职业当主角；爽点挪到规则漏洞；限制越狠越爽；身份或辈分错位；现实制度搬进奇幻世界；观众全知反讽；组合倍率爆表；反向目标（主角想输、想被开除，越努力越成功）。

**主引擎**（爽靠什么触发，不需要感知外挂）：迪化（旁人脑补抬轿）、苟道（越想低调越藏不住）、规则漏洞与合规反杀、追放崩塌（主角走后原集体一样样出问题）、自食其果、身份辈分错位、集体翻盘、限制内取胜、资源反差经营、职业手艺。

每个候选写一行：一句话钩子｜**开场 30 秒观众怎么看懂核心设定**（§3.1）｜主引擎 / 第一次兑现是什么｜秘密 + 时钟 + 见证者（观众先知道什么、什么时候必须揭、谁在场看）｜新在哪里｜对标组合 / 长青度｜生成法｜快筛分。

### 2.3 打分选一

爽感检查表每项 0/1/2 分（2 = 明确且能在画面里核对）。★ 项 0 分直接淘汰；◆ 是快筛项。

| 组 | 项 |
|---|---|
| A 点子 | A1★◆ 新在哪里成立、过同质化测试；A2◆ 现实之气说得具体；A3◆ 有秘密 + 时钟 + 见证者；A4◆ 拿掉能力和信息优势，爽点靠规则、身份、关系仍成立；A5◆ 主引擎和近三项目不同；A6 可生成（见 §2.4 预算）；A7 有长青先例；A8 平台与形态匹配 |
| B 第一集 | B1★◆ **开场一个不靠字幕就看得懂的冲突画面，30 秒内观众看懂核心设定**；B2 EP001 前半段有第一次可核对的小兑现；B3 决定胜负的证据或动作画面里读得出；B4 受气有具体物件和见证者，憋屈不超过半集；B5 前 30 秒观众已知道主角的秘密 |
| C 系列（集纲写完后复打） | C1★◆ 每次兑现反派失去可核对的东西；C2 具名旁观者，改口有理由；C3 以弱胜强，赢在布局、规则或关系；C4 看见底牌到兑现不超过一集；C5 每集新问题从兑现里长出来；C6 打脸层级逐级升，至少一次自食其果；C7 兑现方式轮换；C8 反派有目标、会反击、不降智；C9 有一条情感线；C10 每次赢都带出新问题 |
| D 情绪 | D1 每集有一个会被截图转发的瞬间；D2 规则一场只讲一个、一句话讲清 |

流程：每个候选先打 7 个 ◆ 项（满分 14）；另派一个没参与出候选的子代理，看删掉分数的候选表盲打同样 7 项；按两份之和排名，任一份低于 7 的不算进 6 个。前三名补一张差异表（主角惯常策略、对抗机制、退出成本、引擎何时耗尽、主要制作负担、会牺牲什么），如果三列只差职业、地点或名字，回去重出。入选点子全表打分（满分 50）：**≥ 37 开工，28–36 改弱项再打，< 28 换点子**；开工线和 ★ 项只有用户能豁免。分差 ≥ 2 的项按简报里的证据重查，解决不了取低分。

无人值守时按分数自选并记决策；用户要看点子时给前三名（钩子 + 分数 + 一句理由）让他挑。落选候选只作对照，以后要借用先改简报。

打脸层级用于 C6：L1 口头（不算兑现）→ L2 事实当场证明 → L3 失去钱、位置、权限 → L4 对方意识到弄丢了主角（后悔、求回来）→ L5 自食其果 → L6 旁观者集体改判（只作叠加）。前几集 L2，中段 L3–L4，大卡点给 L5。

### 2.4 选定后把点子落实

**四问**，答案落到动作和物件：观众替主角受什么气（"被删掉的署名""被推离桌子的椅子"）；观众盼着什么结果，落点是关系、位置还是认知；主角凭什么能做到，观众要在受气段之前或之中先看见一角；这一轮兑现多少、下一轮更大的期待是什么。

**选一个主爽点类型**：身份打脸 / 智斗复仇 / 能力碾压（默认只作辅类型）/ 资源升级 / 甜宠关系拉扯。先让观众认得回报会花在谁身上、什么场合，再让主角拿到能力，否则兑现不解气。

**一句话承诺**：当【主角】用【惯常策略】追求【当前目标】时，【对抗机制】迫使他【面对的核心困境】；系列反复兑现【观众回报】，直到【终止性转变】发生。终止条件要具体到可核对（"让那份名单被公开更正"，不是"变成最强的人"）。再补压力来源、对手凭什么真挡得住、主角为什么不能走开。

**对手卡**：目标、资源与权限、已知信息、方法、能造成的具体损失、对主角的误判、失败后学到什么、下一步策略、为什么没早点把主角按死。反派要有可执行手段（签字权、把柄、舆论、规则解释权），要会学习：第一次失败后看穿主角的办法，第二次改变资源或规则，第三次逼主角放弃旧优势。小反派一次打脸就退场；中反派至少交锋三次，其中要真赢主角一次；大反派先只闻其名。憋屈只能来自反派的手段和信息差，不能来自主角迟钝；主角被动挨打最多三个回合，第四回合必须改打法（假意认下、以身入局、主动设局）。

**装置条款**（异能、系统、重生、隐藏身份）：先写条款 DEV-01…：能力范围、失效条件、限制（次数、范围、冷却、触发条件）、可靠性。剧中披露可以晚、可以残缺，但不许先写出条款里没有的能力再回填，也不许在需要紧张的那集临时"今天用不了"。限制要观众看得见、能对账，"消耗精神力"这种看不见的量等于没限制。装置摆出选项，由主角在限制内选。三次节奏：第一次展示功能，第二次碰到限制，第三次主角创造新用法。先知型装置（重生、看过结局）要把未来信息切开：只知结果不知过程、只知旧版本（主角一行动时间线就偏）等，前世信息在当下用台词或物件交代，不插回放。会来回切换的状态（失忆、变身、隐藏实力）登记一张表：触发条件、各状态能做什么、观众靠什么画面分辨。

**人物**：主角和主反派写惯常策略、筹码、盲区、底线和一句偏颇但有来历的信念；前史只放在简报里供预测选择，不塞进首集台词。至少一条要在第一集画面里看得见：他在承受不该承受的东西、在替谁扛、有观众想借来用一次的本事。全剧具名角色一般不超过 12 个，新对手出场必须把压力往上推一档。

**可生成性预算**（简报里写一行，超了先改点子）：每集有台词的角色不超过 4 个，首场有名有姓的不超过 3 个；每集主场景不超过 3 个；核心冲突尽量落在两人之间，接触动作两人同框；不写要三人以上同时同框才读得懂的群戏；金手指的视觉表现不靠画面出字，规则靠台词说，面板和数字后期叠加。

**观众验证计划**：简报里写目标观众与平台、要验证的一个假设（"观众能理解主角为什么让步，并想看下一段"）、最早能验证它的片段、失败时改哪里。榜单和 AI 打分只是选题线索；没有真人反馈就写"观众未验证"，不因此停工。

## 3. 开场 30 秒：立项阶段就要写清楚

这是 SKILL.md 规则 1 在立项和集纲阶段的落点。上一次 EP001 的失败就是开场没人问"观众第一次看，懂不懂"。

### 3.1 立项时写一段"开场设计"

写进系列简报，也写进每个候选的那一行。必须回答四件事：**主角是谁、在哪、核心设定（装置或能力）是什么、她要什么**，观众在前 30 秒内全部知道。

- 核心设定靠**一个能看见的事件**交代：一个动作引发一个所有人都看得见的结果，再有人当场确认。例：她心里一句话响起 → 全家同时停手 → 有人小声问"你也听见了？"。
- 不靠字幕卡堆背景，不靠旁白介绍世界观，不从起床、街景、日常慢慢铺。
- 设定只讲当下看懂剧情所需的那一条规则；第二条规则留到它第一次起作用的那场。
- 默认 `opening_mode: story_driven`，从已有冲突开场；只有明确选定"获得能力"型故事才用 `power_acquisition`，让"遇险 → 得能力 → 当场生效"尽快发生。
- 从切入时刻里选压力已经启动、主角必须马上行动、旧办法眼看要失效的那一刻；切得太早变成准备工作，太晚丢掉关键选择。
- 闪回、闪前只在观众一眼分得清过去将来、不会把因果读反时用；做不到就按时间顺序讲。

写完用一个问题自测：把这段开场设计念给一个没看过任何材料的人听，他能不能复述出上面四件事？不能就改，不进下一步。

### 3.2 开头 1 分钟的参考节拍

| 时间 | 该发生什么 |
|---|---|
| 0–10 秒 | 反常或最惨的画面，让人问"为什么会这样" |
| 10–30 秒 | 当众受辱或死局，看得见谁在欺负主角、有谁在场；核心设定用 §3.1 的可见事件交代完 |
| 30–60 秒 | 第一次兑现，画面上看得见，只给一小口 |
| 集尾 5 秒 | 停在"下一秒就要发生"的地方 |

和 story_driven 开场冲突时，写"不适用 + 原因"，不硬凑遇险开场。

## 4. B 情绪集纲：每集一行

产出 `项目开发/情绪集纲.md`（模板 `assets/templates/情绪集纲.md`）。

| 受什么气 | 底牌与谁先知道 | 主角行动（可见动作） | 反派失去什么 | 兑现什么爽点 | 留下什么新问题 | 交接事实 |
|---|---|---|---|---|---|---|

每格写法：

- **受什么气**：具体动作、物件、人名，受气档位 1–3（口头轻视 / 当众失去东西 / 失去在乎的人或位置）。受气段结束前，观众要么已看见底牌，要么已看见主角在行动。
- **底牌与谁先知道**：默认观众先于反派知道；写清观众从哪个画面得知。
- **主角行动**：写动作不写功能。"她放下笔说'授权你自己给'"，不是"她夺回主动"。本集结果要追溯到主角的一次选择；外力送来的结果，要写清主角哪个动作让它现在到达、拿到后他做了什么。
- **反派失去什么**：钱、位置、权限、信用之一，画面或记录能核对。写不出说明整集只在受气，并入下一集或补一次小兑现。
- **兑现什么爽点**：兑现档位不低于受气档位。兑现要有前置的不公、主角可验证的行动、证据或第三方当场生效、对手可核对的损失、主角拿到新空间也背上新问题；只有"所有人震惊"而局势没变不算。兑现方式在证据反杀、原话奉还、局中局、第三方裁定、一通电话、当众公开之间轮换，同一种不连续两集。旁边写一句观众会打的弹幕（"活该！"），写不出说明这个点还不具体。用户点名的兑现是下限，不许降成握手言和。
- **留下什么新问题**：从本集兑现里长出来，不是新人物踹门。括号注明钩子型（揭示 / 反转 / 危机 / 时限 / 情绪 / 闯入 / 抉择），相邻两集不同，最后一集收束不留钩子。
- **交接事实**：只写下一集第一场要用的：位置、持物、谁知道谁不知道、进行中的动作。

整体要求：

- **EP001 这一行额外写"开场 30 秒"一格**，照 §3.1 写出那个可见事件，以及观众看完能说出的四件事。
- 每集都有一次可核对的兑现，最晚第 1 集前半段就有第一次；连续只挨打的时长单集不超过一半，跨集不超过一集。默认按免费看、广告解锁（IAA）写；付费门槛集只在用户指定位置设，停在反击出手前一瞬。
- 每集给台词留位置：在场的角色各自有开口的理由，被抢、被打、被戳穿的那一下有人当场喊出来。
- 用"所以 / 但是"朗读相邻两拍：只能用"然后"连起来的，缺人物选择或对手反制。
- 集纲只写这一集独有的事；人物弧线、装置条款写在简报里一次。
- 维护一张**信息权限表**（事实｜谁知道 / 误信 / 不知道｜观众何时知道｜可见载体｜改变谁的选择）。可见载体分三层记：看见了什么 → 直接证明什么 → 仍未证明什么；读心类装置听到的是"他这么想"，不是世界事实。主角每次"知道"都要指得出来源镜头。每次反转至少列出一个更早的线索位置。
- **铺垫台账**：`铺垫 ID｜首次出现（集-场）｜观众当时会怎么理解｜承诺回答什么｜计划兑现方式｜状态`。不改变任何人下一步的铺垫删掉。
- **机制循环**：同一套机制每次运行都要改变对手的认知、难度、范围、知情者或退路之一。观众能提前说出赢法、兑现变大而状态变化变小、对手为让机制生效开始变笨，出现两项就收束、改造或移交机制，不另开新线并接。同一个核心矛盾最多跑约 6 个回合；换单元换矛盾和对手，不换观众追的那口气，下一层对手是上一层背后的人。
- 集纲写完，回去复打 §2.3 的 C 组分数。

## 5. 长篇、续季与跨集记忆

超过一季、集数明显多于 6 集或续写下一集时加做：

- **按季规划**：简报 `## 季规划` 每季一行：大循环（机制 + 回报）、境界或地图、主要对手、这一季金手指多出的限制、季末大兑现、续季钩子。先写到第 3 季，后面只写方向。能续的判据是同一条规则下每季都能拿到更大的东西。
- **世界观扩一格**：新季的规则在上一季末以次要身份先出现一次。跨季线在铺垫台账标 `跨季`，每季露一次面。主角封顶后升级线交给弟子或搭档。
- **续季首集**：接住上季季末钩子；新观众靠当下行动和一两句台词看懂主角是谁、凭什么、在受什么气，不回放上季片段；§3 的开场 30 秒要求同样适用。
- **人物弧线**：每次碰到旧策略记一行"进入策略 → 压力测试 → 选择 → 结果 → 付出 → 下一次更难的测试"。长篇里主角至少一次"裂缝"和一次"不可逆选择"。只靠台词说"我变了"不算。
- **跨集记忆**：超过 12 集或有续季时建 `项目开发/跨集记忆.md`（模板 `assets/templates/跨集记忆.md`），6 集单季用简报加各集剧本的 `[连续性]` 段就够。只存后续决策要用的：人物当前目标与状态、关系与债、信息权限、铺垫台账、装置披露进度、精确交接（位置、持物、伤势、服装、时间、进行中的事）。每集剧本定稿后只更新变化的部分；记忆和剧本冲突时以剧本为准。伤势、失去的东西、公开过的秘密、已披露的条款不能无原因复原，要复原先改清单。
- **续写流程**：读决策记录、简报、跨集记忆和上一集 `[连续性]` → 逐项核对上集出去状态和本集进入状态 → 写集纲行 → 写剧本 → 剧本过审后更新记忆。做到第 3 集后检查一次机制是否耗尽。

## 6. 本阶段过关

- A0：逐章抽取和机械自检完成、改编契约写好，独立审查一轮。
- A：候选 ≥ 6、打分表在、入选点子全表分达到开工线；开场设计写清四件事；可生成性预算一行；`python3 "$S/project_tool.py" next <项目>` 不再指向 A。
- B：每格具体、反派失去非空、EP001 有"开场 30 秒"格；独立审查一轮，只拦会让观众看错、看不懂的问题。
- 两个阶段的开场设计都要能过 SKILL.md 规则 1 的盲看复述：没看过材料的子代理能说出主角是谁、处境如何、装置规则是什么。

python3 "$S/project_tool.py" init <项目> --title 剧名 --episodes N --dialogue-lang zh
