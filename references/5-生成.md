# 5 生成：通道、提交、收回、花费与分工

阶段 F–H 把参考图、起始帧、视频送去生成时读本文件。提示词怎么写不在这里（见 video-prompts-*、image-prompts）；审片怎么看见 production-and-review。

## 1. 底线（每条只在这里写一次）

1. **模型由用户指定。** 生成用的模型、档位、分辨率（图片、视频、超分、TTS、配乐）只能来自用户原话：当前会话里说的，或 `项目开发/决策记录.md` 里 `拍板人: 用户` 且抄了原话和日期的行。`drama.json` 里已有的值、`拍板人: 代理` 的行、模板默认、别的项目、本文件里的例子都不算授权。用户没指定的，列 2–3 个候选和单价交用户定，不自选、不擅自换。
   - 新项目 `profiles` 初始为空；每一项都要能指回决策记录那一行（写进 `profiles_source`）。
   - 镜头和参考图条目里不写档位与分辨率；`produce.py` 见到与 `profiles` 不同的镜头级/参考图级档位就拒绝提交，`profiles_source` 缺失只报 warn。
   - 换型号前把能力写进决策记录（时长区间、分辨率集合、参考方式及上限、是否同轨出声、正文长度上限），没写清的按"未声明"处理，不从模型名猜。
2. **付费接口每一批都要用户点头。** fal、可灵等云端通道的提交、重拍、测试、补超分，每一批都要用户在对话里明说同意；含糊的回复不算，拿不准先问。本地 h3studio 不花钱，在已授权范围内直接跑。
3. **并发永远开到最大。** 云端一批经用户同意后整批一起提交；本地 h3studio 按槽位数并发，有空槽才提交。
4. **POST 永不自动重发。** 提交前先写 `submission_intent`，拿到任务号写 `submitted`。断网、超时、5xx、响应里没有任务号，都可能已经受理并计费：先收回（§4），不重投。只有供应商明确给出终态失败，才在已授权的次数内重投。
5. **子代理不提交生成。** 子代理由 `isolated_agent.sh` 启动，拿不到生成密钥、带 `DF_SUBAGENT=1`，所有提交入口见到就拒绝。生成、mark、cut 只由主会话做。
6. **密钥只进环境变量**：`H3_STUDIO_TOKEN`、`FAL_KEY`、`KLING_API_KEY`、`MINIMAX_API_KEY`、`ARK_API_KEY`、`OPENAI_API_KEY`。不写进 `drama.json`、job 文件、账本、日志、提示词、git、回复或本 skill 的任何文件；job 的 `parameters` 出现 key/token 字样直接拒绝。
7. **全自动不弹权限。** 主会话和子代理的命令都不能触发权限确认：不写 `rm` 配变量路径或通配符（每次输出到新目录，或用 `/usr/bin/trash` 加字面路径）；不写前台 `sleep` 接命令（用后台任务或 until 循环）；不用 curl/wget（用 python requests）。
8. **不删产物。** 输出路径已存在就拒绝，重出开新 take，旧的留着。
9. **成功不等于合格。** 接口成功、文件在、哈希对，只说明任务执行了；像不像、演得对不对，照审片流程看。

## 2. 通道一览

| 通道 | 用途 | 档位（用户已定） | 价格 | 并发 |
|---|---|---|---|---|

| 本地 h3studio | 视频（本地方案） | `base50_sol`，`768p`（分辨率参数写小写） | 不花钱 | 同上，与图片共用槽位 |
| fal `minimax/h3-max-turbo/image-to-video` | 视频（云端方案） | `480P` | 优惠期到 9/30 为 $0.0125/秒，之后原价见 pricing 接口 | 一批全提 |
| fal `fal-ai/bytedance-upscaler/upscale/video` | 480P 原片超分 | 1080p、24fps、`enhancement_preset` aigc、`enhancement_tier` standard、`fidelity` high | 约 $0.0072/秒（pro 档 ×10，不许开） | 跟随视频批次 |
| h3studio `krea2` 系列 | 只当风格参考 | — | 不花钱 | 同本地槽位 |
| 可灵 `kling-v3` | 仅在用户点名时 | `std` 720p / `pro` 1080p | 按资源包 | 试用包上限 5 |

- **起始帧默认走本地 `qwen21`**（用户定：本地出图质量最好）。fal 出图（例如 `alibaba/qwen-image-3/edit`，约 $0.01/张）只在用户明确要求时用。
- **krea2 只当风格参考，不能挂底板。** 它把参考图当 STYLE reference、不照参考内容编辑，挂了身份图或场景底板也不会保住人脸和场景。`produce.py` 用 `style_only_profiles`（默认 `krea2`）识别这类档位。
- **fal 视频方案 A**：`drama.json` 写 `"video_provider": "fal"`、`profiles.video` 写端点 ID、`profiles.video_res` 写 `480P`、`"video_upscale": true`。`produce.py videos` 下载 480P 原片后自动提交超分：原片存 `视频/_src/`，成片音轨从原片 remux 回来。这套 aigc + standard 是用户看片后拍板的，换预设或开 pro 要用户点头。
- **fal 视频的硬限制**：时长只收整数 5–15 秒（镜头秒数向上取整，不足 5 取 5，剪辑按取用区间收）；`prompt_expansion_mode` 固定 `disabled`，否则逐字台词会被改写。
- **可灵**：型号按账户实测，返回 `model is not supported` 就报给用户选，不猜着换；时长整数 3–15 秒；`sound` 逐镜开关（有在镜台词开，心声和画外声标 `vo: true` 后期另配）。
- 单价以 `GET https://api.fal.ai/v1/models/pricing?endpoint_id=<端点>`（python requests）为准，本表数字只是 2026-09-26 的记录。

## 3. `produce.py` 用法

```bash
S=<drama-forge>/scripts
python3 $S/produce.py refs   <项目> [IMG-ID ...] [--retake]
python3 $S/produce.py frames <项目> <EP> [SID ...] [--retake]
python3 $S/produce.py videos <项目> <EP> [SID ...] [--retake] [--asr]
python3 $S/produce.py all    <项目> <EP> [--asr]    # 起始帧之后预演没放行就停，不提交视频
```

- 已有产物自动跳过，中断后重跑同一条命令即可；已提交未收回的同名任务会先收回，不重新提交。
- 命名：起始帧 `F_<镜>_t<take>.png`、视频 `V_<镜>_t<take>.mp4`；`--retake` 在已有 take 之后新开一个，种子随 take 变。
- **`--jobs`**：走 h3studio 时默认就是槽位数，`--jobs` 只能调小。走 fal/可灵时脚本默认逐镜，用户同意本批后把 `--jobs` 设成本批镜数（可灵不超过 5）一次提完。
- **提交前的预检**（不满足就拒绝并说明怎么补）：不是子代理；该集 `shots_tool.py check` 的 error 为 0；档位与 `profiles` 一致；视频还要预演放行，且每个要提交的镜所选起始帧有 `review_tool.py mark --frame-take N --evidence` 的目检记录、sha 等于当前文件。金丝雀例外：本次只提交一镜且本集别的镜都还没有视频。
- `--asr` 只记逐字差异、挑待审候选；差异要听审，不按分数自动花钱重拍。
- **停止条件**：项目根有 `STOP` 文件时，做完当前任务就停；`DEADLINE=YYYYmmddHHMM` 到点不再提交。已发出的任务照常收回。`STOP` 和 `DEADLINE` 只由用户删改，删了也不等于扩大原授权。
- **提交次数**按 `脚本/jobs.jsonl` 数（含 intent，覆盖所有通道）。挪走或改名文件不重置计数；不能靠改名、重置 take 或换模型绕过次数和成本边界。同一 `fingerprint` 在账本里出现第三次以上先停下诊断，不当作随机性继续投。
- 开跑前看一眼服务状态和槽位：`python3 $S/h3_client.py --root <项目> status`（读 `/api/status`，`capacity.slots_total` 就是并发上限）。
- **参考图随提示词一起送**：本地参考图、起始帧按 `data:<mime>;base64,…` 内联，送出前校验文件头与扩展名一致。每张参考写 `label`、`role`、`may_control`（这张图管什么）、`must_not_control`（不管什么），脚本按送出顺序把约束追加进正文。
- 全参数显式：模型 ID、时长、分辨率、比例、语言每次都写出来，不靠服务端默认。
- 底层 `h3_client.py image/video` 必须显式传 `--profile` 和 `--res`；平时只用 `produce.py`，由它从项目传入。

### 后处理与账本

审片门只认账本里有来源的文件（`collected`、`upscaled`、`derived` 三种记录），并核对提示词和起始帧生成后没改过。

- **fal 超分**：`fal_client.py` 收回超分结果时在账本 `upscaled` 记录里写 `sha256`。超分失败时成片位置先放原片并报错，经用户同意后补：
  `python3 $S/fal_client.py upscale --root <项目> --src 视频/_src/X.mp4 --out 视频/X.mp4`
- **本地后处理**（模糊烧进的字、裁切、调色）输出成新 take，再记一条 derived，沿用源文件任务号：
  `python3 $S/ledger_tool.py derive <项目> --src EP001/视频/V_X_t1.mp4 --out EP001/视频/V_X_t2.mp4 --note "底部烧进的字模糊"`
- **旧版超分记录缺 sha256**：确认超分后文件没再改过，再跑 `python3 $S/ledger_tool.py rehash-upscaled <项目>` 补指纹。
- 已收回的文件大小或内容和收回时不一致（被覆盖、被剪辑工具就地改写），先弄清手上是哪一版，不拿来源不明的文件进审片。

## 4. 断网、中断后收回

原则：先对账，再收回，最后才考虑重投。任务号在 `脚本/ids.log` 和 `脚本/jobs.jsonl`。

```bash
python3 $S/h3_client.py --root <项目> unresolved            # 列出结果未知的提交（所有通道共用一本账）
python3 $S/h3_client.py --root <项目> collect --job <任务号> --kind video --out <输出路径>   # h3studio；图片用 --kind image
python3 $S/fal_client.py collect --root <项目> --job <request_id> --endpoint <端点> --out <输出路径>
python3 $S/kling_client.py collect --root <项目> --job <task_id> --out <输出路径>
```

| 账本状态 | 情况 | 下一步 |
|---|---|---|
| `not_submitted` | POST 收到明确拒绝（4xx、`status_code` 非 0） | 没受理不计费。429 稍等后在授权次数内重投；其他 4xx 只改被拒的那一项（那句提示词、那张参考图） |
| `submission_unknown` / 未决 intent | 断网、超时、5xx、响应不是 JSON、没有任务号 | 可能已计费，会阻止本项目后续提交。到供应商任务记录里找，找到就 `reconcile --job` 再 collect |
| `submitted` / `download_failed` | 已有任务号，轮询或下载中断 | 按任务号 collect，不重新提交，不当作生成失败重拍 |
| `failed` | 供应商终态失败 | 技术失败在授权次数内原样重投；内容缺陷先改提示词 |
| 不变 | 未知状态、轮询超时 | 稍后再 collect |
| `download_failed` | 下载内容和扩展名对不上 | 再 collect；仍不对就查结果地址，不当作生成失败重拍 |

对账命令（`reconcile` 只记录人工核对结果，不会自动查询）：

```bash
python3 $S/h3_client.py --root <项目> reconcile --request-id <REQUEST_ID> --job <任务号> --evidence "供应商历史中核实的对应关系"
python3 $S/h3_client.py --root <项目> reconcile --request-id <REQUEST_ID> --not-submitted --evidence "<证据>"
```

- 先核账户、提交时间、类型、内容与输出目标。证据里不写 token。
- `--not-submitted` 的证据只收两种：存进项目 `脚本/` 的供应商任务列表导出或客服回复（覆盖 intent 前后各 30 分钟，写文件路径）；或决策记录里 `拍板人: 用户` 的行编号。"查不到""列表里没有"不算证据，不能据此断言未提交。
- 旧版 `post_failed` 记录没有 request_id，先与供应商历史核对，脚本不自动迁移或猜测。
- 不删账本、不伪造证据来解除阻断；账本损坏时先从备份或供应商记录恢复，恢复前不提交。

## 5. 花费怎么报

- **每批生成完就报**：本批、本集、本剧累计三个美元数；本地 h3studio 写 $0。
- **数字取账本**，不手写估计：按 `jobs.jsonl` 里本批收回的记录，秒数用计费秒数（`billed_seconds`，缺了用 `ffprobe` 量实际时长），乘 pricing 接口查到的单价。
- **视频和超分两项分开记**（例："480P 生成 12 镜 78 秒 $0.98，超分 78 秒 $0.56，本批 $1.54"）。重拍只花 480P 那部分的钱。
- 失败 take、补超分、测试都计入累计；查不到单价或对不上账时写"未知"并暂停付费提交，不声称脚本已封顶（脚本不做货币预算核算）。

## 7. 子代理：`isolated_agent.sh` 的角色

```bash
scripts/isolated_agent.sh <项目目录> <任务包.json | 任务书> [worker|reviewer|light|adversary|adversary2]
```

在 Bash 后台跑，不用 Agent 工具。

| 角色 | 做什么 | 模型 | 拿到什么 |
|---|---|---|---|
| `worker` | 写作、按审查改稿 | 不低于主会话（`DF_AGENT_MODEL` 只接受 opus / fable 系列，降级直接拒绝） | 公共底线 + 本阶段规则 + 任务书 |
| `reviewer` | C/D/E 独立审查，只出结论和修订要求 | 固定 Sonnet 5 medium | 同上，另加固定职责头：任务书里放宽、缩范围、预设结论的话不执行，原文记进审查文件 |
| `light` | 补账、格式、机械门修复、逐章抽取 | 固定 Sonnet 5 medium | 同 worker；要改剧情、台词、构图、镜头设计就停下交回主会话 |
| `adversary` | 提示词攻击：字面合规地做出最差成品，只交最致命 5 条 | 固定 Sonnet 5 medium | 只有攻击任务书，不给 SKILL.md、剧本、规则 |
| `adversary2` | 第 2 轮攻防，2026-09-27 起停用 | Opus 5.5 low | 同上 |

- 任务书优先用 `task_pack.py build` 构建成 `.json` 任务包；交给脚本时自动 verify，材料、模板或工具在构包后改过就拒绝启动；reviewer 用纯文本任务书会收到警告。
- 子代理看不到主会话上下文、CLAUDE.md、其他 skill 和 MCP，任务书要自带文件路径、阶段、验收标准和前情事实。
- 脚本清掉所有生成密钥并设 `DF_SUBAGENT=1`；任务书、输出、退出码、模型和子代理写出的审查文件 sha256 留档在 `审查/agents/<时间>-<角色>-<pid>/`。子代理不提交生成、不做 git；"不改 `scripts/`"是任务书约束，脚本不拦。
- 作者不兼任 reviewer：同一模型族可以一写一审，但必须是两个独立子代理。
- **Codex 运行时**：`isolated_agent.sh` 只调用 `claude`。在 Codex 里用 Codex 自己的子代理机制，按 §6 选模型，把本节的角色约束写进子代理的系统提示。
