# 观众验证与规则迭代

立项、首集预演、首集交付以及维护 skill 时读。复用系列简报、决策记录、模型观察和成片终验，不新建服务、评分门或强制多轮评审。

## 1. 先确定什么结果值得继续拍

在系列简报加一段“观众验证计划”：目标观众与平台、要验证的一个假设、最早能验证它的片段、已有预算与批次边界、失败时改哪里。例如“观众能理解主角为什么让步，并因尚未兑现的反击想看下一段”；不能只写“爽、吸引人”。

榜单和 AI 评分是选题线索，不是观众验证。保留既有候选与质量检查，但不追加模型投票来假装扩大观众样本。题材库的统计口径、日期、平台与形态不相容时，不拿排名证明当前点子更有潜力。

新项目在已有授权内优先完成首集或一个能闭合冲突的试看片段，再扩大后续集的付费生产；用户已明确授权整批连续制作时继续执行，不另加等待真人的硬门。没有授权的试拍、招募、发送、发布或投流不能自动执行。已有项目从下一次自然交付接入，不要求补齐所有历史验证表。

## 2. 用真实反馈区分三类失败

优先复用 G2 预演检验理解与节奏、用首集成片检验表演和声音。静帧预演不能证明动态动作、口型或听感合格。用户愿意提供反馈时，可请用户或少量目标观众不看剧情说明直接看片；先听复述，再问哪里想划走、为什么、是否想继续以及想知道什么。不给标准答案，不用诱导式“是不是很爽”。

记录在决策记录中：片段路径和版本/sha256、匿名样本数及招募来源、原话、退出或困惑时间点、实际看到后续的行为（如有）、修改决定。只问“想不想追”得到的是意愿，不是追更率；小样本只定位问题，不推算商业成功率。AI 扮演观众不算真人样本；创作者自己的意见与目标观众意见分开记。

| 观察 | 下一步 |
|---|---|
| 不知道谁对谁做了什么、为何行动 | 修对应信息或因果，在同一片段复测；不能靠介绍剧情消除问题 |
| 看懂了但不关心结果 | 回到主角诉求、兑现和悬念；不要先花钱提升画质 |
| 想看，但被声音、动作或切点打断 | 定位具体秒数修制作，不重写已奏效的剧情 |

同一核心问题经一次有针对性的修订仍重复出现，先比较换开场、缩小故事承诺或搁置候选的成本，记下选择，不无限精修。停拍或改动已锁定承诺超出授权时交用户决定；质量缺陷仍按原门处理。没人反馈就标“观众未验证”，继续授权内工作，下一次交付再利用自然反馈，不反复催问。

若有用户提供或已授权读取的平台数据，记录曝光口径、样本量、时间窗、流量来源和版本后再比较开头留存、完播与后续观看；同时换封面、投流和内容的结果不能归因给单项修改。不设置跨平台通用“爆款及格线”。

## 3. 交付时分开报告，不把 PASS 扩大解释

保留现有 `final_qa.py`、`next`、首行 `结论：PASS / REVISE` 和准入逻辑。以下是汇报口径，不新增 schema 或伪造脚本支持：

- **制作验收**：照抄当前文件对应的脚本与终验结果；存在文件不等于验收完成，草剪不算成片。
- **声音验证**：分别报告 `asr_ok`、`listen_ok`、`sync_ok` 与证据范围。任一为 null 就写明“声音验证未完成”，即使制作验收 PASS；真人听审仍按 quality-contract 执行。
- **观众验证**：写未验证，或“已收集 N 人对版本 X 的反馈：……”。反馈积极也不能称“商业验证通过”；上线数据只能支持其实际测量的指标。

复用账本与现有审查记录统计费用、成片可用时长、人工介入分钟和返工原因（剧情理解 / 视听缺陷 / 补账）。可用成片分钟按本轮通过制作验收且非草剪的输出计算，声音待验证数量并列报告；总费用须包含失败 take，未知价格不能当 0，分母为 0 时写“暂无可用成片”，不算比值。人工时间只用实际记录，不从聊天间隔反推。补账不算审查轮次也仍计成本。

## 4. 经验何时成为规则，何时退出

在现有模型观察里记录新旧写法各自的尝试数、成功与失败、模型/档位、镜型、素材版本、同时变动的条件。成功三次只能提出候选经验；没有可比对照就写相关性，不能写因果。优先利用已有素材，额外付费对照仍须在授权内。

维护 skill 时，每条新增或收紧的经验规则用一行写清：适用范围｜避免什么失败｜依据与反例｜增加的费用/耗时｜何时复核｜何时撤销或降回建议。默认在后续两集或下一次模型/档位变动时复核其适用性；这是复核节点，不是统计显著性门槛。

只在已有证据支持的范围采用，不能把某模型某镜型的修法扩成全局禁令。若没有减少原缺陷却持续增加返工，或已有更便宜且同样满足目的的办法，提出缩小范围或撤销的修改；保留旧记录与理由，不覆盖失败样本。预算、提交对账、如实汇报、素材指纹、必拍事实等底线不因收益统计而撤销。

生产中不自动修改 skill、门或记忆。维护修改必须已有用户授权，日期、理由与回退依据写在版本 diff 或维护记录；不要把“升级经验”当作放行失败素材的理由。
