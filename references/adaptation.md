# 改编：小说、网文与多集原稿

用户给的是小说、连载网文、梗概或已经写好的多集原稿，要把它做成 drama-forge 短剧时读本文件。它在阶段 A 之前加一个 **A0 原著拆解**，把长材料变成能被引用、能被反驳、能接着用的分析层，再立**改编契约**，然后照常走 A（立项与系列简报）→ B（情绪集纲）→ C（剧本）。

改编不是把原文缩短，也不是给原著套一层流行结构。目标是保住原材料真正承担的戏剧功能，再为竖屏短剧、单集边界和 AI 生成条件找新的载体。两条总原则：

- **分析是候选，契约才是决定**。拆解产物可以被推翻；改编契约一经写进系列简报，下游就按它对账。两者分文件存，推翻分析时不动已定的改编承诺。
- **原著事实是用户的契约**。原著的核心关系、关键选择、结局含义和必要世界规则不偷换；要改，先在改编契约里写明改了什么、为什么，记决策记录。

## 0. 与阶段的关系

| 阶段 | 改编项目多做什么 | 产出 |
|---|---|---|
| A0 原著拆解 | §4 的 S0–S5；多集原稿走 §5 | `项目开发/原著分析/` 下各文件 |
| A 立项 | 改编契约（§6）；premise-novelty 的候选改成"同一原著的不同改编方向"（premise-novelty §6 第 7 条）；开篇替换点对照 B1 前 3 秒钩子 | `项目开发/改编契约.md`、`项目开发/系列简报.md` |

| C 剧本 | 回原文取细节按 §7；多集原稿按 §5.4 规范化 | `EPxxx/剧本.md` |

## 1. 材料前提

- 只处理用户合法持有、有使用权的作品。授权说不清的，改编契约"未决"一栏写明，不替用户定案。未授权的网文 IP 改编是 market-hits §4.5 的禁区，不做。
- 拆解是只读的转化性工作：记定位、行号范围和去引用的功能摘要，不把原文成段复制进分析，不模仿原作文风生成新文本；需要证据时只引最短的必要片段。原文不进交付物。
- 通俗题材里的暴力、复仇、背叛、情爱张力和黑暗伦理是常规虚构元素，照常做结构化提取。个别片段处理不了就跳过并记录，不中止整章或整本；中止会让后面每个阶段拿到一份有洞却看不出洞在哪的分析。
- 派子代理逐章提取时，每条任务提示自带一段前缀：这是用户合法持有的虚构作品，任务是只读的转化性分析，黑暗元素照常提取。不带前缀，子代理可能把正常的戏剧情节误判为有害内容拒绝整章，主线程只看到一个空结果。

## 2. 入口判断

1. **只有书名，没有原文**：不凭书名回忆情节。没有原文就没有行号，没有行号的分析既不能引用也不能反驳。写进决策记录，汇报里请用户提供文件；在拿到原文之前不做改编，其他授权范围内的工作照常。
2. **有小说或网文原文**：建 `项目开发/原著分析/`，把原文字节原样复制到项目的 `输入/`（只读，不交付），跑 §4。
3. **有多集原稿**（已经分集写好的剧本、散稿、合订稿）：跑 §5，不走章节拆解。
4. **只有梗概或几页设定**：不需要 S0–S5；直接写改编契约（§6），不可改事实照样逐条落集。
5. **已有部分分析**：读 `项目开发/原著分析/进度.md` 从断点续跑，不重跑已完成阶段。
6. **已有单集剧本**：不为流程完整虚构分析，直接进 C 阶段规范化（§5.4）。

### 4.1 S0 章节索引

索引是唯一切片真源。每个阶段各自跑一次正则，会切出互相对不上的章节：第 47 章按一种边界提取、按另一种边界聚合，而且没人发现。

有配套脚本时（纯标准库的 `novel_index.py`，放在本 skill 的 `scripts/` 下）：

```bash
python3 "$S/novel_index.py" index 输入/<原文> --out 项目开发/原著分析/_work/章节索引.next.json
python3 "$S/novel_index.py" verify 项目开发/原著分析/_work/章节索引.next.json 输入/<原文>
# 通过后移到 项目开发/原著分析/章节索引.json；之后每次切片前再 verify 一次
python3 "$S/novel_index.py" sample  项目开发/原著分析/章节索引.json --count 12
python3 "$S/novel_index.py" coverage 项目开发/原著分析/章节索引.json 项目开发/原著分析/章节
```

没有脚本时手工建：用 `grep -n` 找出只占一整行、长度很短的章标题行（`第N章` / `第N回`，阿拉伯数字或中文数字含"千""两"），每章记 `sequence`（从 1 连续编号）、原文章号、标题、`line_start`、`line_end`、字数，再记整个原文文件的 sha256；每次切片前重算 sha256，不一致就重建索引，不沿用旧行号。

索引要检查的问题（任何一条命中就停下修，不带着错表进 S1）：
- 章号跳号（缺章或抓错标题）、同卷内重号、无法解析的章号；
- 正文极少的章（多半抓到了目录残留或卷首页）；
- 编号单位只认一种：一本书用"章"分章、用"节"分小节，就只按"章"切，"节"不算边界；
- 以章号开头但很长的正文行不算标题；这类行特别多，说明这本书标题确实很长，改成手写边界；
- 原文没有章标题时，按场景变化、叙述视角、时间跳转和行动因果手写边界，边界写进索引并记决策。

改了原文必须重建索引。行数变化会被 verify 报出；同行数的原地改写 verify 查不出，谁改原文谁负责重建。

### 4.2 S1 改编价值快评

回答"这本书值不值得全量拆、先拆哪几段"。用确定、可复现、首尾必取的等距抽样（默认 12 章，书很长或框架复杂就调大并写明）；抽到正文极少的章往后顺延一章并记录。快评只判断功能和载体，不写完整情节点表和人物表。

`快评.md` 第一行写覆盖率：`> 本快评基于抽样：读了 340 章中的 12 章（3.5%），章号见下表。结论是假设，不是结论。`之后固定六段，缺一段不算快评：

1. **故事框架**：从 §4.4 的框架表选一个；抽样判不出就写"抽样不足以判断"和原因。
2. **三类判定比例**：抽到的每章按 `能直接拍` / `要换载体` / `只能靠文字`（定义见 §4.6）归类，写出各占几章、分母是抽样章数。"只能靠文字"过半时直接写明。
3. **开篇替换点**：见下。
4. **制作负担量级**：最多几人同框、多少个不重复空间、有没有群戏 / 动作 / 特效 / 可读文字 / 跨时间造型；按项目 `style_preset` 估，未定时按两种画风各一句。对照 story-engine §1 的可生成性预算。
5. **三处最大改编风险**：具体到哪一章、哪个功能；"改编难度较大"对哪本书都成立，等于没写。
6. **分集候选量级**：按抽样里的戏剧结果密度给量级（"约 20–30 集"），写清从几章推出来的。

**开篇替换点**：改成短剧后第 1 集从哪里开始？找第一个可见的、有代价的、当场发生的转折——主角第一次做出要付代价的选择，而且这个选择拍得出来而不是想出来。它通常不在第一章。写清落在第几章（sequence）；它之前哪些内容观众必须知道、开场后怎么在当下补进去（台词、物件、字幕，不插回忆）；哪些是原著读者需要而短剧观众不需要的。它还要能过 premise-novelty §7 B1 和 market-hits §6 的开头 1 分钟结构；抽样里找不到就写进第 5 段风险。

**自动决定拆多少**（替代"停下问用户"，写进决策记录）：
- 默认继续全量拆解。拆解只花分析的算力，不调用付费生成接口。
- 书很长（例如几百章）而本次授权只做一季时，全量拆到覆盖本季规划所需的剧情单元再多一个单元余量，其余章节只保留索引和快评结论，后续季再接着拆；在 `进度.md` 写清拆到哪一章。[推断]
- "只能靠文字"过半，或抽样内找不到开篇替换点：仍按上一条拆，但在决策记录标"改编风险高"，并在立项候选里至少放两个大改方向（换切入点、换主视角）。
- 用户一开始就要求"一次拆完"时照做；快评照样要写，S5 要拿它回填对照。

### 4.3 S2 逐章功能提取

每章一份 `章节/ch-<N>-extract.md`，`<N>` 用索引的 sequence（多卷书原文章号会重复，sequence 不会）。第一行 `# ch-<N> <原文章标题>`，原文没有标题就只写 `# ch-<N>`，不自拟。其下五节，固定顺序：

1. **概要**：3–5 句，说这一章让谁的处境、认知或筹码和上一章不一样了；不是缩写剧情。
2. **情节点**：每点一行，四段用 `|` 分隔：

   ```text
   P1 类型 | 白描 | 涉及：称谓、物件、地点 | 功能：这一步改变了什么
   ```

   `P<n>` 与类型之间、类型与 `|` 之间各一个半角空格（下游按字面形状 grep，写成全角空格这一行就不算情节点）。类型只取：行动、对话、信息、转折、铺垫、兑现、状态。功能写权力、信息、关系、暴露、资源、时间或代价至少一项的变化；写不出功能的多半不是情节点。"功能："四个字只在这里用，别处要说就写"作用"。密度大约 150–200 字原文一个点，同一目的的连续微动作合并成一点，不为凑数拆步。
3. **载体记录**：表头 `| 关键信息 | 原文载体 | 通道 | 对读者的作用 |`，每章至少一行数据，常见 2–5 行。关键信息 = 本章必须让读者知道、误判、期待或确认的事；原文载体 = 作者用了什么事件、对话、反应、细节、误导、回扣；通道 = 可见行动 / 对白 / 心理叙述 / 叙述者旁白 / 信息密度；作用 = 好奇、期待、压抑、爽、心疼、紧张、甜、热血。这一栏是 S5 判断要不要换载体的原始数据；过渡章也要写它维持了什么期待或冷却了什么情绪，不写"无"。
4. **出场人物**：称谓原样记，附本章内的作用；不做跨章归并（归并是 S4 的事）。
5. **未决项**：无法判断的指代、时间关系或矛盾，逐条列；留白比猜测便宜。

**白描只写原文写出来的可观察事实**，不写心理断言、作者意图，不用叙事框架词概括：

| 不行 | 行 |
|---|---|
| 通过对话，他得知对手在国外训练 | 教练告诉他，对手在国外训练 |
| 林风展现了自己的实力 | 林风三招击败对手，围观者倒吸一口凉气 |
| 她感到心碎和愤怒 | 她目睹男友与人拥抱，表情由刺痛转为冷漠 |
| 这一章为后文埋下伏笔 | 管家把一枚旧钥匙放进抽屉最里层，没说用途 |

原文本身是内心独白时，写他想的那句话（"他在心里说这次真的完了"），不写"他感到绝望"。左列的问题是把结论写在了证据的位置上：S3 以后每次聚合都离原文两跳，证据本身是结论，就再也核对不了。**硬事实必须能回溯**：等级、数值、距离、势力数量、谁对谁说了什么、某人出现在哪几章，写进后续产物前必须能回到某条白描或原文，回不到就写"原文未明确"，不用近义项、别处的例子或题材惯例补；相邻实体的属性不互相挪用（坐骑的等级不是骑手的等级）。

**机械自检**（主线程在文件落盘后跑，不信子代理自报；命中即算失败）：

```bash
F=项目开发/原著分析/章节/ch-${N}-extract.md
P=$(grep -cE '^P[0-9]+ ' "$F")
grep -cE '^P[0-9]+ [^|]+\|[^|]*[^|[:space:]][^|]*\|[^|]*涉及' "$F"   # 必须 == $P（每点都有白描和涉及）
grep -cE '^P[0-9]+ .*\|.*\|.*\|[^|]*功能：' "$F"                     # 必须 == $P（每点都写了功能，全角冒号）
grep -hoE '^P[0-9]+ [^|]+' "$F" | awk '{print $2}' | sort -u        # 必须都在七种类型内
awk '/^## 载体记录/{f=1;next} /^## /{f=0} f&&/^\|/{n++} END{print n+0}' "$F"  # 必须 >= 3（表头 + 分隔行 + 至少一行数据，只数载体记录小节）
```

**并发与失败**：能派子代理就每批 5–8 章，一批全部落盘、自检过、更新 `进度.md` 后再发下一批；不支持子代理就主线程串行，自检一样。子代理崩溃、超时或空输出，同条件重试 1 次；自检不过，带着失败项重写 1 次；仍失败就标 `跳过`，写进 `进度.md` 失败记录。单章失败不阻断管道，但**跳过的章必须写进之后每一份继承它的聚合产物**；看起来完整、其实缺了第 47 章的分析，比明说缺章的更危险。全部落盘后跑覆盖率，缺章补跑；文件名写歪的改名，不重跑。覆盖率不足不进 S3。

### 4.4 S3 剧情单元与节奏

只读 S2 的提取，不回头重读原文（再读一次得到的是第二份互相矛盾的事实）；核对硬事实时回查具体那条白描。

**先判故事框架**（扫全部概要加首尾各三章的提取；判不出就写"框架不明确"和原因，不硬套）：

| 框架 | 特征 | 按什么切单元 | 改编提示 |
|---|---|---|---|
| 升级流 | 等级 / 境界体系清晰，按阶段推进 | 按等级阶段 | 阶段边界天然是集或季的边界（series-long-form §6） |
| 复仇线 | 核心矛盾明确，目标驱动 | 按复仇对象或阶段 | 每个对象一个小高潮，贴合爽剧 |
| 单元剧 | 每卷独立故事，弱连续 | 按单元 | 和短剧集结构最贴合 |
| 多线交织 | 多视角、多时间线 | 按线索切，交叉点单独标 | 竖屏最贵，观众要记的人最多；先删线（§6.2） |
| 蜕变成长 | 主角内在变化为主线 | 按成长阶段 | 内在变化必须找到外部载体 |

框架结论写在 `剧情单元.md` 开头，和快评的判断对照，不一致写清哪个错了。

**剧情单元**每条记六项：标题（15 字内）、章节范围（sequence 起止）、进入状态（谁知道什么、谁有什么筹码）、核心冲突（具体对象 + 具体事件）、代价（谁付出了什么，不写"无"）、出去状态（改变了什么、下一单元必须继承什么）。上一单元的出去状态就是下一单元的进入状态，对不上说明漏了单元或边界切错。

单元粒度：一个单元同时满足有独立可衡量的戏剧目标、具体的对抗力量、本单元特有的核心角色、自己的紧张—缓和节奏；缺一条多半是另一个单元的阶段，降级处理。"获得神器"（1–2 章）是事件，"主角的成长之路"（1–100 章）是主题，"家族觉醒与传承认知"（1–6 章）才是单元。

**阈值自检**（边界模糊的信号，不是评分；数字对不上先怀疑边界，不为凑数拆并单元）：

| 指标 | 参考值 | 算法 | 不达标 |
|---|---|---|---|
| 归属置信 | ≥ 0.85 | 真正服务本单元目标或对抗力量的情节点 / 单元内情节点总数（只是落在章节范围内不算） | 标"待复核"，不删 |
| 覆盖率 | 85%–95% | 已归类情节点 / 总情节点 | < 85% 走散落兜底；> 95% 复核是否过度归并 |
| 重叠率 | ≤ 35% | 跨单元共享的情节点 / 总情节点 | > 35% 多半两个单元其实是一个 |

不足 30 章、单主线连续叙事的材料按时序切，覆盖率天然接近 100%，不是过度归并；复核重点换成"有没有把两条剧情硬并进一个单元"。

**散落兜底**：孤立比例低于 5% 标"少量散落"即可；否则按角色重叠、地点重叠、因果关系判相关性，强相关归入标 `[孤立归入]`，中等相关标 `[低置信归入]`，弱相关不强塞，按主题聚出 5 个以上才成候选单元标 `[聚类生成]`，仍归不了的按章列进 `剧情单元.md` 末尾的散落清单。宁可留在散落清单，也不塞进不相关的单元：塞进去的那条事实会让单元进出状态对不上，下游看起来却和真事实一模一样。

**`节奏与情绪.md`** 写三件事，每条都要回指章或情节点，回指不到的删：关键信息怎么推进（何时进入视野 → 如何被延迟、误导或验证 → 何时爆发 → 余波与新钩子）；情绪触动点索引（落在哪章、哪条情节点）；长间隔说明（连续 3 章以上没有触动点时作者靠什么维持期待——这些段落就是改编时要合并或砍掉的，短剧没这个耐心）。

### 4.5 S4 人物与设定

**一人一实体**：不能确定两个称谓是同一人就分开建两条。并错的代价不对称，两个人被并成一个之后，每条关于"他"的事实都可能属于另一个人，而文本里几乎看不出来。

| 称谓类型 | 可否合并 | 例 |
|---|---|---|
| 专名（全名、常用名） | 可 | "顾禾""顾小禾" |
| 绰号 | 有同指证据才可 | 文中点明"城东那位"就是某人 |
| 姓氏或名 + 头衔 | 有同指证据才可 | "周团""钟记者" |
| 描述性称谓 | 不可 | "红衣女子""随从" |
| 不带姓名的头衔职务 | 不可 | "护卫队长""家主"（可能先后换人） |

同指证据指同位说明、括号别名、上下文明确指代、文中改名；"读起来像同一个人"不算。判据：去掉头衔还剩不剩一个姓或名，剩就按证据判，不剩就不合并。分级按戏份（出场章数占比、是否推动主线、有无独立动机和变化），每条人物记来源章和未决项。

**设定**从提及数据归纳，不从记忆或题材惯例补：力量体系（名称、层级、晋升方式，没写清的层级写"原文未明确"）、地理、势力（目标与相互关系）、区别于现实的特殊规则。相互依赖、共同起作用的设定合成一条（"戒指 + 里面的残魂"是一个整体）。每条标出现在哪几章，标不出来的多半是从惯例补的，删掉。原著的能力规则进改编契约后，要改写成 story-engine §4 的条款级契约（DEV-xx），剧中披露服从条款。

### 4.6 S5 改编价值与分集候选

判定对象是剧情单元，不是章，也不是情节点；原始依据是 S2 的载体记录（通道走可见行动或对白的多半能直接拍，走心理叙述或叙述者旁白的要换载体或换不了）。每个单元落进且只落进一类：

| 判定 | 含义 | 后续 |
|---|---|---|
| 能直接拍 | 功能由可见行动、可听对白或空间关系承担 | 直接进候选集 |
| 要换载体 | 功能成立，但现在的载体只属于文字 | 必须写出新载体，写不出就降级 |
| 只能靠文字 | 功能依赖读者和叙述者的关系，屏幕上兑现不了 | 明说放弃了什么 |

"只能靠文字"的典型：长段内心权衡、叙述性诡计（读者被叙述视角骗，镜头做不到同样的隐瞒）、靠信息密度堆出来的爽感、要读者记住三十章前一个细节才成立的回扣。不要把它悄悄改成"要换载体"：承认放弃比假装能拍便宜，假装的代价要到分镜和静帧预演才暴露。

**换载体**逐单元写：原载体（抄 S2 的通道）→ 新载体（可见行动 / 物证 / 空间关系 / 对白策略 / 第三方反应，要具体）→ 保住了哪些功能（逐项对上）→ 改变或失去了什么（不写"无"）。检验只有一条：观众不需要旁白就知道发生了什么。新载体要能在 drama-forge 的条件下拍：一镜一人加接触同框、画面不出字、可生成性预算（§9）。

**制作负担**逐单元记：几人同框、哪些不重复空间、有没有群戏 / 动作 / 特效 / 可读文字 / 跨时间造型。它是改编排序的依据：同样能直接拍，负担低的先进候选集；超 story-engine §1 预算的单元先改写法再进。

**桥段标签**：给每个单元打标签，逗号分隔，用来数重复（同一桥段在一本书里出现五次，要么是卖点，要么是拖沓）并对照 premise-novelty §1 的饱和设定：命中饱和设定的单元，在改编契约里写清这部改编"新在哪里"。种子表（可扩展，凑不出就留空）：

| 题材 | 常见桥段 |
|---|---|
| 都市 / 言情 | 打脸、扮猪吃虎、马甲掉落、先婚后爱、追妻火葬场、破镜重圆、替身、契约婚姻、萌宝助攻 |
| 玄幻 / 修仙 | 废柴逆袭、越级战斗、夺宝、护短打脸、绝境翻盘、机缘逆天 |
| 历史 / 种田 | 先知先觉、改变历史、科举经商崛起、攒钱起家 |
| 悬疑 / 无限 | 信息差、反转打脸、规则怪谈、身份揭穿、复盘解谜 |
| 系统流 | 任务奖励、签到、面板升级、强制任务、积分兑换 |
| 重生 / 穿越 | 前世复仇、改命、身份调换、双重生、未卜先知 |
| 世情 / 家庭 | 极品亲戚、偏心打脸、维权反击、自我觉醒 |

**分集候选**按局部戏剧结果和精确交接切，不按章号、字数或平均分配。每条候选要答得出：进入时观众已知道什么；本集兑现了哪一部分承诺（一条都不兑现的不算一集，观众到第三集就走）；出去时留下的具体决定、危险或问题；下一集必须继承哪些事实。集数不由拆解决定：候选多于或少于本批授权集数都照实写，差多少在改编契约里决定合并还是拆分。

`分集候选.jsonl` 每行一条（合成例）：

```json
{"candidate_id":"EPC-003","story_units":["UNIT-03"],"chapter_range":{"sequence_start":14,"sequence_end":19},"screen_judgement":"要换载体","trope_tags":["信息差","反转打脸"],"entering_knowledge":"观众已知两人共用一份旧证据，不知道其中一人改过它","promise_paid":"改动被第三方当场指出，怀疑变成具体指控","exit_pressure":"被指控者要在下一次公开场合前决定认不认","inherited_facts":["改过的证据还在对方手里","两人的合作还没破裂"],"preserved_functions":["关系压力","信息不对称"],"carrier_change":{"original":"长段内心权衡","new":"第三方当众比对两份文件的动作（文件字样后期叠加）","lost_or_changed":["原著读者先于角色知道改动，改编后观众与角色同时知道"]},"production_load":{"locations":2,"speaking_roles":3,"readable_text":true},"unresolved":["第三方的立场在原文前后不一致"],"status":"候选"}
```

**回填快评**：`改编价值.md` 开头写一段快评对照，逐条对上六段，写出哪些判断被全量结果推翻、为什么。"三类比例"两边的对象不同（快评按章、S5 按单元），不做换算，只对方向。全中也写一句；从不出错的快评多半没被认真对照过。

**交给改编契约前自检**：每个能直接拍或要换载体的单元，在候选集里有落点或写明为什么没有；每条候选的功能能回溯到某个单元、某条白描；硬事实能回到白描或原文；只能靠文字的单元、跳过的章和散落清单都写进交接摘要（不只躺在文件深处）；所有判定都写成候选。交接摘要写进决策记录：拆了多少章、跳过哪些、三类各多少单元、切出多少候选集、三处最大风险（具体到单元）、快评里被推翻的判断。

## 5. 多集原稿接入

用户给的是已经分集写好的剧本、散稿或合订稿时用这一节，它不是小说拆解。原则：**由 Agent 判断这份文件实际怎么分集、每集讲了什么；工具只保存精确定位、防止重复劳动**。

### 5.1 不变边界

- 原文件原样放进 `输入/`，定位按原始字节算，换行符不做归一化；不为迎合工具改写用户原文。
- 不把整稿、全部分集正文塞进一次上下文、命令参数或 heredoc；一次只读当前批次的单集切片。
- 自动标题识别只给候选索引，不是语义裁决。

### 5.2 建索引

有配套脚本 `episode_intake.py`（纯标准库）时：`index` 识别短独立行的 `第N集`、`第N集 标题` 和 Markdown `# EP N`，统一成 `EP001`；`manual-index` 接受 Agent 写的边界 JSONL（每行 `{"episode_id":"EP002","line_start":58}`，必要时加 `line_end`）；`verify` 在每次切片前核对长度、跨度、顺序和行号；`slice` 取单集；`progress` 按本批大小列出待做集；`merge` 把本批记录合进候选文件（拒绝未知 ID、批内重号、对已完成集的冲突重写）。没有脚本时照 §4.1 的手工办法：记每集 `line_start` / `line_end` 和文件 sha256，切片前重算。

索引只能标出第一个集标题之前的前言和目录；集与集之间插的制作方说明、尾注，会被并进前一集或最后一集而不报错。这是语义判断，不靠扩大正则猜：每一集都要读首尾几行，确认边界落对了位置；前言和目录做小范围检查。

### 5.3 分批与续跑

批大小没有固定值：看索引里各集的长度、实际复杂度和可用上下文，本轮明确选一个；首轮保守，读过真实切片后再调。每集读完先落一条记录再读下一集，连续性只带已定的交接事实和上一集记录，不回读整稿。中断后以磁盘上已完成的记录为唯一完成真相，重新列待做集（已有 EP001、EP003 时 EP002 仍在待做里），不用"上次做到第几集"去猜。

### 5.4 规范化进 drama-forge

- 每集原稿规范化成 `EPxxx/剧本.md`（screenplay §1 格式：场次标头、`[连续性]`、`[画面文字]`、`[OS]`/`[VO]` 标签），只动格式，不改动作和台词的内容；集纲那一行从原稿反推（受气、底牌、行动、反派失去、兑现、新问题、交接），反推不出的格子记进改编契约的"原稿缺口"，不自己编剧情补上。
- 原稿台词语言和 `dialogue_lang` 相同时，台词按原稿保留；reviewer 照常做母语审读，但对用户原稿的意见写进审查文件和决策记录，不自动改写。语言不同（例如中文原稿要做日语台词）时，按 screenplay §4c 本地化改写，原意逐句对照，专名写 `reading`。
- 原稿违反 drama-forge 硬规则的地方（画面里要出字、群戏要多人同框才看得懂、事件没有起因拍、插回忆），按 §9 的对应改法最小改动，并逐条记决策记录；这是改编，不是替用户重写。

## 6. 改编契约：删线、合并、换载体

模板 `assets/templates/改编契约.md`，复制到 `项目开发/改编契约.md`。无人值守时由主会话按下面的规则自己拍板，每一项决定写进决策记录。契约定下来的内容再投影进系列简报（人物、装置条款、分集走向、不可改事实清单），系列简报是下游对账的唯一依据。

### 6.1 四类

| 类别 | 含义 | 处理 |
|---|---|---|
| 不可改承诺 | 核心关系、关键选择、结局含义、必要世界规则 | 保持事实与功能；每条写明落在第几集、观众从哪个画面得到，或延后到第几集（story-engine §8 登记不等于兑现） |
| 可换载体 | 叙述顺序、场景、配角、信息出现方式 | 可压缩、合并，记下替代关系 |
| 可删冗余 | 重复说明、只负责走路程的段落、没有新状态的复述 | 删，并写明没损失什么 |
| 未决 | 原著自相矛盾、授权不清 | 保留问题，不替用户定案；按默认可逆假设推进时单独标出 |

不要把"更短"当成唯一目标：删掉的段落可能很短却承担着一次信任转变，保留的奇观可能很长却不推动任何选择。

### 6.2 先删线，再合并

删整条支线和合并人物是两种操作，顺序不能反：合并是把功能重新分给某个人，如果那个人所在的线随后被删，刚做的分配全部作废。

删一条线的判据不是它好不好看，而是删了以后主线还成不成立：
1. 它的结果是不是别处铺垫的兑现，或别处兑现的铺垫？两个方向都查铺垫台账。
2. 主角是不是靠它拿到证据、盟友、权限或技能？是唯一来源的，删了主角后面就凭空拥有这些东西。
3. 它提供的是世界规模还是主线推进？只让世界显得大的支线，在竖屏短剧里最该删：观众为主线兑现节奏买单，不为世界广度买单。
4. 它是不是某个"观众知道、主角不知道"落差的唯一来源？删了，后面所有替主角着急的场次一起失效。
5. 删了会留下多少孤儿铺垫？前面为它埋的每一处都要跟着删或改指向；孤儿铺垫比支线本身更伤，观众会一直等。

最常见的错删：删节奏慢的线、留好看的线。慢线常常正是快线成立的条件，铺垫、代价、信息落差都住在慢线里。删线时把它承担的功能逐项列出（功能账本：谁逼主角选择、谁握着证据或资源、哪场改变了权力或关系、哪段建立了后面要兑现的误信、哪个空间限制让冲突必须现在发生），每项标"一起删"或"转给哪条保留的线、接收方多承担了什么"；只写"并入主线"等于没交代。

### 6.3 合并人物与场景

两个角色只有在功能能由同一人的目标、知识范围和关系位置自洽承担时才合并。合并前问五条：两人原本知道不同的事实吗，合并后会不会提前泄密？两人分别代表支持和压力吗，合并后对抗会不会消失？两段关系需要不同的历史或伦理位置吗？同一个人在同一时点做得了两件事吗？合并后某次背叛、证言或牺牲会不会失去代价？

- 弱合并："配角太多，改成同事甲。"
- 可用合并："门店会计和房东都在阻断账本获取；改成房东兼代账人，但把原会计掌握而房东不知道的假发票来源转给另一条证据链。"

合并人物同时服务 story-engine §1 的可生成性预算（每集有台词角色 ≤ 4）和 visual-assets 的身份图数量；但"人更少"本身不证明合并成功。

场景可合并要同时满足：时间和地点能连续；两个议程能同场碰撞；信息出现不改变因果顺序；合并后每个关键反应仍有空间。不能只因为"都在办公室"就把隔日的后果塞进同一分钟。合并场景同时服务"每集主场景 ≤ 3"。

### 6.4 信息视觉化阶梯

原著里"人物知道 / 回忆 / 解释"的内容，依次尝试转成：
1. **行动后果**：他不报门牌，直接用旧钥匙开门；
2. **可争夺的证据**：缺页、录音、伤痕、持物（证据上的字后期叠加，手机屏幕背对镜头）；
3. **空间行为**：谁挡出口、谁避开座位、谁够得着证物；
4. **对话策略**：试探、误导、讨价、逼供、拒绝，而不是中性说明；台词按 screenplay §4 写多、写快、写用途；
5. **规则和装置信息**：用台词明说（SKILL.md 6c），数值走后期面板；
6. **`[VO]` / `[OS]`**：只在前五种都不行、且用户或原著明确要这种声音时用；H3 不生成画外人声，要按 SKILL.md 硬约束 11 另做音源。

视觉化不等于每句话配一个动作：来回倒水、走到窗边、翻无关文件，不改变议程或证据条件，就是假运动。

### 6.5 保住因果桥

压缩时间后逐项检查这条链有没有断：原因事实 → 人物理解 → 选择 → 对手反制 → 可见后果 → 新压力。删掉的段落如果承担"人物为什么相信""对手怎么得知""道具怎么到手"，要在新版本里建一个等价且可见的桥（screenplay §5b 的起因拍），不能用一句"原来如此"跳过。

### 6.6 功能对照表（大幅重排时）

`项目开发/改编对照.jsonl`，每行一条，只存定位和去引用的功能摘要，不复制原文：

```json
{"mapping_id":"ADAPT-07","source_span":{"file":"输入/原著.txt","line_start":812,"line_end":840},"source_function":"一次旧选择让两人对同一证据承担不同风险","disposition":"换载体","candidate_episode":"EP004","new_carrier":"两人当面交换钥匙时的停顿与拒收","preserved":["关系压力"],"lost_or_changed":["原著的三页内心独白压成一个动作"],"status":"已定"}
```

`disposition` 取：保留 / 合并 / 换载体 / 压缩 / 删除 / 未决。

### 6.7 单集化而不肢解

每集完成一个局部状态变化，同时保住长线：当集兑现原著吸引力的一部分；集尾压力由本集选择或后果产生；不靠把一个完整反应切掉来制造卡点；下一集的进入状态是精确事实，不是"局势更紧张"。一段长叙事可以拆成多集，但每集都要回答"本集观众具体得到了什么"。拆出来的集同样要过 story-engine §5 的爽点间隔门和集纲六件事。

## 7. 写下游时回原文取细节

写集纲、剧本时常要回原文取具体细节：动作顺序、东西在谁手里、围观者的反应、某句话实际起了什么作用。两种稳定的失败是查不准和查到了不该用的。

- **用事件锚点查，不用概念词**。能力名、境界名、组织名、主题词会在几十处命中，横跨全书各阶段。锚点 = 谁 + 在哪里或用什么 + 正在做什么或和谁冲突：弱锚 `修炼 突破 功法`，强锚 `<角色名> 后院 药炉 当众被夺`。命中为空就换一组更具体的锚点，不退回更宽的词。
- **命中后回读原文段落**，不凭检索摘要写；摘要最先丢掉的正是要取的东西：动作先后、谁先开口、东西在谁手里。
- **命中可能来自故事后段**。后段的片段里人物关系、知情范围、能力边界都已经推进过，直接拿来写当前集，人物就会提前知道不该知道的事、提前拥有还没拿到的手段，而且读起来完全通顺。用前把片段的知情状态和本集进入状态逐项对照（谁知道了什么、谁和谁结盟、主角手里有什么），任何一项超前，这段只能作风格或信息参考，不能作依据。
- **召回只补细节，不加剧情**。集纲决定这集发生什么；回原文是把已定的事写具体。原文另有更好看的段落，走"先改改编契约和集纲、再写剧本"的修订路径，不在写正文时顺手塞进来。

## 8. 对标作品只学机制

用户提供对标剧、小说、分镜样例或提示词时，学它解决问题的机制，不召回它的表达外壳。只读用户在当前会话明确提供或授权的材料，不自行去找外部非公开项目库。

每份材料先写明：来源位置、用户允许的用途、这次要解决什么问题、是主参考还是补充参考（与当前问题无关的材料不加载，避免几部作品的表层元素混成一锅）。材料很长时，按问题选相关段落和完整的因果窗口，不用关键词命中代替读上下文。然后写一张去引用的机制卡（写进决策记录附注或 `项目开发/` 下的参考笔记，原文和观察留在 `输入/`）：

```yaml
参考机制:
  来源: 输入/references/<位置>
  要回答的问题: 悬疑怎样一步步缩小安全空间
  直接观察: 对功能的转述，不复制原句
  观众状态: 进入这一段时观众知道、期待或误信什么
  戏剧问题: 要解决的戏剧问题
  可选机制: 怎样改变信息、权力、关系、路线或代价
  可见效果: 由什么行动、物件、空间或反应承载
  适用条件: 适用的观众承诺、人物状态与制作条件
  失效边界: 反例或需要换法的信号
  可以影响: [因果功能, 信息释放, 场面职责]
  不许照搬: [文风, 原句, 独特情节顺序, 专有设定, 人物关系组合]
  仍不确定: 需要另找反例的部分
```

离开人物名、专有设定或原句就说不清的发现，还不是可迁移的手艺，不进写作上下文。迁移检验：用完全不同的题材、人物关系、场景和措辞解释这个机制，仍能说清它解决什么、怎么看效果、何时失效，才算抽象完成；再比较至少一个替代机制的制作负担和副作用，按分数自选并记决策。研究对标剧的台词时，不只收藏"金句"：记录这一句之前压了什么情绪、这一句改变了什么、后面接的是谁的反应。

参考作品不是质量证明："和参考很像"既不能批准，也不能单独否决；当前项目照样凭自己的因果、可演性和连续性接受审查。对标剧的播放量、集数、成本不进交付物，也不当质量判据（市场判断只用 market-hits）。

## 9. 原著写法与 drama-forge 硬规则的对应

原著常见写法和本 skill 的硬规则冲突时，以硬规则为准，按下表最小改动，逐条记决策记录：

| 原著写法 | 改成 | 依据 |
|---|---|---|
| 倒叙、插叙、回忆章节 | 按故事时间顺叙；前因用当下的物件、台词、字幕交代；确要闪回按 6b 标清时间和信息来源 | SKILL.md 6b、series-long-form §1.1 |
| 长段内心独白、心理描写 | 行动后果、证据、空间行为、对话策略（§6.4）；做不到的判"只能靠文字"并放弃 | §4.6 |
| 叙述者旁白交代世界观 | 规则一场只讲一个、一句话讲清，用台词说出来 | premise-novelty §7 D2、SKILL.md 6c |
| 系统面板、信件、告示、屏幕文字推动剧情 | 后期叠加 `[画面文字]` / 面板，生成画面不出字，手机屏幕背对镜头 | SKILL.md 4、styles.md §12 |
| 群戏、宴会、大比、群众齐声反应 | 具名个体的单人反应镜轮流出；接触动作用接触同框镜；群战拆成短镜 | SKILL.md 3、market-hits §4.8 |
| 人物、援兵、法宝凭空出场 | 先写起因拍或来源镜 | SKILL.md 6f、screenplay §5b |
| 原著对白（与台词语言不同时） | 目标语言母语口语本地化，专名标读音 | screenplay §4c |
| 慢热开篇、前几章铺世界观 | 从开篇替换点进入（§4.2），第一次兑现不晚于 EP001 前半段 | premise-novelty §7 B1/B2 |
| 真实宗教神佛、未授权 IP、明星形象 | 换成虚构神系或原创设定 | market-hits §4.5 |
| 原著节奏的长间隔（三章以上无触动点） | 合并或砍掉 | §4.4 |

## 10. 审查问题与失败征兆

C、E 阶段的 reviewer 在 review-checklists §A–C 之外，改编项目另答 review-checklists §R2（改编契约落地，7 问）；A0 原著分析层按 §R 审。

失败征兆：凭书名回忆情节；分析里成段抄原文；白描写成了结论（"展现了实力""埋下伏笔"）；聚合时回头重读原文得出第二套事实；缺章的聚合看起来完整；按章号或字数平均切集；描述性称谓被合并成同一人；设定从题材惯例补出来；删了慢线、留了快线，快线不再打中人；开篇照原著第一章慢慢铺；原著的回忆章节原样变成闪回镜头；原著人物表直接变成资产表。
