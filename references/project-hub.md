# 项目总控：进度总览、导出资料、决策记录与观察日志

跨阶段、跨项目的事读本文件：同时做几部剧时看全貌，把制作资料打包给别人，决策记录该记什么，模型观察怎么记才能用，规则打架时听谁的。单集怎么做仍按 SKILL.md 的阶段表和 [pipeline-contract.md](pipeline-contract.md)。来源：原总控套件的创作路由、项目模板、导出、观察记录与决策记录样例，已按本 skill 的全自动流程改写。

## 1. 进度总览：一部剧、几部剧

- 一部剧：`project_tool.py status <项目>` 看每集各阶段，`next` 给下一步（SKILL.md「每次执行」第 1 步）。
- 几部剧一起做：`python3 scripts/hub_tool.py overview <工作区目录>` 扫描目录下（两层以内）所有 `drama.json` 项目，每部剧一段：系列简报、情绪集纲、参考图完成数，每集的剧本 / 视觉 / shots / 门 / 起始帧 / 预演 / 视频 / 审片 / 成片，以及 `next` 给出的下一步。`--json` 给机器读，`--html <文件>` 写一张只读网页快照（自适应浅色/深色，手机宽度也能看），用浏览器直接打开本地文件即可；进度变了重新运行刷新。
- 用它排交付节奏：硬约束 10 要求先把每部剧的 EP001 都出成片再做后续集，总览里谁的 EP001 还没「成片✓」就先推谁。
- 一部剧读不了（缺 `drama.json` 字段、schema 不对）只在它那一段报错，不影响其他剧。

**为什么不搬原来的本地 Dashboard**：原套件的 Dashboard 是一个本地 HTTP 服务加网页编辑器，服务于"五份 Markdown 就是创作真相"的项目结构，能在网页里直接改剧本和提示词。本 skill 的分镜.md、图片提示词.md、视频提示词.md 是 `shots_tool.py render` 从 `shots.json` 生成的，网页里改了会在下次 render 时被覆盖；进度数据也来自 shots.json、review.json 和任务账本，和原 Dashboard 读的结构完全不同。要搬就得重写服务端和前端（约 15 万字节代码），换来的只是一个看进度的页面，所以只做了只读的 `overview --html`。

## 2. 什么时候把用户的话写进 `drama.json`

用户在对话里说定的项目级事实，当场写进 `drama.json`，不能只留在对话里——下一轮会话读不到对话，就会退回模板默认值，时长、画幅、方言都要重猜：

| 用户说了什么 | 写到哪里 |
|---|---|
| 集数、单集目标时长、画幅 | `episodes`、`target_seconds`、`aspect`（及 `width` / `height`） |
| 用哪个视频/图片/参考图模型、档位、分辨率 | `profiles` 对应字段（硬约束 1b：只有用户说了才写，不自选） |
| 台词语言、提示词语言 | `dialogue_lang`、`prompt_lang` |
| "这个时长是硬要求" | 决策记录写一行"目标时长为硬交付"（edit-and-delivery §2b） |

写完用 `project_tool.py status` 复核。只写用户明确说过的；没说的保持模板值或 null，不替用户补。

## 3. 导出制作资料

用户问"做完了怎么把资料给我/给别人"时：

```bash
python3 scripts/hub_tool.py export <项目> --out <项目外的目录> [--episode EP001 ...] [--media none|final|all] [--overwrite]
```

- **带什么**：`drama.json`（`api_base` 清空）、`项目开发/*.md`（系列简报、情绪集纲、决策记录、模型观察）、`参考图/refs.json`，每集的 `*.md`（剧本、视觉设定、渲染出的分镜与提示词、剪辑单）和 `shots.json`，`审查/` 里该集的 `.md` 与 `.json`（审查意见、review.json、ASR、交付测量）。
- **媒体三档**：`final`（默认）加顶层参考图 PNG 和 `成片/*.mp4`；`all` 再加起始帧、视频 take、配音、预演片和接触表；`none`（或 `--no-media`）只要文字。
- **不带什么**：`脚本/`（任务账本、ids.log、ASR 缓存、渲染提示词）、`参考图/` 下的子目录（用户给的原始真人照片等私有素材）、`STOP`、隐藏文件、文件名像凭据的文件（token、secret、key、.env）。token 本来就只在环境变量里，不会出现在项目文件中。
- **附带**：`manifest.json`（文件清单、字节数、sha256、排除规则，`asserts_approval: false`）和 `checksums.sha256`。
- `--out` 必须在项目之外；目标目录非空时要 `--overwrite`，而且只覆盖本工具以前导出的目录（有对应 manifest），别的目录一律拒绝，不会误删。
- 导出是**当前状态快照**，不声称任何审查通过或用户接受；正式交付的判断仍看剪辑单、审片记录和 edit-and-delivery §7 的交付核对。

## 4. 模型观察与参考图观察

`项目开发/模型观察.md` 只收本项目实测的模型行为，升级规则见 SKILL.md「修改纪律」最后一条（同一写法有效 ≥ 3 次才升级成 references 里的规则）。一条观察要能被别人复核，每行写清：

- **条件**：镜号与 take、提示词版本（`脚本/prompts/<EP>/` 下的那份文件，或 shots.json 当时的提交记录）、参考图槽位与顺序（Picture 1/2/3 各是哪张）、`profiles` 里的模型/档位/分辨率、种子；
- **区间**：第几秒、画面哪一块；
- **直接看到或听到的**：只写观察到的事实（"第 2.1 秒起口型落在右侧那张脸上"），不写推测的原因；
- **局限**：遮挡、分辨率不够、哪段没看、原因未知、混杂因素（同时改了两处）；
- **观察方式**：看图工具目检、ASR、用户描述；
- **有效范围**：只对本项目、这组提示词和参考图有效。"没看到失败"写成"目前 N 次里没出现"，不写成"不会失败"。

**参考图观察**（用户给的真人素材、外部参考图、重出的身份图）：接进 refs.json 之前先看一遍，在视觉设定或审查里记：看到的可读文字、水印、门牌校徽这类标识；裁切或遮罩；这张图能支撑哪些身份或地理事实。有字、有水印、多一个人就重出或裁掉（负面词擦不掉已有像素，visual-assets §8）；还没看过的写"未验证"，不写"已通过"。真人素材的身份与尊重要求见 visual-assets §11 和硬约束 12。

## 5. 决策记录：替用户拍的板都记在这里

本 skill 全自动：原套件里"每一步都等创作者确认"的地方（选画风、接受剧本、选调度方案、接受镜头结果），在这里都改成主会话或对应岗位自己决定，写进 `项目开发/决策记录.md`（日期、阶段、决定、理由、放弃的选项、可不可回退）。常见要记的类别：

| 类别 | 例 |
|---|---|
| 立项与画风 | 选了哪个候选、`style_preset`、Look Development 锁了哪套规则（styles.md §1b）、形态卡的覆盖（styles.md §13） |
| 写作阶段接受 | reviewer 两轮后仍未清的 Major 怎么处理、剧本/分镜 PASS 的依据 |
| 调度方案 | 一场戏比过两三种拍法时选了哪一种、为什么 |
| 生产与审片 | weak 的接受理由、drop 的三类理由（edit-and-delivery §2）、补拍与承担表（§2c） |
| 剪辑交付 | 目标时长是参考还是硬要求、调色、未实现的 L-cut 或白光、AI 标识为什么不叠 |
| 未决 | 需要用户回来看的真实创作分叉 |

**仍然必须由用户定、不能自己拍板的只有两类**：花钱的授权（本轮集数、提交次数上限、成本边界，runtime-boundaries.md）和模型选择（硬约束 1b）。这两类记用户原话和日期；用户没给就停在依赖它的那一步，先做不花钱的写作工作。

## 6. 规则冲突时的优先级

从高到低：

1. 安全、授权与付费边界：硬约束 1、1b、2 和 runtime-boundaries——任何项目设定都不能放宽；
2. 用户当前请求，以及已经写进 `drama.json` / 决策记录的用户决定；
3. 本项目的系列简报（装置条款、能力规则）和情绪集纲的交接事实；
4. SKILL.md 的其余硬约束与机械门（商业爽剧的创作预设在这一层，用户和项目设定可以改）；
5. references 里的手艺默认（可以写理由覆盖，记决策记录）；
6. 风格库、形态卡、题材卡和案例（只是参考，不单独阻断交付）。

同一层里两条冲突时，按更具体的那条（本集 > 全剧，本镜 > 本场），仍判不出就选对剧情可读性更有利的一条，写进决策记录。

## 7. 写入纪律

- 改文件前先读当前版本；别的会话或用户可能刚改过，不要用旧内容整段覆盖。保留未受影响的内容和稳定 ID（镜号、场号、IMG ID），修订时不无故换 ID。
- 交付文档（剧本、视觉设定、剪辑单、审查意见、导出包）里不写 token、私有中转地址、本机绝对路径和原始私人照片路径；需要引用时写项目相对路径。
- 生成、mark、cut 由主会话统一做（硬约束 9）；子代理只写自己岗位的文件。
- 进度一律落在项目文件里（决策记录、审查/、review.json），不留在只存在于临时目录的脚本或笔记里（硬约束 10）。
