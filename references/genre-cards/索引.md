# 题材卡索引

阶段 A 选定主爽点类型（story-engine §1）之后读。题材卡回答"这个题材更常用哪些压力、哪些场面、兑现落在哪、AI 拍起来难在哪"，不回答"这一集怎么写"；后者由系列简报、情绪集纲和 story-engine 决定。市场表现（上榜多不多、能不能续季、适合哪个平台）不从题材卡推断，以 [market-hits.md](../market-hits.md) 为准，卡里只摘与本题材直接相关的几条并注明出处。

## 怎么用

1. 先确认主题材、`style_preset`、用户声明的尺度与结局承诺，再查下表。
2. 只读匹配的那一张卡，不把整套卡加载进上下文。
3. 跨题材时主题材读全卡，辅题材只摘一两条"场面颗粒"或"禁止漂移"；先写清主要矛盾归谁、观众先看到哪个结果，再检查两套制作要求会不会打架（一个要公开场合与多名见证者，另一个要封闭空间与状态连续，成本是叠加不是平均）。
4. 传给编剧子代理的题材提示只保留和当前集相关的条目（压力来源、人物策略与信息权限、本集要落的兑现、可用的场面颗粒、钩子取向、禁止漂移），短到能完整读进上下文；写不满不凑。
5. 卡只在内部校准题材味：用了哪张卡记进决策记录；卡名、置信度、"已按题材卡执行"之类的字样不写进系列简报、集纲和剧本。
6. **前提装置不是题材**：重生、系统、读心、异能等装置不单独查卡，照常取主题材那一张，装置那一层按 story-engine §4 校准。
7. 表里没有的题材不硬套最接近的卡：按下面"跨题材比较"的六个轴（压力从哪来、人物怎么应对、观众每集看到什么结果、谁知道什么、观众具体看到什么、制作难点）自建一次，再决定借哪张卡的个别条目。

## 优先级

```text
用户的硬约束与已定事实（含改编契约的不可改承诺）
→ drama-forge 硬约束（SKILL.md）与已定的系列简报、情绪集纲、装置条款
→ 题材卡（默认做法，项目有理由就可以不照做，理由记决策记录）
→ 通用手感
```

题材卡永远是默认做法：不产生机械门，reviewer 不得单凭"卡里写了"或"卡里没写"判 Major；卡里的钩子取向、情绪落点和结局气质是可选项。卡与 story-engine、premise-novelty 或 market-hits 冲突时，以那三份为准。

卡里的任何内容都不是配额：没有"每集几个转折""几秒一个钩子"，不规定场景数、台词占比或句式，场面颗粒是可选素材不是打卡清单；连续几集用相似收尾不自动算缺陷，要看它们是否改变了不同状态（相邻集钩子不同型的要求在 story-engine §5，那条照旧有效）。

## 跨题材比较

同一个"悬疑"可以由空间规则、关系谎言或技术证据驱动，同一个"婚恋"可以走互助、权力不对等或身份冲突；只有推进方式和当前条件相符才借用。

| 题材方向 | 压力怎样持续 | 每段先给什么结果 | 画面里必须拍清什么 | 常见写坏 |
|---|---|---|---|---|
| 悬疑 / 规则 / 生存 | 安全规则逐步失效，路、时间、保护手段越来越少 | 查明一条决定下一步的事实，同时失去一条退路 | 门槛、路线、计时、有明确用途的关键道具、异常的条件 | 只把黑暗和声音加强；旁白替代可见验证 |
| 家庭 / 照料 / 伦理 | 私人义务与自我保护冲突，经济、照料、名誉筹码可执行 | 关系边界、证据归属或公开地位改变 | 照料动作、便携证据、见证者分区、退出路径 | 全家重复谴责，没人有新选择 |
| 亲子 / 认亲 | 关系未被承认，监护、就学、就医的硬期限逼近 | 名分或责任真的落地：签字、称呼、接送 | 签字栏、接送与等待、检验流程、孩子带来的物件 | 孩子只卖萌；血缘结果自动等于情感结果 |
| 古装 / 宅斗 / 隐藏身份 | 礼制、阶序、阵营与公开选择限制关系 | 隐藏地位或联盟获得新的公开解释 | 造型层级、随行、身份道具、入场方式、站位界线 | 辞藻堆叠；突然报头衔代替此前证据 |
| 职场 / 技术 / 喜剧 | 一个日常疏漏造成越来越具体的后果 | 别人能当场核对的修复结果，随后地位改变 | 操作顺序、核对点、设备状态（屏幕字后期叠加）、见证更新 | 同事先夸天才；人人同一种惊讶 |
| 复仇 / 权力反转 | 对手有真实手段，主角以证据、联盟或能力改变实际权力 | 一项旧权力失效并产生后果 | 证据链、半公开场合、对手反制、受影响者的反应 | 重复受辱—亮牌；揭身份不改变任何人的行动空间 |
| 动作 / 任务 | 地理、资源、时间和对手学习共同收窄路径 | 完成阶段目标，留下伤、损耗、暴露或路线变化 | 轴线、出入口、距离、持物、伤势 | 动作更大而任务状态不变 |
| 身份错位 | 外部任务逼人物用不合身的身份、身体或权限解决问题 | 任务先推进，再让误读带来关系余波 | 当前谁占用哪个身份、别人怎么识别、身体能力边界 | 设定梗重复，任务没进展 |
| 生活流 | 一个具体小目标被来客、误会、匮乏或照料打断 | 小事完成、放弃或被重新理解，关系留下轻微可见变化 | 日常物件、距离、手部选择、环境节奏 | 套用爽剧的密集大特写和公开翻盘 |
| 仙侠 / 修真 | 等级决定资源，对手也在修炼 | 力量差被具体改写，主角的金手指只受限制、不付代价 | 规则的可见限制、持物归属、损伤状态、旁人退让的距离 | 设定名词堆砌；境界数字自动等于胜负 |
| 游戏化世界 | 规则对所有人生效，旧权力作废；每单元新规则封掉主角上一套打法 | 一条规则被用出别人想不到、当场可核对的结果，处境随之改变 | 公告与面板（后期叠加）、倒计时、排行榜、旧身份符号失效 | 只打怪升级涨数字；新能力无铺垫 |
| 众嘲蓄势 | 众人基于错误常识否决并嘲笑主角，错误决定开始产生后果 | 每集一次小打脸，单元末众人回头求他，季末最公开处认错 | 嘲笑者站位与表情变化、后果现场、证据数字（后期叠加） | 主角只挨打不反击；嘲笑者一种蠢法；靠亮身份反转 |

**开场入口**（与 series-long-form §1.2 同一个方法）：比较几个入口，选观众能立刻追踪因果的一处——人物正在用惯常办法而异常结果让它开始赔钱；日常仪式里出一个会改变处境的小错；一个请求同时碰到双方不能兼得的义务；已经发生的后果通过一件看得见的东西再次出现；观众比角色多知道或少知道一条会影响下一步的事实。开场必须同时过 premise-novelty §7 B1。

**钩子从本集结果往下长**（型的轮换见 story-engine §5）：

| 本集留下的 | 可形成的下集压力 | 不成立的替代品 |
|---|---|---|
| 选择带来的代价 | 这个选择即将要求下一项代价 | 没有来源的新人物踹门 |
| 旧证据有了新解释 | 同一载体现在支持更窄、更危险的解释 | 只喊"你竟然不知道真相" |
| 对手反制 | 对手按主角刚暴露的策略封路 | 反派重复上集威胁 |
| 代价到达 | 先前的成功造成伤、债、关系或资源损失 | 黑屏前把结果全部藏住 |
| 谁能行动变了 | 新事实让某人能公开、逃离、作证、进入或拒绝 | 群众只重复惊叹 |
| 安全线或出口变了 | 安全距离、出口或可达区域变化 | 只把环境写得更暗 |

**立项时写清制作难点**（写在候选的"主要制作负担"里，premise-novelty §6 第 4 步）：跨镜跨集复用的状态数（关键道具、伤势、礼制造型、证据版本）；需要不同方位的空间（安全线、公开场合、仪式区、操作点）；谁是反复出现的具名见证者、谁只是背景；哪些文字必须观众读清（一律后期叠加）；哪段操作、仪式、保护或险情必须拆成清楚的起止状态。
