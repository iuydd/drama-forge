## 1. 输入与顺序

`cut.py <项目> EP001` 读三样：`shots.json`（镜序、台词、叠加）、`审查/EP001-review.json`（take、in/out、mode、verdict、speed）、`脚本/asr_cache.json`（词级时间）。`cut_order` 存在时按它排，否则按 shots 顺序。verdict 为 drop / missing 的镜跳过；mute 的镜去原声。每段重编码到项目画幅与帧率后 concat，再叠字、混音、归一。

进入阶段 J 的条件是素材**当前能打开**：视频文件在 `EPxxx/视频/` 里、ffprobe 读得出时长。提示词写完、任务提交成功、`jobs.jsonl` 记了 done，都不等于素材可用。素材不全时可以先剪已有的连续段落做草剪（`--draft`），但不能把它当成正式成片交付。

## 1b. 先看完整素材，标可用带

标入出点之前，先把每个 take 从头到尾看一遍，写下它**实际能用的时间区间**，以及区间外发生了什么。这一步产出的是事实，不是剪辑决定。

- 看法：先看 `review_tool.py sheets` 的接触表（每秒 2 帧）；怀疑有缺陷的地方（动作回弹、脸或道具漂移、突然提亮、口型对不上、重复表演）加密到每 0.25–0.5 秒抽帧，必要时逐帧看。亮度曲线只能帮忙发现缓慢漂移，身份、动作和局部细节仍要看画面。
- 生成素材常见的不可用段：开头起势的静止或干等、结尾漂移或回弹、整体发白、同一动作做两遍、无台词镜自编人声（标 mute）。静止、暗部和停顿本身不算缺陷，要看它是否符合这一镜的职责（反应镜的停顿就是可用的）。
- 记录位置：写进该 take 的审片 note（`review_tool.py mark --note`），格式「可用 0.6–4.2；0–0.6 起势静止；4.2 后右手回弹」。实测动作和对白区间照常用 `--action-window` / `--speech-window` 记，入出点必须落在可用带之内。
- **可用带比计划短时**，按顺序判断：
  1. 这段已经完整承载了信息和表演 → 直接缩短，不补时长；
  2. 缺的信息能由相邻镜承接 → 换镜或调 `cut_order`，调完复核预演和信息权限；
  3. 必要动作、台词或反应仍然缺 → 按 production-and-review §7 在授权内重拍或改分镜，不能为了避开画面缺陷把故事需要的信息剪掉。
- 画面不可用但对白完整时，可以评估"保留声音、换画面"：把这句对白作为音源镜，用 `audio_from` 垫到反应镜或插入镜上（§5 录音垫入）；做了就写进剪辑单和决策记录。
- **把缺陷反馈给上游**：写清缺陷在第几秒、画面上是什么，以及希望保住的状态（例：「3.8 秒后桌面高光过曝，重拍要保住桌面木纹可辨」）；重拍只改诊断出的那一项，重拍后比较同一处是否改善。某一次重拍变好只记进 `项目开发/模型观察.md`，不当成模型规律（见 [project-hub.md](project-hub.md) §4）。

## 2. 出点规则

| mode | 出点 |
|---|---|
| after_last_word（有台词默认） | max(review.out, min(素材 − 0.1, 末词结束 + 0.5))；有印章字时尾巴 = hold + 0.1 |
| to_end（留白结尾） | 末词结束 + 0.02 |
| fixed | review 里的 in/out |
| full（无台词默认） | 素材 − 0.2（生成素材片尾常有回弹或异常帧） |
| action（动作镜） | 入点 = min(首词 − 0.15, 动作开始)；出点 = max(动作结束 + 0.2, 末词 + 0.3)；没有动作区间时退回 after_last_word / full |

入点默认 0；模型看图后按可用带收紧，开口前、动作前的干等要剪掉（入点可以大于 0）。段长 < 0.5 秒的镜跳过并打印。

**出点不能只按台词**（EP001 复盘：7 镜的撞、让开、空箱弹开、扑箱、愤怒反应全被"末词 + 0.5 秒"和计划秒数剪在出点之后，成片里人不会动、故事断了）：
- 动作区间只取当前 take 的有效 assessment.action_window；计划、旧镜头级区间和运动曲线都不能替代实测审批。
- cut.py 在所有模式保护当前 take 的已审动作和对白两端；越界区间报错。正式剪辑前检查审批与素材/镜头指纹，未审只可显式 `--draft` 草剪。
- 参考运动能量：`review_tool.py motion` 打出每镜的能量峰和动作区间；取用段之后还有明显更高的能量峰（EP001 S04 取用段 1.08、被剪段 12.36），就是动作被剪掉了。
- **动作晚于台词时优先保动作**：宁可让台词说完后多留一两秒动作，或用 J-cut / L-cut 把台词压到下一镜，也不为了台词把动作剪掉。
  - L-cut：上一镜的声音延长 N 秒盖到下一镜的画面上，下一镜那 N 秒的原声静音；J-cut 反过来，下一镜的声音提前进来。短剧最常用的是对白 L-cut 接听者反应镜：说话人最后半句压在听者脸上，镜头能切得更快，台词一个字不丢 [社区]。
  - **cut.py 目前只做音画同步切段，不支持 J/L-cut** [自测：读 cut.py]。要用就在成片后用 ffmpeg 把音轨和画轨分开 concat 另做，整条命令写进剪辑单；没做成的，剪辑单写"计划 L-cut，未实现"，不能写成已完成。
- fixed 镜的入出点必须来自接触表上看到的时间，不照搬 shots.json 的计划秒数。
- 片长超出目标时先删镜、合并台词，不靠缩短每镜的尾巴来压时长。

**节奏下限（用户原话："拍摄镜头切换太快"）**：成片里每一镜的取用不低于下表，参数在 `drama.json` 的 `pace`；只设下限，长镜头（同一个人合并成的 8–15 秒镜，storyboard-keyframes §7b）照常整段用，不为"节奏快"把长镜头剪短。

| 镜头 | 下限 |
|---|---|
| 对白镜 | 台词说完 + 0.8 秒，且不短于 2.5 秒；一句完整台词在一个镜头里说完，不在句中切 |
| 反应镜 | 1.5 秒 |
| 插入特写 / 冲击剪辑 | 可以短于 1.5 秒，但 shots.json 要写 `fast_cut_reason` |
| 同一场平均镜长 | ≥ 2.5 秒 |

cut.py 在剪辑单每镜的"时长"格标出「过短：对白镜下限 X s」，末尾写一行"节奏：平均镜长、长镜个数、过短镜清单、同场平均镜长低于下限的场"。有过短镜时：先看是不是出点剪早了（按审片的 speech_window / action_window 放宽），再看是不是分镜把同一个人拆碎了（回 E 合并成长镜头），最后才考虑写 `fast_cut_reason` 豁免。

### 审片定 mark 的默认

- 有台词镜：`--mode after_last_word`，入点 = 首词开口 − 0.15 秒（开口前的干等剪掉）；台词以「……」开头、表演上需要先停顿的反应镜，入点可以更早，写进 note。
- 有动作职责的镜用 `mark --action-window START END` 记录当前 take 实测动作；对白用 `--speech-window`。命令与证据要求见 [审片与剪辑准入](quality-contract.md)。
- 无声插入镜（倒水、手部动作等）：`--mode fixed --in 0 --out <该段可用长度>`。
- 核心审查通过且只有非关键瑕疵时，weak 需 `--acceptance-reason` 明确接受的缺陷；未审或关键缺失不能 weak 放行。
- mark 清单直接用 `review_tool.py mark` 落进 `审查/<EP>-review.json`（locked），不要只写在临时目录里的脚本上——临时目录会丢；丢了就按 `审查/<EP>-asr.json` 的词级时间重新定。
- **drop / missing 的理由分三类**写进 note，三类的去向不同：
  - 文件缺失（还没生成、生成失败、下载失败）→ 回阶段 H 收回或生成；`download_failed` 先 collect，不当成生成失败重拍；
  - 质量不可用（身份漂移、关键动作没出来、出字、认错人，且 take 已用尽）→ 回 E 改分镜或提示词；
  - 叙事取舍（信息与相邻镜重复、删掉后更紧）→ 写清这一镜承担的信息由哪一镜接住，或明确这条信息在成片里不再出现。
  没写理由的 drop 不算完成审片。

### 2b. 剪辑的权限：只取舍，不改写

- 剪辑可以缩短、删镜、调 `cut_order`、换 take；不能改台词文字、镜头职责、起止状态。发现需要改这些，回 C（剧本）或 E（分镜）改源文件并重拍受影响的镜，决定写进决策记录；不在剪辑单里写一套和 shots.json 不一致的说法。
- 同一段素材在成片里出现两次（闪回、强调）：`cut_order` 不允许重复镜号（G41），cut.py 也没有"让另一镜复用这段视频"的字段 [自测：读 cut.py / shots_tool.py]。要么把闪回写成新镜（新 ID）重新生成，要么在成片后用 ffmpeg 把那段素材再插一次、整条命令写进剪辑单；两处取用的源区间不重叠，并写明为什么第二次仍然成立。同一批帧无理由出现两次是重复镜头，不是复用。
- **目标时长分两种**：`drama.json.target_seconds` 默认是创作参考，实际时长与目标的差写进剪辑单即可，J 阶段门是 ±30%；用户明确说"必须 N 秒"时它就是硬交付要求，要继续删镜、合并或补素材直到满足，或列出缺哪些素材才能满足，不能自行降为参考值。
- 删短某一段后，只有别的段落确实需要更多表演或阅读时间才延长，不机械把省下的秒数摊给其他镜。

### 2c. 补拍与替代 take：逐项交代谁承担

重拍时缩小提示词范围（只拍手部、只拍反应）常常是对的，危险在于把只拍了一部分的版本悄悄当成完整版本，原本由这一镜承担的台词、反应、揭示或终点从此没人负责。

| 版本 | 承担什么 | 与原镜的关系 |
|---|---|---|
| 原镜（母版） | 这一镜在 shots.json 里写的全部职责 | 默认进成片的版本 |
| 补拍（新增插入镜） | 补一个动作、反应、构图或效果 | 在 shots.json 新增镜号，与原镜并存，不替代 |
| 替代 take | 同一职责的另一种实现 | 只有逐项比过原镜职责都在，才在 review.json 选它 |

做补拍或选替代 take 时，在审片 note 或 `审查/<EP>-审片.md` 写一张承担表：原镜的每项职责（台词、动作、反应、终点状态）现在由哪一镜哪个 take 承担；两边都没有的项，回 E 改分镜，不能靠改名让缺口消失。例：原镜要求"甲拍下账页、乙别开视线、丙起身"，补拍只拍了甲的手，那乙的反应仍由原镜承担，丙起身若两边都没有，就回分镜。

## 3. 字幕

- 文字逐字取剧本（`dialogue[].text`），不信 ASR 的字，只信它的时间。
- 时间：每句先用 ASR 词序列按文字对齐（`align_phrases`），对不上的句子再按字数比例落在 [首词 − 0.1, 末词 + 0.25] 里；没有 ASR 时落在段长的 20%–80%。
- 样式：底部居中，白字黑描边加投影，≤16 字 50px，否则 40px；按像素宽自动换行，优先在标点后断。字体候选在 `drama.json` 的 `fonts.sub`，默认 Hiragino / PingFang / Noto CJK。
- **字幕长度与阅读速度**（审片和交付核对都查）[官方：Netflix 字幕规范]：
  - 中文每行不超过 16 字、日文横排每行不超过 13 个全角字，最多 2 行；超出的句子不要靠缩小字号塞进去，在剧本 / shots.json 里拆成先后两句 `dialogue`（台词原文不改，只是断开）。
  - 阅读速度：中文不超过每秒 9 字；日文原声同文字幕删不了字，超过每秒 6 字时在审片表里标出，考虑延长镜头或分条。
  - 每条字幕显示不短于约 0.83 秒（5/6 秒）、不长于 7 秒，相邻两条之间至少隔 2 帧。
- **画幅与安全区**：现在三部剧都是 16:9 横屏，cut.py 的"贴底 40 px、`max_width` 1200"能用。**改 9:16 竖屏投抖音、TikTok 之前**，先改 cut.py：字幕放在画高约 72–78% 处，避开底部约 400 px 和右侧约 180 px 的平台按钮区（按 1080×1920 算），`max_width` 改成画宽的 80%；30% 高的叠加字也要避开顶部约 140 px [社区]。
- 双语字幕（日语台词配中文）：剧本里先有译文，作为 `dialogue[].subtitle` 另给；没有就只出原文。

## 4. 后期叠加

- 生成画面里不出任何字；所有字都在这一层。
- `text`：画面中上部（30% 高），58px，白字描边；多条按段长均分依次出现，或用 `at` / `until` 指定；有录音垫入的镜等录音放完（42%）再出。
- `panel`（系统弹窗、金手指面板、灵识提示、圣旨卷轴）：用户原话"系统弹窗做的有科技感一点"。cut.py 默认样式是**半透明深色玻璃底**（面板下的画面做毛玻璃模糊）+ **细描边与外发光**（主色默认冷青、副色电蓝）+ 圆角 + **标题栏**（小图标 + 标题，默认 `SYSTEM`）+ 正文逐字打出（带光标）+ **入场动画**（0.32 秒缩放入场，光带从上往下扫过一遍，之后每 3 秒淡扫一次）+ 出场淡出 + 轻微全息抖动 + **入场音效**（程序生成的电子"叮"，混在 −10 dB）。面板至少显示 1.6 秒（够入场、打字、读完）。时机和多条排布同 `text`（`at` / `until`）。
  - 样式写在 `drama.json` 的 `overlays.panel`，常用键：`theme`（`tech` 都市科技 / `xianxia` 修仙灵光 / `scroll` 古风卷轴）、`accent`（主色 RGB）、`position`（`top_left` 默认，避开右上角的 AI 标识；也可 `top_right` / `top` / `center` / `[x, y]` 画面比例）、`width`（画宽比例，默认 0.36）、`title`、`icon`（hex / rune / seal / none）、`enter`（入场秒数）、`enter_mode`（scale / slide / unroll）、`type_cps`（每秒打几个字，0 = 一次出全）、`glass`、`glow`、`scanlines`、`hologram`、`sfx`（开关）、`sfx_file`（自备音效文件，相对项目根）、`sfx_gain_db`。单条 overlay 里可以再写 `title` / `theme` / `position` / `width` / `accent` / `icon` 覆盖。各画风的主题预设见 [styles.md](styles.md) §12。
  - 音效生成不了（ffmpeg 不支持 lavfi 表达式）时打印一行跳过，不报错；要固定音效就写 `sfx_file`。
  - 先看效果：`python3 cut.py --panel-demo /tmp/panel.png --theme tech [--bg 起始帧.png] [--project <项目>]`，出一张中间帧和一段 4 秒预览。
- `stamp`（印章字，例如一个代表"谎言"或"命中"的大字）：`drama.json.overlays.<name>` 定义字形、字号、颜色、发光、透明度、hold、位置比例、抖动。亮起时机 = 谎的那一小句最后一个音落下（`overlay.phrase` 用 ASR 词序列对齐；没写 phrase 才用整段末词），停 hold 秒，本镜内淡出，不跨剪辑点；放在说话人脑后留空的一侧（`side: L/R`，起始帧构图要留出这块空位）。
- 面板里的字同样来自剧本 `[画面文字]`，一条面板只说一件事，中文每行不超过约 16 字、最多 3 行。

## 5. 声音设计（必做）

EP001 成片 43% 的时间是数字静音，没有环境声、没有咔哒和倒带声、没有白光，"回溯"这个核心奇观在视听上等于不存在。每集必须做下面四层：

1. **每场底噪 bed**：`drama.json.beds` 按场景 ID 映射到 wav（`"*"` 兜底），循环铺底，默认 −18 dB；同场相邻镜底声一致。没配 beds 的镜，cut.py 会整片垫一层粉噪房间音（`room_tone_db`，默认 −48 dBFS），这只是防数字静音的保底，不算完成声音设计——每场仍要有自己的底噪（文化祭远处人声、楼梯间空响、教室空调）。
2. **关键动作音效**：shots.json 每镜 `sfx: [{"file", "at", "gain_db"}]`，`at` 是源素材秒，剪点之外的会丢掉。撞击、咔哒（按表冠）、倒带呼啸、金属箱落地、脚步踩空这类音效是叙事的一部分，`sound` 字段里写到的都要落成 `sfx`。音效文件放项目 `音效/`；可以用 MMAudio（`fal-ai/mmaudio-v2`，按画面生成对齐的拟音，付费）或本地音效库。
3. **特效**：白光、闪白、震屏这类视觉特效和它的音效一起设计。cut.py 目前没有 `flash` 叠加类型（G12 只认 text / stamp / panel），白光在成片后用 ffmpeg 补一遍，例如 `ffmpeg -i EP001.mp4 -vf "eq=brightness=0.85:enable='between(t,13.5,13.8)'" -c:a copy EP001_fx.mp4`，写进剪辑单；不做就把"回溯瞬间缺白光"写成风险。
4. **静音上限**：成片按 100 ms 窗口测电平，低于 −50 dBFS 的窗口占比不超过 5%（`ffmpeg -i EP001.mp4 -af silencedetect=n=-50dB:d=0.1 -f null -` 汇总静音时长）；超了就补 bed 或音效再出片。

- **录音垫入**（`audio_from`）：从另一镜的对白抽音，加 phone / hall 滤波后按 `at` 垫进本镜；字幕跟录音走。
- **关键动作音效的 V2A 生成**（MMAudio，或本地的 HunyuanVideo-Foley；后者官方只写了 CUDA，Mac 上先测）：只拿它做音效层；送进去的片段先去掉原声，文本提示写具体声源（例 `metal cash box hits concrete stairs`）；生成结果跑一遍 ASR，出现含糊人声就丢掉 [官方 + 社区]。
- **剪辑点与底噪连续**：同一场的底噪要跨剪辑点连续铺，不在每个剪辑点重新起播；每个剪辑点的音频做 10–20 ms 交叉淡化（或段首段尾各 5 ms 淡入淡出），防止咔哒声 [社区]。cut.py 目前按镜分别铺 beds、不做音频交叉淡化 [自测：读 cut.py]，EP001 的镜间空隙还出现过绝对零电平 [自测]；交付核对要回听剪辑点，有咔哒或底噪断开就在成片后用 ffmpeg 补，并写进剪辑单。
- **配乐**：属于时间线层，成片阶段统一加；生成里一律 `non_diegetic_music: N/A`。**cut.py 没有配乐轨**（EP001 成片无配乐 [自测]），所以配乐在 cut 出片后另做：
  - 剪辑单写一张 cue 表（文件、成片入点、出点、增益、有没有对白压低），每条都要写清。
  - 三个位置要设计 [社区]：开头几秒内有一个声音事件（hit 或上升音落点，配合 EP001 式的开幕遇险）；反转、打脸那一拍用 hit 重音把音乐切到下一段情绪；结尾悬念在最后一句落地后 0.3–0.5 秒硬切到静音或只留底噪。其他位置可以不放配乐。
  - 对白处用 `sidechaincompress` 自动把配乐压低 8–12 dB，台词每个字都要听得清 [官方：FFmpeg]：
    ```bash
    ffmpeg -i EP001_nomusic.mp4 -i music_bus.wav -filter_complex \
    "[0:a]asplit=2[dx][sc];[1:a]volume=-8dB[mx];\
     [mx][sc]sidechaincompress=threshold=0.03:ratio=8:attack=20:release=350[mxd];\
     [dx][mxd]amix=inputs=2:normalize=0:duration=first[a]" \
    -map 0:v -map "[a]" -c:v copy -c:a aac -b:a 192k EP001_mx.mp4
    ```
    改了 threshold、ratio 这类参数后，要重新测响度和真峰，整条命令写进剪辑单。
- **响度**：整体归一到 `loudness`（默认 −16 LUFS）+ 限幅 0.8；用编码后的成片实测 LUFS。注意 `alimiter=limit=0.8` 限的是采样峰值（约 −1.9 dBFS），不是真峰，AAC 编码后还可能过冲 [官方：FFmpeg]；所以真峰也要在 AAC 成片上实测：`ffmpeg -i EP001.mp4 -af ebur128=peak=true -f null - 2>&1 | grep -A12 Summary`，互联网分发要求真峰不超过 −1 dBTP [官方：AES TD1008]。超了就降整体增益或改用两遍 `loudnorm`（第一遍测，第二遍带 `measured_*` 参数加 `linear=true`）重出。
  - 两遍 `loudnorm` 也不保证正好落在目标上：线性增益会让真峰或响度范围超标时，loudnorm 会自动退回动态处理；短片和音效稀疏的片子尤其明显 [官方：FFmpeg]。所以目标值永远不是实测值，交付数字只取编码后成片上测到的 LUFS 和真峰。输出统一 48 kHz（cut.py 已按 48000 重采样），避免 loudnorm 内部升采样直接决定 AAC 采样率。
  - 整片响度达标不等于每句都听得清；还要回听对白和底噪、音效的相对关系（§7 第 4 步）。

## 5b. 接镜色彩与颗粒

生成素材常见两个 take 同一人同一桌，却差一档曝光或半档白平衡，剪在一起像失误而不是剪辑点。

- **先分组再比较**：按同一场景、同一光态分组，挑可比的区域做基准（脸、同一件衣服、中性墙面）。全画面平均 RGB 会被景别、衣服面积和背景左右，只能用来筛查，不能单独决定校正量。夜景和日景、有意的冷暖对比不需要拉到同一均值。
- **怎么量**：`python3 scripts/hub_tool.py measure <项目> <EP>` 按剪辑单的成片位置逐镜报平均亮度和"蓝减红"，相邻同场两镜差得明显时再看接触表确认。
- **怎么校**：在 `审查/<EP>-grade.json` 逐镜写校正，然后 `python3 scripts/hub_tool.py grade <项目> <EP>` 输出 `成片/<EP>_graded.mp4`（不覆盖原成片，音轨直接复制）：

  ```json
  {"shots": {"EP001-S03": {"brightness": 0.06, "warmth": -6}, "EP001-S05": {"saturation": 0.9}}, "grain": 6}
  ```

  `brightness` 是加法偏移（−0.25…+0.25），`saturation` 是倍数（0…2），`warmth` 是冷暖校正量（−30…+30，正数提红压蓝，不是开尔文值），`grain` 是整片动态颗粒（0–20，0 或不写就不加）。这些范围是工具的处理范围，不是画质标准。先小幅校，出片后在同一区域重新量、再看画面，不要把整片均值差按固定系数直接换算成校正量。
- **grade.json 是校正的账**：cut.py 重剪会重写剪辑单和成片，grade 按最新剪辑单的成片位置重新套用，所以校正写在 grade.json 里而不是只写在命令行里；交付的是 `_graded` 版时，剪辑单末尾手写一行"调色：hub_tool grade，校正 N 镜，颗粒 X"。
- 人物身份漂移、光源方向错、缺动作不是调色问题，回生产阶段处理。颗粒只是可选质感，修不了身份、动作和光线错误；要按场景区别处理用外部调色工具，并把决定写进决策记录。

## 6. 冷开场与剪辑单

- 剪辑遵循剧本的叙述顺序；可使用明确标记的回忆或闪前。调整 cut_order 后复核预演和信息权限。
- `剪辑单.md` 由 cut 自动写：每段的镜、take、取用、时长（过短的标出）、成片位置、字幕、叠加、结论，末尾总长、节奏统计、面板主题与个数、声音、AI 标识。它是成片的账，不是创作文档。
- 剪辑单要能复现成片：cut.py 之外做过的每一步（L-cut、白光、配乐 cue、底噪补接、调色、重复插入）都在剪辑单末尾写一行，带整条命令或 grade.json 路径；先改记录再重出片，不让成片领先于记录。重剪时保留未受影响镜的取用不动，改一镜的入出点不连带改别的镜。

## 7. 交付核对

只报数字，不冒充质量结论：成片时长与目标差值；画幅帧率；LUFS 与真峰；每段平均亮度；静音窗口占比。再对成片跑一遍 ASR，比对全集台词表，漏句就回到该镜的取用区间。台词完整性、画内文字、边界帧没测就写"未测"。渲染成功、时长对上、文件存在都只是技术结果，不能写成"这集能看"；能不能看由第 3 步复述和 reviewer 判断。

`python3 scripts/hub_tool.py measure <项目> <EP> [--write]` 一次报出这些数字（时长与目标差、画幅帧率、LUFS 与真峰、静音窗口占比、逐镜亮度与蓝减红），测不了的项写"未测（原因）"；`--write` 存到 `审查/<EP>-交付测量.json`。它不给质量结论。

**边界帧**：每个剪辑点前后各抽一帧看，查意外的黑帧、白帧、半渲染帧和画面断裂（`ffmpeg -ss <剪辑点-0.04> -i EPxxx.mp4 -frames:v 2 cut_%02d.png`，剪辑点取剪辑单"成片位置"）。有意的黑场、静默和光态变化按创作意图判断，不因数值异常直接判错。

成片出来后的固定五步（每集都做）：
1. **每秒抽一帧目检**：`ffmpeg -i EPxxx.mp4 -vf "fps=1,scale=384:-1,tile=6x5" sheet_%02d.jpg`（Homebrew ffmpeg 可能没有 drawtext，别往滤镜里加时间码），逐张 Read：镜序是否按时间顺序、有没有认错人、印章字/面板是否落在对的镜上、叠字有没有压脸。
2. **整片 ASR**：用 `ASR_PY` 的 faster-whisper `medium` 转写整片，比对全集台词表。人名、同音字写法不同（拓海→匠）按听感算通过；任何删词、增词、替换或截断都定位听审，尤其否定、姓名、金额与条件；不能只查整句缺失。别临时换 `large-v3`：本地没缓存时会卡在下载，看起来像死机。

3. **只看画面 + 字幕复述故事**：关掉声音（或只看 1fps 接触表和字幕），按集纲把本集每个情节点逐条复述（例：被撞 → 后仰要摔 → 按表 → 白光回溯 → 预判 → 让开 → 撞空 → 包甩出 → 空箱暴露 → 老师证实）。每一条写"看得到 / 只靠字幕 / 看不到"，看不到的回到对应镜查取用区间、重拍或补插入镜；复述不出来的集不算交付。同时逐条答：每个关键物品、每个新出场人物是从哪来的（成片第几秒看得到来源）？每个事件的起因在成片第几秒？（EP001 的空箱凭空出现在老师脚边就是这一问答不出来。）再看节奏：剪辑单"节奏"一行有没有过短镜、有没有切得太碎的场。
4. **声音核对**：静音占比（§5 第 4 条）；每场有底噪；`sound` 字段写到的关键音效都在剪辑单的音效计数里。另外逐项过 [社区 + 官方]：
   - 真峰 ≤ −1 dBTP（§5 响度，AAC 成片上测）；
   - 剪辑点前后回听没有咔哒，同场底噪不在剪辑点重新起播；
   - 有配乐的台词段每个字听得清；
   - 单声道兼容：手机外放基本是单声道，下混后回听一遍（`-af "pan=mono|c0=0.5*c0+0.5*c1"`），没有明显变薄或消失；
   - 手机外放在最小音量和中等音量各听一遍，台词听得懂。
5. **AI 生成标识**：默认不叠（`ai_label: null`）。用户明确要求时才写文字，cut.py 叠在前 3 秒右上角，剪辑单记「AI 标识：有」。不要自己替用户决定加（用户 2026-09-26：「谁让你加了」）。

**交付物**：成片（和 `_graded` 版，如有）、剪辑单、`审查/<EP>-review.json` 与审片记录、外部混音或调色的命令/配置。说明是否满足用户要求、还有哪些内容缺口；需要补素材、改台词或改分镜时，指出对应镜号和成片第几秒，交回负责的阶段。要把整套资料交给别人，用 `hub_tool.py export`（[project-hub.md](project-hub.md) §3）。

然后按已授权的 Git 交付策略同步（SKILL 硬约束 10），回复里给成片路径。

## 8. 已知坑

- `audio_from` 不写 `filter` 时默认按 `phone`（削高低频、音量偏小）：同场画外人声（拳台上喊话、布帘后说话）要显式写 `"filter": "hall"` 或 `"none"`，否则成片里几乎听不见、ASR 也识别不出（2026-09-25 一拳剧 EP002「何者だ」实测）。只有电话听筒里的声音才用 `phone`；隔玻璃/墙用 `glass`。
- 音源镜也要写审查记录：被 `audio_from` 引用的镜要 `mark --speech-window`，否则新版 cut.py 取不到截取区间。

- Homebrew 的 ffmpeg 没有 libass，烧 ASS 字幕会失败；本工具用 PIL 出 PNG 再 overlay，不依赖 libass。
- faster-whisper 不在系统 Python 里：`ASR_PY` 指向装了它的 python（例如 `~/.venvs/asr/bin/python`；不设则自动扫 `~/.venvs/*`）；模型 `ASR_MODEL` 默认 medium，快测用 tiny。
- 印章字字体：macOS 的教科书体/凸版文久明朝在 AssetsV2 里，Linux 用 Noto Serif CJK；找不到就退到字幕字体。
- H3 无台词镜会自编人声：审片标 mute，剪辑去原声后用底声补。
- 生成素材片尾 0.1–0.2 秒常有异常，full 模式默认去掉 0.2 秒。
