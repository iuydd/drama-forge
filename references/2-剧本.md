# 阶段 C：剧本补充（格式与交接）

> **创作以 [references/编剧/](编剧/00-编剧总流程.md) 为准，本文件只是本流水线的格式与交接补充。** 怎么写好一集（首屏承诺、场景因果、爽点、反转、对白、结尾、审稿标准）都在编剧库；这里只管剧本落成什么格式、怎么过机械门、怎么验证看得懂、怎么交给分镜。两处看似冲突时，创作方法听编剧库，文件格式和门听本文件。SKILL.md 的六条硬规则优先于两者。

创作方法去哪查：

| 要做的事 | 编剧库模块 |
|---|---|
| 首屏承诺、开场 30 秒、场景最小因果、悬念、反转支点、结尾、时长估算 | 编剧/06 |
| 台词在做事、可影像化、对白减负 | 编剧/07 |
| 爽点卡、认可链、爽感饱和 | 编剧/01 |
| 开头 / 回报 / 结尾换着用 | 编剧/14 |
| 认知差、风向反转、连续拉扯、揭晓兑现 | 编剧/15 |
| 人物知道什么、连续性、世界反馈 | 编剧/04 |
| 审稿硬门槛、100 分量表、十二种坏稿 | 编剧/08 |
| 交给分镜必须移交什么、制作复杂度替代 | 编剧/10 |

## 1. 文件格式

每集只维护一份 `EPxxx/剧本.md`，从骨架 `assets/templates/剧本.md` 复制。编剧库的 `EPxx-Sxx` 场景 ID 在本流水线写成 `EPxxx-SCxxx`。

```markdown
# EP001 集名

## EP001-SC001 内 · 地点 · 时间/天气

[连续性] 在场：甲（门口）、乙（桌后）；画外：丙（门外走廊）

动作段落，现在时，一个段落一个行动单位。

甲（把威胁说成提醒｜冷笑·中·慢·小）：台词
乙（辩解｜心虚·弱·快·小｜读音 売上=うりあげ）：台词

[SFX] 会改变注意或信息的关键声音
[画面文字] 观众必须读清的文字（后期叠加）
[OS] 丙：画外同场人物的台词
[VO] 甲：不在现场的主观声音（心声、叙述）
[转场] 有叙事意义的转场

[连续性] 退出状态……必拍：①… ②… ③…
```

- **场次标头** `## EPxxx-SCxxx 内/外 · 地点 · 时间`：场次 ID 是分镜主键；地点或时间一变就新开一场，标头和场内动作一致。
- **每场第一行是在场名单** `[连续性] 在场：…；画外：…`，只有主角看得见的角色也列上。场内有人进出，在那一拍的动作行写路线。分镜的 `scene_state` 从这行抄。
- **对白行** `角色（策略｜情绪·强度·语速·音量）：台词`，全角冒号。括号里只写能和这句同时完成的东西；独立动作、接触道具、产生新状态的内容拆成动作行，否则下游漏拍。
- **只有六种标签**：`[SFX]` `[画面文字]` `[OS]` `[VO]` `[转场]` `[连续性]`。
- **动作行不以"短语＋冒号"开头**：`他写下两个字：军宣。` 会被解析成说话人，改成 `他写下两个字——军宣。`
- **不写 HTML 注释、不写镜头**：备注写进 `项目开发/决策记录.md`；剧本里不出现景别、机位、运镜、提示词、模型字段。空间事实（谁挡着门、谁看得见字）要写。
- **群演概括写**（"围观的学生们"）；有台词或以后回归的才单独建人物。
- **台词语言**按 `drama.json` 的 `dialogue_lang`，用目标语言直接写母语口语，不从中文翻；称谓、敬语、一人称按人物关系定并全剧一致（写进视觉设定人物条目）。
- **专名读音**放在表演提示括号最后一项 `｜读音 売上=うりあげ`；全剧反复出现的写进 `drama.json` 的 `readings`。
- **画面不出字**：手机屏幕背对镜头，文字一律走 `[画面文字]` 后期叠加。

```bash
python3 scripts/screenplay_lint.py <项目> EP001        # 0 error 才能往下走
python3 scripts/screenplay_lint.py <项目>/EP001/剧本.md --json
```

查场次标头、重复 ID、未知标签、半角冒号、注释、行首冒号、缺情绪标签、镜头术语、缺「必拍：」（SP13，error）、缺在场名单（SP14，warn）。它只证明格式没错，不证明观众看得懂。

**现成剧本接入**（用户交来的别的格式）：原文按字节存进 `项目开发/原稿/<EP>-原稿.<ext>`；只做最小映射，**台词逐字保留**，原稿缺的时段不按上下文补；改了说话人、先后、因果、语气的地方列进决策记录的"语义变化表"。

## 2. 情绪标签

每句台词带 `情绪·强度·语速·音量`，四项写全。配音和视频模型只会照写的演，不写就是平读。

| 项 | 取值 |
|---|---|
| 情绪 | 一个具体的词：惊慌、愤怒、冷笑、轻蔑、委屈、强装镇定、得意、心虚、决绝…… |
| 强度 | 弱 / 中 / 强 |
| 语速 | 慢 / 中 / 快 |
| 音量 | 小 / 中 / 大（大 = 喊出来） |

标签要和同一拍的动作一致：喊"惊慌·强"的那一拍，动作行写身体后仰、手乱抓，不写站着不动。分镜把标签逐字抄进 `dialogue[].emotion`。

## 3. 心声 [VO] 与画外 [OS]

- 写成 `[VO] 角色：台词` / `[OS] 角色：台词`。`[OS]` 是同场画外人物说话；`[VO]` 是不在现场的主观声音，不能代替本该看见的行动。什么时候该用心声、什么时候必须出声说给对手，按编剧/07。
- **心声是剧情装置时**（例如"全家能听见她的心声"），每句心声后面都跟一个听见者的可见反应，否则观众分不出是普通旁白还是被听见的心声；她本人对"被听见"的认知状态全集保持一致。

## 4. 必拍事实与 [连续性] 行

每场最后一行 `[连续性]` 末尾写「必拍：①… ②… ③…」，每场 3–5 条（短场至少 1 条）：**去掉台词、只看画面也必须读到的事实。** 只收五类：

- 数量：`箱子打开：上排五件、下排五件，正好十件。`台词说十件，动作行也是十件。
- 谁做了什么：写成可表演的动作，不写"他认输了"。
- 状态：剑断在地上、支票撕成两半。
- 反派具体损失：落到看得见的东西上（钱、证据、位置）。
- 身份：谁进来了、谁在场，容易认错的写清外观差异。

必拍事实写进剧本就不可妥协：拍不出只能重拍、改分镜或回来改剧本，"台词能解释"不是放行理由。分镜照抄成 `scenes[].must_show`。它就是编剧/10 §3 "连续性锁定表"在本流水线的落点，不另建一张表。

同一行写退出状态：谁在哪、正要做什么；谁知道/不知道什么；谁拿着什么；哪项动作已不可撤回。集尾那场同时写下一集前 5 秒要发生什么。

**改事实要全剧追**：改了数量、金额、时间、谁拿着、谁知道，全剧 grep 这条事实和由它推出的东西，剧本、跨集记忆、shots.json 逐处核对。台词只在剧本阶段改。

## 5. 盲看复述（SKILL.md 规则 1，交审前必做）

EP001 第一版失败在两处：原著里靠上下文才成立的短台词被单独搬进剧本；核心设定全集没有一个一眼看懂的时刻。写作者自己觉得懂不算，要让没看过材料的人复述。

剧本过了 `screenplay_lint` 之后、派 reviewer 之前：

1. 复制一份去掉 `[连续性]` 行的剧本（在场名单和必拍是写给下游的）存到 scratchpad。
2. 先在决策记录写好"标准答案"（下面 1–3、5 四项）。
3. 用隔离方式派出：`bash scripts/isolated_agent.sh <项目> <任务书> worker`（不降级模型）。只给本集剧本（可附上一集已通过的剧本），不给 `项目开发/`、原著、审查文件的路径。
4. 任一项说错、说"看不懂"、或第 4 问列出的句子涉及剧情关键句 → 改剧本（补前因、补装置的可见事件、删依赖原著的台词），改完换一个新子代理重做。
5. 复述原文存为 `审查/<EP>-盲看复述.md`，首行 `结论：PASS` 或 `结论：REVISE`，附对照结果。

任务书模板：

```text
你是一个第一次看这部短剧的普通观众。你没看过原著，也不知道任何背景。
下面是这一集的剧本：动作行是你在画面上看到的，"角色：台词"是你听到的，
[VO] 是某个角色的内心声音，[OS] 是画面外有人说话，[画面文字] 是屏幕上叠的字。

只根据这份剧本回答，不要猜作者意图，不要补剧本里没有的信息。看不懂就直接说看不懂。

1. 用三到五句话复述这一集发生了什么。
2. 主角是谁？她现在处境如何？她想要什么，什么在挡着她？
3. 这部剧有什么特殊设定（能力、系统、装置）？它的规则是什么？谁知道这个设定，谁不知道？你是从哪一句或哪个动作看出来的？
4. 列出所有你读到时会问"这是什么意思""这东西哪来的""这人为什么这么做"的台词或动作，逐条引原文并说明哪里不懂。没有就写"无"。
5. 最后一场结束时，你最想知道接下来会发生什么？

<剧本全文>
```

## 6. 剧本审查（reviewer 一轮）的流水线手续

审什么按编剧/08（硬门槛 → 证据式审稿 → 最严重三个问题；用了认知差另做编剧/08 §5 专审），本流水线只加手续：

- 盲看复述 PASS 之后，派没参与写作的 reviewer：`bash scripts/isolated_agent.sh <项目> <任务书> reviewer`。给它剧本、系列简报、本集集纲、盲看复述结果；改编项目再给原著对应章节，重点查从原著直接搬来、离开上下文就不懂的短台词。
- 只审一轮，只拦会让观众看错、看不懂、剧情事实前后矛盾的问题（Blocker / Major）；口味问题写"建议"，不阻塞。
- 结果写 `审查/<EP>-审查.md`（骨架 `assets/templates/审查.md`），带 `剧本指纹：` 行（`python3 scripts/project_tool.py fingerprint <项目> <EP>` 打印），写完跑 `python3 scripts/review_md_check.py <审查文件>`。每条问题写位置（场次 + 原句）、为什么观众会看错、最小改法。
- 编剧库之外加查三项：每场有在场名单和「必拍：」且数字与台词一致；每句有情绪标签、是目标语言母语口语；装置心声每句后有听见者反应。
- 写作者改完由主会话逐条核对，reviewer 不审第二轮。同一问题改两次不过，回上游（集纲、系列简报）改或记入决策记录未决项。

## 7. 交给分镜前的清单

编剧/10 §2 要求移交的内容，在本流水线落在这些位置，逐项确认：

- [ ] `screenplay_lint.py` 0 error
- [ ] 角色/地点/道具稳定 ID 和可识别特征 → 系列简报人物表，D 阶段写进视觉设定与 `refs.json`
- [ ] 场景时间轴、在场人物、动作先后、对白与声源 → 剧本本身（在场名单、动作行、`[OS]`/`[SFX]`）
- [ ] 每个爽点必须被看清的证据、前后连续性 → 每场「必拍：」与退出状态
- [ ] 结尾停留状态与下一集入口 → 末场 `[连续性]`
- [ ] 难拍内容及不损失回报的替代（编剧/10 §4）→ 决策记录一行
- [ ] 盲看复述 PASS（`审查/<EP>-盲看复述.md`）
- [ ] reviewer 结论 PASS，指纹等于当前剧本
