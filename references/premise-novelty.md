## 0. 用户口味（本项目的第一优先级）

用户原话的意思：点子要**新颖**、要**吸引人**，最重要的是**让观众爽**；老套点子没人想看，做出来等于浪费钱。所以：

- 立项要先按 §6 出候选、打分、选一，不能只出一个点子就开工。
- "新"指爽的**来源**新，不是换一个更炫的感知能力。情绪内核（受气—逆袭、护短、被看不起后翻盘）照用，头部爆款证明观众仍然吃这一套。[平台数据] 见 §9 的《十八岁太奶奶》条目
- 新颖和爽冲突时，爽优先：一个新但不爽的点子同样是浪费钱。§7 检查表 50 分里只有 A1、A5 两项管新颖，其余都管爽；新颖项满分而总分不到开工线，照样不开工。

## 1. 饱和设定清单：可以用，但必须带新内容

下表这些设定**不是不能用，而是要有新内容**。用了其中任何一个（包括用户点名要的），就在系列简报候选表的"新在哪里"一栏写清楚新在哪里，并记进 `项目开发/决策记录.md`。

**新内容**指至少一项实质创新：

1. **新规则 / 新限制**：能力有此前没人写过的触发条件、次数、范围或冷却；
2. **新的使用场景**：同一能力用在此前没人写过的场合或职业里（金手指不设代价，只设限制，见 SKILL.md 6a）；
3. **新视角**：从反派、配角、受害者的视角讲这个设定；
4. **新的兑现方式**：爽点不再是"当场揭穿打脸"；
5. **新的反派反制循环**：反派知道或摸清了这个能力并开始针对它，形成每集升级的攻防；
6. **与另一引擎的新组合**：和 §4 的另一种爽感引擎叠在一起，组合本身前所未见；
7. **新的世界观 / 职业承载**：放进一个这个设定从没用过的世界或行当，并且那个世界的规则真的改变了能力怎么用。

"新在哪里"按固定格式写：「第几种新内容（上面 1–7）｜EP00x 第几场｜观众看见的那个画面（谁做了什么）｜老路数在同一处会怎么演」。最后一栏写不出来，或这句话原样搬到别的候选上也成立（搬家测试，SKILL.md「防钻空子总则」第 7 条），就是套话，按没写算。只换皮（换题材、换名字、换道具、换能力名，比如"看见谎话"换成"听见心声"）不算新。

## 2. 同质化一句话测试

每个候选都过一遍，任一条命中说明还没有新内容：先补新内容（§1 的七种之一，或 §3 的生成法），补完再进打分。[推断]

1. **能压成"主角多了 X 能力，所以当场揭穿 / 打脸 Y"** → 还没有新内容，补新内容后再进打分。
2. **拿掉信息优势**：把"主角知道别人不知道的事"删掉，爽点还在吗？不在就是老路数。
3. **路人一句话反应**：一句话讲完设定，路人的反应应该是"真的假的？"或"那不就……"（想往下猜），而不是"然后呢？"
4. **独占画面**：前 3 秒能不能拍出一个只有这个设定才会出现、不靠字幕就看得懂的画面（测力石裂开、长老对小丫头磕头、雷公停在半空谈价钱）？

## 3. 新点子生成法（10 种）

每个候选标注用了哪一两种；一次出多个候选时，候选之间尽量用不同的法。[推断] 归纳自 novelty-mechanics 报告 §3，修仙示例均为原创草稿。

| # | 生成法 | 做法（一行） | 修仙示例 |
|---|---|---|---|
| 1 | 反转常识 | 列出题材里人人默认的常识，倒过来一条，问新世界里谁最占便宜 | 修为越高越短命，所以真大能都拼命藏修为；主角是被迫当众测修为的天才，只能装废物 |
| 2 | 能力有边界 | 给力量配一条看得见的限制（次数、范围、条件、冷却），让主角在限制内想办法赢，而不是付代价 | 每挥一剑就忘掉一个人；为救师妹连出九剑，回头问她"姑娘你是谁" |
| 3 | 配角职业当主角 | 从爆款里挑一个被忽视的工具人（裁判、护道人、秘境 BOSS），问他最大的委屈和最大的权力是什么 | 被天骄打了一千年的秘境守关妖，这一回决定不演了 |
| 4 | 爽点挪到规则漏洞 | 主角不比别人强，只比别人懂规则；高潮是"规则判定"，不是放大招 | 宗规禁止筑基以上对炼气出手，他就永远卡在炼气九层不突破 |
| 5 | 限制越狠越爽 | 给主角一个一眼可见的残缺或禁令，再设计一个只有带着它才能赢的局 | 立誓一生不拔剑；大比最后对手的魔剑专吞出鞘剑气 |
| 6 | 身份或辈分错位 | 外表地位和真实地位相差到极致，放进最讲身份的场合（祠堂、寿宴、拜师礼） | 杂役闭关睡了三百年，现任掌门是他当年捡回来的小乞丐，全宗得叫他太师祖 |
| 7 | 现实制度搬进修仙 | 挑一个观众亲身痛过的现代制度（贷款、KPI、考试、选秀、裁员）原样装进去 | 主角是天庭法力贷唯一的催收员，全宗天骄都欠他寿元 |
| 8 | 观众全知反讽 | 真相先告诉观众、不告诉剧中人；爽在看别人误判。知道真相的是观众，不是主角 | 隐世大宗集体装穷，扫地大爷是渡劫期，少宗主下山挨欺负，老祖们连夜"路过" |
| 9 | 组合倍率爆表 | 单个很烂的东西组合起来乘法叠加，每集一次"算分"时刻（数字走后期叠加，生成画面不出字） | 扫地诀 × 烧水诀 × 晒被诀同时运转，测力石裂开 |
| 10 | 反向目标 | 主角想要的和观众以为的相反（想输、想被开除、想低调），越努力越成功 | 一心想被逐出师门回家卖凉茶，考核交白卷，白卷上的茶渍恰是失传阵图 |

## 4. 爽的来源：不靠感知外挂的引擎

候选的"主引擎"一栏从这里选，写表里的引擎名。每个都不要求主角有感知能力。[推断] 归纳自 novelty-shuang 报告 §3 与 novelty-hits 报告 §4。

| 引擎 | 观众爽在哪 | 兑现层级（§5） |
|---|---|---|
| 迪化（误会抬轿） | 主角做普通事，旁人脑补成高深布局；观众和主角一起知道真相 | L4 + L6 |
| 苟道 / 拒绝当主角 | 越想低调越藏不住；终于不躲的那一下 | 平时 L2，大卡点 L4/L5 |
| 规则漏洞 / 合规反杀 | 反派用规则压人，主角用同一套规则把他钉死 | L2 → L3 |
| 追放崩塌 | 主角被赶走，原集体一样样出问题，欺负他的人来求他 | L4 |
| 自食其果 | 反派的手段反噬自己，主角甚至没动手 | L5 |
| 身份 / 辈分错位 | 小身体里装着大人物；讲身份的场合被降维 | L3 + L6 |
| 集体翻盘 | 把同样受气的人组织起来一起赢（用具名个体轮流出单人镜） | L3 + L6 |
| 限制内取胜 | 在能力够不着的地方靠布局补上；观众知道她只有一次机会 | L2 → L4 |
| 资源反差经营 | 别人饿着，我满仓；从一堆火建起营地 | L3 |
| 职业手艺 | 看得懂"他是怎么赢的"（千术、验尸、修复、阵法） | L2 → L3 |

story-engine §1 的五个主爽点类型照用；上表的引擎回答"这个类型的爽靠什么触发"。"能力碾压"只作辅类型，除非 §7 的 A4"不靠能力碾压也成立"拿到 2 分。

## 5. 打脸层级 L1–L6

| 层级 | 内容 | 备注 |
|---|---|---|
| L1 口头 | 一句狠话，对方语塞 | 局势没变，不算兑现（story-engine §6） |
| L2 事实 | 证据或结果当场证明对方错了 | 要第三方或记录生效 |
| L3 资源 | 对方失去钱、位置、权限 | 可核对的损失 |
| L4 关系 | 对方意识到弄丢了主角这个人（后悔、求回来） | 追放ざまぁ的核心 |
| L5 自食其果 | 对方害主角的手段反噬自己 | 最爽，不需要主角强 |
| L6 群体改判 | 旁观者集体改口 | 放大器，叠在 L2–L5 上用，单用显假 |

系列曲线逐级升：前几集 L2，中段 L3–L4，大卡点给 L5。过去五个点子几乎都停在 L1–L2。[推断] 综合 novelty-shuang 报告 §1.3

## 6. 立项流程：≥6 候选 → 快筛 → 选一 → 全表打分

0. **先查市场**：读 [market-hits.md](market-hits.md) §1–3，确定目标平台和形态（真人 / AI 仿真人 / AI 漫剧，对应 `style_preset`），列出本次可以对标的 2–3 个爆款组合（题材 × 金手指 × 形态）及其长青度。候选不必照抄对标组合，但每个候选都要标注对标的组合和长青度；对标栏写 market-hits §1 表里的组合原文，加一部代表剧名（或 CSV 综合排名号），要能回查；找不到对标的写"无先例"，A7 按 0 分，理由写进决策记录。修仙玄幻另读 market-hits §4。
1. **先写现实之气**：一句话说出观众在现实里受的哪种气（被 KPI 压、被亲戚比较、被平台规则收割、被前公司轻视、被婆家试探）。越具体代偿越强。[行业] 网易短剧显微镜 2025-03-19 https://c.m.163.com/news/a/JR21KBFV0517D4E0.html
2. **出 ≥6 个候选**，写进系列简报 `## 立项候选`。约束：
   - 两两**机制不同**：不能都是"主角多一个感知能力"，感知/读取类最多一个且必须写清新在哪里；任何两个候选主引擎（§4）不能相同。
   - 至少覆盖三类：规则类（法 4/7/9）、身份与关系类（法 6/8）、世界观或职业类（法 3/7），每类至少一个。
   - 和最近三个项目用过的主引擎不同：候选表下写一行「近三项目：<路径>=<主引擎>；…」；查不到就写查了哪个目录，A5 最多给 1 分。
   - 用户给了点子时，用户的点子算一个候选，另补 ≥5 个作对照；用户点名要饱和设定，照做，并写清新在哪里。
3. **每个候选写一行**：一句话钩子｜前 3 秒画面｜主引擎（§4 表名）/ 第一次兑现是什么｜秘密 + 时钟 + 见证者｜新在哪里（用了饱和设定时必填）｜对标爆款 / 长青度（market-hits §1、§3，例如"修仙 × 废柴 + 外物 × 3D 漫｜长青"）｜用了哪几种生成法｜快筛逐项分。昙花一现型要写明按单部打爆规划，或补了哪条可升级的进度条。
4. **快筛打分**：用 §7 标 ◆ 的 7 项（A1–A5、B1、C1）给每个候选逐项打分（满分 14，写成「2 1 2 1 2 2 1 = 11」）；另派没参与出候选的 reviewer 子代理，拿删掉分数列的候选表盲打这 7 项，两份分并列写，按两份之和排名；任一份合计低于 7 的候选不计入 ≥6 个。★ 项 0 分直接淘汰；最高分入选，同分选更新颖的（和饱和设定清单、和最近项目距离更远的）。
   **前三名补一张机制差异表**（写在候选表下面，不改候选表的列）：主角惯常策略｜主要对抗机制｜退出成本｜引擎终止条件｜主要制作负担（群戏、特效、可读文字、跨时间造型、儿童角色）｜擅长提供什么｜会牺牲什么。每个方案都写"会牺牲什么"，避免三个都被包装成最优；如果三列只差职业、地点或秘密名称，说明候选并不真的机制不同，回第 2 步重出。
5. **选定后全表打分**：入选点子按 §7 全表打分写进 `## 爽感打分`；情绪集纲（阶段 B）写完后再打一次 C 组，分数变了就更新。
   **分歧按证据解决**：作者评分后由第 4 步的独立 reviewer 复核全表，逐项引系列简报的具体内容；分差 ≥2 或 ★ 项判断不同，只重查争议项，不默认启动 3–5 轮投票。正式分采用证据能支持的分值，未解决的分歧取较低分，不为过线润色评分。保留两份原始分与修订理由。模型间一致只说明检查意见一致，不能当观众样本；下一步按 [audience-feedback.md](audience-feedback.md) 做最早可用片段的现实验证。
6. **无人值守**时按分数自选并记决策记录；用户在场且要看点子时，给前三名（钩子 + 分数 + 一句理由）由用户挑。落选候选记在 `## 立项候选` 里只作对照，不进入既定事实；以后要借用落选点子的某个部件，先改系列简报并记决策。
7. **改编项目**：原著的核心设定和结局承诺是用户的契约，算一个固定候选，不因打分低就换掉；打分用来找弱项（例如 A4、B2），用改编手段补（开篇替换点、换载体、删线），见 [adaptation.md](adaptation.md) §6。另补的 ≥5 个候选改成"同一原著的不同改编方向"（换切入点、换主视角、换主爽点类型），不另起原创点子。

## 7. 爽感检查表

## 8. 修仙题材：最爽的场面与用烂的写法

| 最爽的场面 | 让它不老套的改法 |
|---|---|
| 越级战 | 赢在布局和限制内的巧用，不是临场爆种；赢完带出新问题 |

| 法宝 / 丹药反杀 | 物件规则提前种下，观众先知道、反派不知道 |
| 宗门大比 | 比赛规则本身有漏洞，主角是唯一读懂的人 |
