## 1. 生产纪律

1. **串行**：提交前查 `/api/status`，`running` 空且 `queued` 为 0 才提交；一次只有一个任务在飞。写作阶段可并行，生产阶段全项目串行。
2. **先入账再轮询**：POST 返回任务号立刻写 `脚本/ids.log` 和 `脚本/jobs.jsonl`（含 profile、res/seconds、seed、prompt sha256），早于第一次轮询。
3. **只重试 GET，POST 永不自动重发**；网络断开就等，不放弃已提交的任务。
4. **先收回再重投**：提交前先查 `jobs.jsonl` 里同名（同镜同 take）有没有已提交未收回的任务；有就 collect，不重新 POST。进程被杀后重跑同一命令即可。
5. **落盘校验**：下载写临时文件，校验非空和文件头（PNG 魔数 / MP4 `ftyp`），再原子改名。
6. **全参数显式**：profile、res、seconds、seed、aspect、image_mode 每次显式传，不靠服务端默认。
7. `STOP` 文件当前任务做完后停；`DEADLINE=YYYYmmddHHMM` 到点不再提交。
8. token 只从 `H3_STUDIO_TOKEN` 读；不写进任何文件。
9. 不删产物：重拍开新 take，旧 take 留着；参考图重出把旧图改名 `_oldN`。

## 2. 命令与 take 机制

```bash
python3 scripts/produce.py refs   <项目>                  # 参考图：refs.json 全部，已有跳过
python3 scripts/produce.py frames <项目> EP001            # 起始帧 take1；已有跳过；--retake 开新 take
python3 scripts/produce.py videos <项目> EP001 --asr      # 视频：ASR 不达标自动重拍到 max_takes，选最好的 take
python3 scripts/produce.py all    <项目> EP001 --asr
```

种子由 `剧名:镜:种类` 派生并随 take 递增，可复现；`SEED_OFF` 环境变量整体平移。视频用的起始帧是 `review.json` 里 `frame_take`（默认最新）。

## 3. 金丝雀

每集开工，以及新角色、新场景首次出场时，先跑 **一个代表镜头**（最能检验身份、场景、音色的那一镜）：参考图 → 起始帧目检 → 视频 → ASR + 看接触表。通过才放行整集；不过先修资产或提示词，不在批量烧完队列后才发现资产有问题。

## 4. 参考图与起始帧的目检

脚本管不了"像不像"，这一步由模型用 Read 看 PNG。逐张按四类打标签，再决定：

| 标签 | 含义 |
|---|---|
| visibly confirmed | 看得见且符合关键帧描述 |
| absent / unclear | 描述里有、画面里没有或看不清（例如手里的底牌） |
| conflicting | 画面与描述矛盾（朝向反了、服装不对） |
| contaminated | 多出来的人、水印、可读文字、参考图带进来的东西 |

**身份图**通过条件：一个人、正面、全身、素背景、中性表情、无可读文字、不带以后要消失的饰品；和视觉设定的识别锚点一致。
**底板**通过条件：无人、无字、画左画右各是什么与轴线声明一致。
**起始帧**通过条件：一人（插入镜除外）；朝向 = `facing`；持物、位置、表情与 `keyframe` 一致；印章字要放的一侧留空；身份像参考图；物理可达（手够得到要拿的东西，动作能从这个姿态开始）。

不过：`produce.py frames <项目> EP --retake` 最多到 `max_takes`；仍不过就只改失败的那一项提示词（单变量），再拍。负面词擦不掉已经画进去的东西——起始帧里多了个人，就换构图或换参考，不是加 "no extra people"。通过：`review_tool.py mark <项目> EP <镜> --frame-take N`。

## 5. 视频审片三层

| 层 | 工具 | 查什么 |
|---|---|---|
| 脚本 + ASR | `review_tool.py asr` | 台词完整性（LCS 命中率 ≥ `asr_pass`）、句尾截断、无台词镜冒人声、反应开口延迟、实际语速（校准 `speech_rates`） |
| 脚本 + 抽帧 | `review_tool.py sheets` | 2 帧/秒接触表；开头静止、结尾回弹、闪白、画面出字、多出的人、身份漂移 |
| 模型看图 | Read 接触表 | 唯一动作是否发生、看不看得懂；终点姿态与持物；反应是否可读；口型落在谁脸上；相邻镜轴线、视线、服装连续；表演强度是否相称 |

画质不作重拍理由。审的是剧情、动作可读、台词完整、有无出字、有没有认错人。静音看一遍接触表，冲突还能不能读——这是口型或配音失败时的兜底。

`review_tool.py auto` 先按 ASR 给默认 verdict（ok / weak / retake / mute / missing），模型看图后用 `mark` 覆盖并锁定；`report` 汇总成 `审查/<EP>-审片.md`。

## 6. finding 与处置

每条问题写：位置（镜、take、秒）、证据（ASR 文本 / 接触表第几格）、影响、处置、最小修复。四级规则：脚本能证明的阻断；语义问题带证据判断；手感只警告；口味不阻断。

**先定处置再修订**（五选一）：
- 保留；
- 后期处理（入出点、去原声、换底噪、叠字）；
- 局部编辑（只一层错，改那一层）；
- 重新提交（文字无缺陷、像随机；同一输入原样重投 ≤2 次）；
- 改写（同一缺陷已复现，回提示词改结构：一次只改诊断变量，写 change_set + preserve_set）。

失败三路：技术失败（超时、限流、5xx）有上限原样重试；点名被拒的输入只改那一项；重复出现的内容缺陷回提示词 owner。改写后回归六行义务：原文覆盖｜镜头目的｜起止与时长｜资产与连续性｜对白文字声音｜项目配置，逐行记保留/丢失/改变——自动改写最常见的副作用是"变短了但丢了台词或反应"。

缺陷三分法（谁负责）：故事坏了重写剧本；身份坏了重做资产；执行坏了重新生成。不靠堆负面提示词修补。

## 7. 自动重拍决策表

| 缺陷 | 检测 | 首次处置 | 复现后 |
|---|---|---|---|
| 台词缺字、句尾截断 | ASR 命中 < 0.6；最后 0.2 秒仍在发声 | 原样重投（换 take = 换种子） | 开口前移到 0.25s、删并行动作、秒数 +1～2；仍不行拆镜；不改台词 |
| 无台词镜冒人声 | ASR 有词 | verdict=mute（剪辑去原声） | 重投并补 "He says nothing. No other voices speak words." |
| 反应开口晚于 1 秒 | ASR 首词时间 | 后期：入点移到开口前 0.15s | 剪掉后动作不完整才重投，正文改 at the same instant |
| 画面出字、乱码 | 接触表 | 原样重投 | 查起始帧/参考图是否带字，裁切或重出 |
| 认错人、多出人 | 接触表 | 原样重投 | 重出起始帧；正文加 "Only one person in the frame" 同义正向句 |
| 首帧与起始帧不符 | 接触表第一格 | 原样重投 | 查 frame_take 绑定 |
| 开头静止、结尾回弹 | 接触表 | 后期收紧入出点 | 可用带短于台词 + 落点才重投 |
| 关键动作没发生 | 模型看图对照 motion / end_state | 原样重投一次 | 按可生成性阶梯改写动作 |
| 口型落在画内别人脸上 | 模型看图 | 重投 | 画内人背身或出画；加 lips remain completely closed |
| 冒出配乐 | 听 / ASR 备注 | 重投 | 核对 non_diegetic_music: N/A |
| 超时、429、5xx | 客户端 | 等待 / 有上限重试 | — |

## 8. 取用区间的自动规则

- 有台词镜：入点 = max(0, 首词开口 − 0.15)；开口晚于 1 秒直接剪前段；出点 = 末词结束 + 0.5（印章字镜 + hold + 0.1），不超过素材 − 0.1；留白结尾（`to_end`）= 末词结束 + 0.02。
- 无台词镜：整条去尾 0.2 秒（`full`），模型看图后按接触表用 `mark --in --out --mode fixed` 收紧。
- 动作偏慢可 `--speed 1.3`（≤1.5），配拉扯声。
- 字幕文字取剧本，时间取 ASR；重出素材后重新 ASR（缓存按文件 mtime）。

## 9. 预算与停止

- 每镜最多 `max_takes`（默认 3）个视频 take；起始帧同样。
- 每集提交上限 = 镜数 × 1.5 的视频任务；到上限就带着 weak 镜进剪辑，记录未决。
- 同一镜连续两轮"改写 → 重投"仍不过，标 weak 并写决策记录，不无限循环。
- API 连不上：写作阶段照做，生产阶段停下并写明原因；这是流水线里唯一需要人的情况。
