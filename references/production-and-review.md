## 1. 生产纪律

1. **串行**：提交前查 `/api/status`，`running` 空且 `queued` 为 0 才提交；一次只有一个任务在飞。写作阶段可并行，生产阶段全项目串行。
2. **先入账再轮询**：POST 前写 `submission_intent`、返回任务号立刻写 `submitted` 到 `脚本/ids.log` 和 `脚本/jobs.jsonl`（含 profile、res/seconds、seed、prompt sha256；视频另记 `frame_sha256`、`source_prompt_sha256`），早于第一次轮询；收回写 `collected` 并记产物 `sha256`。审片批 ok/weak/mute 前脚本按这些字段核对 take 来源（没有收回记录、收回后文件被换、生成后改过 video_prompt 或所选起始帧，都拒绝批准）。
3. **只重试 GET，POST 永不自动重发**；网络断开就等，不放弃已提交的任务。
4. **先收回再重投**：提交前先查 `jobs.jsonl` 里同名（同镜同 take）有没有已提交未收回的任务；有就 collect，不重新 POST。进程被杀后重跑同一命令即可。
5. **落盘校验**：下载写临时文件，校验非空和文件头（PNG 魔数 / MP4 `ftyp`），再原子改名。
6. **全参数显式**：profile、res、seconds、seed、aspect、image_mode 每次显式传，不靠服务端默认。
7. `STOP` / `DEADLINE` 在等待空闲和提交前都生效，已提交任务可继续收回。请求响应未知时按 [运行边界与恢复](runtime-boundaries.md) 对账；下载失败只重试收回，不能当作生成失败重投。
8. token 只从 `H3_STUDIO_TOKEN` 读；不写进任何文件。
9. 不删产物：重拍开新 take，旧 take 留着；参考图重出把旧图改名 `_oldN`。
10. **提交前做恶意执行预演**：每条提示词（参考图、起始帧、视频）提交前按 [video-prompts-general.md](video-prompts-general.md) §2b 第五部分写 3 个「完全符合字面但最差」的成品和各自的堵法，写进本镜（参考图写进 refs.json 条目）的 `adversarial_preflight`；有一条堵不住就先改提示词或改结构，不提交。少于 3 条时 `produce.py refs/frames/videos` 拒绝提交；引句不在提示词里、worst 重复由 `shots_tool.py check` / `check-refs` 报 G52 error。
11. **串行等待用锁文件**：多个等待/排队脚本之间用 `mkdir <lock>` 成功才跑，别用 `pgrep -f produce.py` 判断空闲——等待脚本自己的命令行里也有这个字符串，几条会互相死等（实测空转 1.5 小时）。
12. **删过镜的编号不复用**：新镜头 ID 往后排；确要复用，先把旧的 `起始帧/F_<sid>_t*.png`、`视频/V_<sid>_t*.mp4` 改名归档，否则会拿旧帧连拍作废。
13. **参考图有依赖**：refs.json `refs` 引用的图要先生成；`produce.py refs` 碰到依赖未出会停，先出被依赖的道具图/主底板再跑全部。
14. **官方接口通道**：用户把视频、配音、配乐或参考图指定给 MiniMax 官方接口、Seedance 或 GPT Image 2 时，走 `scripts/providers.py`，参数、限制与失败收回见 [providers.md](providers.md)；它和中转共用同一本账（`脚本/jobs.jsonl`），上面 1–13 条同样适用。

**H3 实拍经验**（两部剧 EP001 实测，后续照做）：
- 开口常比写定时间晚 1–2 秒，且会把台词拉长填满镜长：审片时入点剪掉开口前干等；印章字镜素材不够时 `cut.py` 会尾帧定格补足，不必为此重拍。
- 手机屏幕会在视频里自己翻向镜头：只取屏幕还背对的那一段（fixed 出点），或写成手机贴耳、扣在桌上。
- 门大开会带出门外虚化人群：只有看不清脸、不承担剧情时才接受（§4b 第 9 项），提示词别写「门大开」。
- 由手或上半身带动的动作（碰倒酒杯、酒洒满桌布）一条一个能拍出来；整个人失去平衡的动作（滑倒、摔倒）拍不出来，分镜直接换拍法（E36）。其余拍不出的动作按 §7「关键动作没发生」改写或改分镜（插入镜、双人同框）。承担剧情的动作（must_show 承担镜、duty 关键动作）不能 weak，也不能靠前后镜交代（§5c）；只有不承担剧情的动作才可记 weak。
- ASR 自动重拍会误判：假名/汉字写法不同（いったぁ→痛った）、人名识别错（澪→サヨウ）拉低命中率；`drama.json` 的 `readings` 会让比对多试一次读音。ASR 分歧只能由 readings 重比对消掉，或由真人（用户或用户指定的母语者）听审确认；模型听不到声音，不能用"听感"推翻 ASR。

## 2. 命令与 take 机制

```bash
python3 scripts/produce.py refs   <项目>                  # 参考图：refs.json 全部，已有跳过
python3 scripts/produce.py frames <项目> EP001            # 起始帧 take1；已有跳过；--retake 开新 take
python3 scripts/produce.py videos <项目> EP001 --asr      # 记录 ASR 差异并选候选，仍需看图、听审；不按分数自动重拍
python3 scripts/produce.py all    <项目> EP001 --asr
```

种子由 `剧名:镜:种类` 派生并随 take 递增，可复现；`SEED_OFF` 环境变量整体平移。视频用的起始帧是 `review.json` 里 `frame_take`（默认最新）。

## 3. 金丝雀

每集开工先按实际风险选少量代表镜：身份近景、接触交接、最长对白、多主体或新场景。一个样片可覆盖多个风险；在授权预算内验证高风险后再批量。失败先定位资产、提示词或容量原因，不原样盲重试。

## 3b. 预演粗剪（视频提交前必过）

起始帧全部目检通过（§4）之后、提交第一个视频任务（金丝雀镜除外）之前，用起始帧拼一条**带临时对白和节奏标记的粗剪**。外部审查指出：只按计划时长拼无声静帧，检验不了对白、反应和剪辑节奏；七个成片目录里也找不到可核实的预演产物。所以预演必须是一条能按时间看完、能听或读到每句台词、看得出动作起止和反应拍的片子，并且留档。视频的钱花出去之前就能发现"看不懂""只在说明情况""反应没位置" [社区]。

**产物**（`review_tool.py animatic` 生成；脚本没做到的项按下面手工补齐，缺一项不算预演）：

1. `审查/<EP>-预演.mp4`：按 `cut_order`（未提供时按 shots 顺序），每镜时长 = 计划取用（motion/duty/continuity 里的「取用约 Xs」，没写按 `seconds`，与 G42 同口径），不调换先后。
2. **临时对白**：每句台词在它的计划时点（`dialogue[].at`）出现，底部画说话人和台词。音轨按这个顺序取：① 已有配音 `配音/<sid>_<n>.wav`（单句镜也认 `配音/<sid>.wav`）；② 本地 TTS（macOS `say`，选与台词语言匹配的声音），文件放 `审查/<EP>-预演-temp/`、文件名带 `_temp`，只听节奏、不进成片；③ 都没有就按估算时长留静音，画面标「[台词 x.x 秒]」。`--no-tts` 或环境变量 `ANIMATIC_TTS=0` 跳过第 ② 步。字靠 Pillow 画到起始帧副本上再编码（本机 ffmpeg 常没有 drawtext/libass）；没找到中日文字体时画面上没有字，md 会提示只能对照逐镜表看。
3. **节奏标记**：画面一角标镜号和计划时长；`planned_action_window` 区间内标「动作 起–止」（进行时红色高亮）；反应镜（有 `reaction_first`、无台词的人物镜，或 duty 写反应的镜）标「反应」；承担 `must_show_ids` 的镜标事实 ID（MS1…）；`explains_ability` 镜标「解释能力」；最后一句说完加 `pace.dialogue_tail` 超过计划时长的镜标「台词装不下」。
4. `审查/<EP>-预演.jpg`：1fps 接触表。
5. `审查/<EP>-预演.md`：animatic 自动写，首行「结论：待填…」，下面是 `预演指纹：…`（预演内容）、`预演输入指纹：…`（放行时重算的输入）、预演片与临时对白来源、自动统计（总长与目标差、台词装不下的镜、没有反应拍的场、带台词人物镜比例、能力解释镜与连续解释段、必拍事实的承担镜是否在片中、缺起始帧）、逐镜表和待填的「## 必拍事实」表。预演由没写这集分镜的 reviewer 子代理看（环境不支持时首行下写「复核方式：自检」，汇报单列），把首行改成「结论：PASS」或「结论：REVISE」（「待填」不放行），逐行填「## 必拍事实」表，再把模板 `assets/templates/预演.md` 其余的逐条答案段落补在下面。PASS 不只看首行：`project_tool next` 与 `produce.py videos/all` 放行前（common.Project.animatic_problems）按输入重算「预演输入指纹」（cut_order、shots.json 相关字段、must_show、各镜选定起始帧 sha256），和文件里的不一致（改过分镜、重出过起始帧）、预演片 mp4 不存在、有灰卡占位、还留着模板【…】、某条 must_show 在表里没有「镜号 · 秒 · 看得到」的一行，都按没 PASS 处理，要重跑 animatic 重看；不要整份换成模板，两行指纹删了或改了都不放行。重跑 animatic 时：预演内容（指纹）没变就不动已填结论；变了就重出模板，旧文件挪到 `<EP>-预演.prev.md`。预演片和接触表每次重出会覆盖，要保留旧版先手动改名（例 `<EP>-预演-v1.mp4`）；交付时要能找到当前这一版和它的结论。

**逐条回答**（有一条不过就写 REVISE）：
- 按情绪集纲复述每个情节点，每条标"看得到 / 只靠台词 / 看不到"；
- **必拍事实**：每场 `must_show` 逐条写在哪一镜第几秒看得到（一条一行，缺行不放行；秒数要能在 `预演.jpg` 接触表上找到）；只有"看得到"算过，"只靠台词"和"看不到"都回 E 或 G（storyboard-keyframes §2e）；`kind: count` 的承担镜在预演帧上逐个数；
- **对白与反应节奏**：按时间听/读一遍，有没有一句台词说不完就切走、有没有重要信息后没有反应拍、有没有一段只是人物轮流开口（同场对白镜里只说不做的比例，G49）；
- **能力规则**：金手指规则和每场地点、来由能不能从画面加台词读出来（硬约束 6c）；同一条规则有没有被讲第二遍、新角色确认是不是超过一句、第二集起开头回顾是不是超过 5 秒（screenplay §5b3，G48）；
- 相邻两镜的景别、角度、主体是否至少变了一项；回溯、重复类镜头和原镜是不是同构图 [自测]；
- **一眼看懂**：每个关键物品、每个新出场的人物从哪来？每个事件（登场、摔落、冲突爆发、受伤、闯入）的起因在哪一镜？逐条写镜号；答不出的回 E 补来源镜或插入特写（storyboard-keyframes §2c）；
- **视线**：正反打的说话镜，说话人看向对手所在的一侧、没有看镜头（storyboard-keyframes §4）；
- 同一个人被拆成相邻两镜的，有没有 `split_reason`；一场里是不是切得太碎（storyboard-keyframes §7b、§7c）；
- 预演总时长与 `target_seconds` 的差。

有"看不到"、复述不出、必拍事实只靠台词：回 E 改分镜，或回 G 重出起始帧，再出一版预演。全部通过才进入 H。预演查的是信息顺序、对白与反应的时间位置和必拍事实有没有画面载体，查不了动作是否真的会生成出来；动作仍由 §5 看接触表把关。

## 4. 参考图与起始帧的目检

脚本管不了"像不像"，这一步由模型用 Read 看 PNG。逐张按四类打标签，再决定：

| 标签 | 含义 |
|---|---|
| visibly confirmed | 看得见且符合关键帧描述 |
| absent / unclear | 描述里有、画面里没有或看不清（例如手里的底牌） |
| conflicting | 画面与描述矛盾（朝向反了、服装不对） |
| contaminated | 多出来的人、水印、可读文字、参考图带进来的东西 |

**身份图**通过条件：一个人、正面、全身、素背景、中性表情、无可读文字、不带以后要消失的饰品；和视觉设定的识别锚点一致。
**底板**通过条件：无人、无字、画左画右各是什么与轴线声明一致；同场派生底板与主底板并排看是同一个地方（墙面材质颜色、地面、灯、窗门样式一致）；**空间说得通**——楼梯方向与剧本一致、门后不接门、窗外景与楼层一致、走廊通向合理、护栏/门/台阶是现实尺寸、同场几块底板拼得回视觉设定里那一行平面图（visual-assets §4b、§12）。

**起始帧场景连续**：逐张目检时把本镜和同场上一镜（按镜序，含对方人物的镜）并排看，背景必须读得出是同一个地方——墙面颜色材质、灯、窗门、地面一致；不一致就 `--retake`，两次不过查底板是否需要重出。**有底板的镜头禁止水平镜像起始帧**：镜像会把窗、门、墙面换到另一侧，地理直接错乱；朝向反了只能改提示词重出（写明 `seen in three-quarter profile, face turned toward the left/right edge of the frame, not looking at the viewer`）。只有无背景地理的插入镜（手、物件特写）可以镜像。
**起始帧**通过条件：§4b 细节与比例清单全部通过；人数等于本镜写定的 `exactly N`（插入镜除外），每人位置朝向各自对得上；说话/表情镜脸高 ≥ 画高 1/5、主角眼睛没被刘海遮住；停在动作之前（不在动作中段）；朝向 = `facing`；**视线 = `gaze`**（说话人看向对手所在的一侧，眼神略偏离镜头、不看镜头；看镜头或看错边即不过）；持物、位置、表情与 `keyframe` 一致；印章字要放的一侧留空；身份像参考图；物理可达（手够得到要拿的东西，动作能从这个姿态开始）。

**每一张都要看**：起始帧没用 Read 看过、没通过目检，就不提交视频。整集用 Pillow 按场拼 3×3 网格（每格标镜号、主体、facing、take）再 Read，同场背景并排比。网格只用来找可疑镜，不算看过：放行的每一张都要单独 Read 原图，用 `review_tool.py mark … --frame-take N --evidence "…"` 写 §4b 格式的观察；mark 绑定该起始帧的 sha256，`produce.py videos/all` 拒绝提交起始帧没 mark 或 mark 后文件变了的镜。

## 4b. 细节与比例清单（起始帧、视频都用）

每张起始帧、每条视频的接触表都逐项过这张清单，**任何一项不过即不合格**（起始帧 `--retake`，视频按 §7 处置），不因"画质不作重拍理由"放过——比例错、多一个人、物件凭空出现都是剧情问题，不是画质问题。结论写成能对着原图抽查的具体观察，例 `人数 2（夏樹画左、鬼塚画右）；视线：夏樹看画右；脚下：石板实地；比例：护栏到腰；接 S03 末帧：箱在右手`，不过的写 `细节：比例✗（人和护栏一样高）`。只写 `细节：9/9 过`、"看过无问题"按没看算（SKILL.md「防钻空子总则」）。

| # | 项 | 怎么看 | 不过的例子 |
|---|---|---|---|
| 1 | 人与环境的比例 | 护栏到腰、门比人高约 1.2 倍、桌面到大腿中部、台阶一级约到脚踝（visual-assets §12） | 高中生和楼梯护栏一样高；人坐在椅子上膝盖比桌面高 |
| 2 | 多人相对身高 | 与视觉设定的身高次序一致 | 设定里老师比学生高半个头，画面里一样高 |
| 3 | 手形 | 按实际可见与遮挡关系核对解剖、握持和穿插 | 多指、穿模、握持失真；不要求遮住的手指全部可见 |
| 4 | 持物大小与位置 | 物件尺寸现实、在 keyframe 写的那只手里 | 钱箱比上身还大；应在右手的笔跑到左手 |
| 5 | 服装锁 | 锁面（`locks[].phrase`）的颜色、款式都在 | 灰西装变成黑西装；校服领结消失 |
| 6 | 光源关系 | 同场光源在世界坐标固定，反打后屏幕方向可变；核对实际受光面 | 无原因切换光源、受光与布局矛盾 |
| 7 | 透视与空间 | 消失点一致、地面不倾斜、楼梯方向与剧本一致、门窗位置合理（visual-assets §4b） | 下楼的楼梯接着往上的台阶；门后又是门；地板像斜坡 |
| 8 | 与上一镜的连续 | 物件位置、人物站位、门开关状态和同场上一镜 `boundary.end` 一致 | 上一镜箱子在地上，这镜回到手里 |
| 9 | 没有多余的人和物、数量对 | 画面里只有 keyframe 写到的人和物；出现的人物/物件符合世界事实及本镜揭示计划（storyboard-keyframes §2b）；承担数量类必拍事实的镜放大后逐个数，结果写进 note（`计数：上 5 / 下 5 = 10 ✓`，storyboard-keyframes §6b） | 老师身后凭空多出一个空箱；背景多出一张清晰的脸 |

视频另加两项（看接触表）：

| # | 项 | 不过的例子 |
|---|---|---|
| 10 | 环境行为 | 仅在情节或自然条件要求时核验运动 | 明确要求飘落/滚动却没发生；静止本身不是缺陷 |
| 11 | 细节不随时间漂 | 手指数、服装、持物在第 1 格和最后一格一致；物件没有消失又出现（EP001 S01 钱箱消失又回到臂弯） |

整集按场拼网格时，把清单 1、6、7、8 放在同场并排里看，最容易发现比例和光向不一致。

不过：`produce.py frames <项目> EP --retake` 最多到 `max_takes`；仍不过：诊断出单一变量时只改那一项在原位的写法再拍，不在末尾追加补丁句；同一镜两次重拍仍失败，整段按封闭世界重写（E24、video-prompts-general §2b）。负面词擦不掉已经画进去的东西——起始帧里多了个人，就换构图或换参考，不是加 "no extra people"。通过：`review_tool.py mark <项目> EP <镜> --frame-take N --evidence "§4b 九项逐项的具体观察"`（不带 `--evidence` 只换选定帧、不算目检记录，`produce.py videos/all` 照样拒绝）。

## 5. 视频审片三层

| 层 | 工具 | 查什么 |
|---|---|---|
| 脚本 + ASR | `review_tool.py asr` | 标注删除、替换、新增及否定/数量等关键差异，供定位听审；不自动证明对白正确 |
| 脚本 + 抽帧 | `review_tool.py sheets` | 2 帧/秒接触表；开头静止、结尾回弹、闪白、画面出字、多出的人、身份漂移 |
| 脚本 + 运动能量 | `review_tool.py motion` | 每 0.25 秒的运动能量曲线，写 `video_takes[n].motion / action_peak / action_start / action_end / cuts`；`cuts` 是镜内跳切候选 |
| 模型看图 | Read 接触表 | **职责动作是否出现、在原片第几秒**（见下）；§4b 细节与比例清单 11 项（含必要环境事件、细节不漂）；唯一动作是否发生、看不看得懂；终点姿态与持物；反应是否可读；口型落在谁脸上；相邻镜轴线、视线、服装连续；表演强度是否相称 |

画质不作重拍理由，这里的"画质"只指清晰度、噪点、质感；多人/少人、多手少手、手形错误、出字、认错人、镜像、镜内硬切、比例错、凭空物件都是内容缺陷，按 §4b、§7 判。审的是剧情、动作可读、台词完整、有无出字、有没有认错人。静音看一遍接触表，冲突还能不能读——这是口型或配音失败时的兜底。

**必须看画面并听审，不只看 ASR**：识别文本既不能证明真实发音正确，也不能证明动作存在；短暂接触需加密抽帧或看原片。逐镜记录：
1. 本镜 `duty` / `motion` 里的职责动作（撞、让开、按下、箱子滑出、扑、开箱递出……）**有没有出现**；
2. 出现在原片**第几秒到第几秒**。

写法：通过 mark 将实测动作/对白区间写到当前 take 的 assessment，保留画面、声音、连续性三项证据；详见 [审片与剪辑准入](quality-contract.md)。证据写具体观察（第几秒看到什么、在场几人、和哪一镜并排比过），"看过无问题"按没审算；每次 mark 的 evidence 追加不覆盖，结论绑定当前 take 的 sha256，换 take 或重拍后旧结论作废。计划与运动曲线仅作候选，不回写镜头计划，不跨 take 继承。

**关键情节点缺失必须处理**：先核实区间，再在授权内修提示词或分镜；must_show 承担镜和关键情节镜任何时候都不能记 weak，take 用尽仍缺也一样，只能重拍、改分镜或回剧本（§5c）。记录失败与后续修复，最多输出明确标注的草剪。

**逐镜核对必拍事实**：本镜 `must_show_ids` 里的每条事实，在当前 take 的接触表上看到了没有，用 `review_tool.py mark <项目> <EP> <SID> … --must-show MS1=pass --must-show MS2=fail` 写进当前 take 的 `video_takes[n].must_show_check`（同时镜像到镜级 `must_show_check`）：`{"MS1": "pass|fail|unverified"}`，pass 的证据（在哪一秒看到；数量类写逐个数的结果）写进 evidence。mark 批 `ok` / `weak` 要求本镜 `must_show_ids` 全部是 pass；有一条 `fail`、`unverified` 或缺项：mark 拒绝批 `ok` / `weak`，`auto` 给 retake，`choose_best` 不选这个 take，正式剪辑按 fail 拒绝；只能重拍，或回剧本/分镜改（§5c）。`unverified`（加密抽帧也看不清）先加密抽帧或看原片核成 pass 或 fail，核不出来按 fail。

**声音结论拆三项**，不合并成一个"audio pass"：
- `asr_ok`（true/false/null）：ASR 与剧本逐字比对的结果，只说明"识别出来的字对"；没跑 ASR 就是 null；mark 写 true 要求当前素材（sha 一致）的 ASR 结果存在且没有语种不符；
- `listen_ok`（true/false/null）：真人（用户或用户指定的母语者）听过，情绪、口音、句尾语调、说话人对（§10 听感五问）；非 null 时 mark 必须带 `--listener <谁听的>`，拒绝 model/claude/agent/ai/self 这类值。执行代理和子代理一律写 null，汇报写"未听审"；
- `sync_ok`（true/false/null）：口型与声音逐字对齐；没核就是 null。
- `speaker_face_ok`（true/false，有台词的镜必填）：`speech_window` 内按 4 fps 抽帧，只有台词归属的那张脸嘴在动，画内其他看得见的脸（含侧脸）嘴闭着。这是纯视觉判断，代理可以签；evidence 写具体观察（第几秒谁的嘴在动、其他几张脸各在哪、嘴闭着）。

用 `mark … --asr-ok true|false|null --listen-ok … --sync-ok … --speaker-face-ok true|false` 写进 take 的 `assessment`。入剪要求 `asr_ok` 为 true，有台词的镜还要 `speaker_face_ok` 为 true（null 或缺项脚本拒收）；`review_tool.py asr` 标了 `voice_mismatch`（台词段中位基频和角色身份图 `voice` 写的性别明显不符：男 >200Hz、女 <150Hz；年龄段脚本不判）的镜交真人听或重拍；`extra_vocal_segments`（speech_window 外 ASR 识别到的人声）逐段看口型或听来源。`listen_ok` 或 `sync_ok` 为 false 时拦下；为 null 时放行，但审片报告的"声音"列、剪辑单、终验都显示"未验证"。null 如实显示为"未验证"，任何汇总（审片表、剪辑单、交付说明）都不能把它写成"通过"。审片报告另有"必须拍清楚"一列；关键词识别分歧标"需母语者确认"。关键能力词、专名（例「素手で」）ASR 有分歧时 `asr_ok` 记 false 并写分歧原文，交母语听审确认，不因为"大意对"记 true。旧记录只有 `checks.audio: pass` 时，脚本一律按 `asr_ok: true`、`listen_ok` / `sync_ok` 为 null 读（旧"audio pass"实际只是 ASR 通过）；旧的 `--audio pass` 参数也只等于 `--asr-ok true`。

`review_tool.py auto` 为未审或失效 take 写 pending_review，仅保留当前有效的已有审批。正式成片要求明确 mark 的三项通过与证据；详见 [审片与剪辑准入](quality-contract.md)。

### 5b. 增量审片（提速，必须遵守）

- 返工或重拍后要审的范围按依赖算，不由代理缩（SKILL.md「防钻空子总则」）：①新拍、重拍的镜头；②链式出帧的所有下游镜（起始帧取自本镜末帧的，E33），起始帧作废、重出后再审；③同场前后相邻镜的连续性结论重核（E21）；④该集预演重跑、成片终验重做。其余已 ok 且媒体哈希没变的镜头沿用原结论。全集重审只在剧本或剪辑顺序大改时做。
- 只有一两镜要审时，主会话自己看接触表（`ffmpeg -vf "fps=1,scale=480:-1,tile=5x1"`）并跑 `review_tool.py asr`，直接 mark，不派剪辑子代理（派一次全集审片约几十万 token、十几分钟）。
- 三镜以上才派剪辑子代理，只把待审镜头 ID 发给它；由它自己执行 mark，`--evidence` 开头写 `审片人：<子代理名>`，`listen_ok` 写 null。主会话不改写它的结论和证据，不同意就另写一条带自己署名的 mark。
- 定版前的整片每秒抽帧与整片 ASR 仍要做，这一步不省。

## 5c. 剧情事实不可妥协：不许的放行理由

外部审查实例：审查记录已经数出箱里是十一件（台词说十件，"九假一真"的排除法因此失效），却以"观众三秒数不出来、剧情靠台词立住"放行；设计要"笑僵住、慢慢合箱、认输"，成片里箱子一开始就关着，人物只在微笑动嘴，也过了。

**下面这些理由不能用来放行剧情事实缺陷**（数量、谁做了什么、状态结果、反派损失、身份，即 `must_show` 五类，以及 duty 里的关键动作）：
- "台词能解释""字幕交代了"；
- "观众几秒内数不出来/注意不到"；
- "画面很好看，表演有情绪"；
- "take 用完了""预算紧"（预算到头就暂停正式成片、记未决，不是放行）；
- "用户说了继续/全自动"、weak、waive、未决：剧情事实缺陷都不能靠这些放行（SKILL.md「防钻空子总则」）。

**缺失的关键动作不能靠这些替代**：延长镜头（把没发生动作的素材拉长）、补一句旁白或 `[OS]`、加字幕或面板说明、换一个只有结果没有经过的镜头。只有三条路：①重拍（授权内，按 §7 诊断后改提示词或起始帧）；②改分镜（换承担镜、拆出插入镜、改成双人同框）；③回剧本改这条事实（例如把十件改成画面上真实的件数，并同步改台词和下游全部引用），改动写进决策记录。

背景里多出一个普通摆件、衣服褶皱不同这类不承担剧情的差异，不属于这一节，按 §4b 判。

## 6. finding 与处置

每条问题写：位置（镜、take、秒）、证据（ASR 文本 / 接触表第几格）、影响、处置、最小修复。四级规则：脚本能证明的阻断；语义问题带证据判断；手感只警告；口味不阻断。

**先定处置再修订**（五选一）：
- 保留；
- 后期处理（入出点、去原声、换底噪、叠字）；
- 局部编辑（只一层错，改那一层）；
- 重新提交（文字无缺陷、像随机；同一输入原样重投 ≤2 次）；
- 改写（同一缺陷已复现，回提示词改结构：一次只改诊断变量，写 change_set + preserve_set）。

失败三路：技术失败（超时、限流、5xx）有上限原样重试；点名被拒的输入只改那一项；重复出现的内容缺陷回提示词 owner。改写后回归六行义务：原文覆盖｜镜头目的｜起止与时长｜资产与连续性｜对白文字声音｜项目配置，逐行记保留/丢失/改变——自动改写最常见的副作用是"变短了但丢了台词或反应"。

缺陷三分法（谁负责）：故事坏了重写剧本；身份坏了重做资产；执行坏了重新生成。不靠堆负面提示词修补。

供应商点名拒绝某项输入（内容审核）时，只改被拒的那一项：提示词被拒改写那一句（"一拳砸在对方脸上，血顺着下巴滴"改成"一拳挥空，对方侧身避开，桌上的杯子被带倒"），参考图被拒换一张构图与角色一致、画面本身合规的图，音频被拒重做那一句；改了什么写进决策记录（providers.md §7）。

## 8. 取用区间的自动规则

- 有台词镜：入点 = max(0, 首词开口 − 0.15)；开口晚于 1 秒直接剪前段；出点 = 末词结束 + 0.5（印章字镜 + hold + 0.1），不超过素材 − 0.1；留白结尾（`to_end`）= 末词结束 + 0.02。
- **动作与对白保护**：剪辑仅使用当前 take 有效 assessment 中的实测区间；各模式都保护两端。计划和自动运动曲线不能作为正式依据。详见 quality-contract.md。
- 无台词镜：整条去尾 0.2 秒（`full`），模型看图后按接触表用 `mark --in --out --mode fixed` 收紧。**fixed 的入出点必须来自接触表上看到的动作时间**，不许照搬 shots.json 的计划秒数（EP001 S14、S16 照搬 1.5/2.0 秒，让步和空箱弹开全在剪点之后）。
- 动作偏慢可 `--speed 1.3`（≤1.5），配拉扯声。
- 字幕文字取剧本，识别时间经听审核对；ASR 缓存绑定素材内容哈希、模型和语言，替换文件后重新审。

## 9. 预算与停止

- 每镜最多 `max_takes`（默认 3）个视频 take；起始帧同样。
- 每集提交上限 = 镜数 × 1.5 的视频任务；到上限时，缺陷不承担剧情的镜可按 weak 进剪辑；承担剧情的镜（must_show 承担镜、关键情节镜）暂停正式成片，只出标明的草剪，记未决（§5c）。
- 同一镜连续两轮"改写 → 重投"仍不过：不承担剧情的标 weak 并写决策记录；承担剧情的回 E 改分镜或回剧本改事实，不无限循环，也不 weak 放行。
- 提交前按账本数同一 `fingerprint`（同一请求内容）已经提交过几次：原样重投以 2 次为限，再多就是在为同一个随机结果反复付费，先回 §6 诊断。
- API 连不上：写作阶段照做，生产阶段停下并写明原因。这和"模型/档位/分辨率用户没指定"（SKILL.md 硬约束 1b）是流水线里仅有的两种需要人的情况。

## 10. 配音：按情绪生成，按听感验收

EP001 的配音"平"：所有台词一个腔调读完，被撞时的惊叫和平时说话一样。台词有情绪是硬约束（SKILL.md 硬约束 6e），配音环节的做法：

**生成**
- 每句台词在 shots.json 写 `dialogue[].emotion`：`情绪·强度·语速·音量`，例 `惊慌·强·快·大`、`冷笑·中·慢·小`、`强装镇定·弱·中·中`（写法见 [screenplay.md](screenplay.md) §4b；G31 查有没有写）。只写了一个情绪词时，强度、语速、音量三项按"中"补齐，不在配音环节替剧本编情绪；情绪词本身缺失回剧本阶段补。
- **每句带上下文四项**：配音通常按人物集中生成或录制，不按剧情顺序，配音者（或 TTS 的 instruct）丢掉的正是上下文。所以送 TTS 或交外部配音之前，配音表（放 `配音/` 下，一句一行；验收五问也写在这张表里）每句除了台词原文、说话人、`emotion`，还要写四项：
  - **对谁说**：不写的话，配音者不知道是对上司说还是对下属说、对一个人还是对一屋子人，语气只能靠猜。
  - **上一句是谁说的、说了什么**：接谁的话决定这一句是抢话、回嘴还是自言自语；按镜序（`cut_order` 或 shots 顺序）找上一句，写说话人和那句原文。
  - **说话人此刻知道什么、还不知道什么**：同一句话在"已经知道真相"和"还不知道"时是两种读法，这是最常见的重录原因；按剧本和 story-engine §8 的信息权限表写。
  - **这句的策略**：质问、试探、收回、交换、拖延、示弱、挑衅……写这一句要对对方达成什么。"愤怒"这类情绪词没法直接演，策略可以；策略决定重音落在哪个词、句尾上扬还是下沉。
  这四项是剧本的投影，不是第二份台词权威：台词文字、说话人以剧本为准，表里和剧本对不上时改表、不改剧本（剧本需要改就回剧本阶段）。需要随镜头保存时，可以写进 shots.json 的 `dialogue[]` 可选字段 `to` / `knows` / `tactic`（pipeline-contract §4 示例注释；上一句从镜序推出，不另存）。用 instruct / 自由文本标签的引擎（Qwen3-TTS、CosyVoice、Fish Audio、ElevenLabs v3）把对谁说和策略写进 instruct 或标签；只收情绪枚举的引擎（MiniMax）只能落到 `emotion` 的选择和语气词上，四项仍写在表里给听审对照。
- **TTS 用哪个引擎由用户指定**（SKILL.md 硬约束 1b）：下面的做法和表只是用户定了引擎之后怎么写参数，以及交用户挑选时列候选的参考，不据此自选或换引擎。
- **按情绪选参考音频**：每个说话角色准备同一音色的 5–10 秒情绪参考——至少"平静 / 愤怒 / 惊慌 / 冷笑或轻蔑 / 哭腔或委屈"五段，放 `配音/参考/<角色>/<情绪>.wav`；每句按 `emotion` 的情绪词挑最近的一段克隆。GPT-SoVITS 这类没有情绪标签的模型，情绪完全来自参考音频。
- **或用支持 instruct / 情绪参数的 TTS**：`emotion` 四项在各引擎里落到哪个参数，按下表填，不临场发挥 [官方]：

  | 引擎 | 情绪 | 强度 | 语速 | 音量 | 气声、喘息等非语言声 |
  |---|---|---|---|---|---|
  | MiniMax speech-2.8 | `emotion` 取 happy / sad / angry / fearful / disgusted / surprised 里最近的一个（`providers.py` 只收这六个；calm、whisper、fluent 未经本项目实测、neutral 官方已不再列出，都不送；平读就不传 emotion） | 弱：不传 emotion，只调 speed / vol；强：emotion 再加语气词 | `speed` 慢 0.85 / 中 1.0 / 快 1.15 [推断] | `vol` 小 0.8 / 中 1.0 / 大 1.5 [推断] | 台词里插 `(gasps)` `(pant)` `(sighs)` `(sniffs)` `(breath)` 等，只有 2.8 支持；停顿 `<#0.3#>` |
  | MiniMax speech-2.6 | 同上（官方另有 `whisper`、`fluent`，`providers.py` 不收；压低声音靠 `vol` 调小） | 同上 | 同上 | 同上 | 不支持语气词，只用 `<#x#>` 停顿 |
  | Qwen3-TTS 1.7B（VoiceDesign / CustomVoice） | instruct 用一句中文把四项都写进去 | "非常 / 有点" | "语速很快 / 放慢" | "大声喊出来、声音发紧 / 压低声音" | "带着喘息""说完倒吸一口气" |
  | CosyVoice 3 | instruct 同上 | 同上 | 同上 | 同上 | 文本里插 `[breath]`、`[laughter]` |
  | IndexTTS2 | `emo_vector` 8 维里对应的一维，或给一段情绪参考音频 | 那一维的数值 | 用时长控制功能按镜头剩余可说时长生成 | 生成后做 ±3 dB 增益 [推断] | 情绪参考音频本身带喘息或哭腔 |
  | ElevenLabs v3（付费） | 句首方括号标签，如 `[panicked]` | 标签可以叠加，如 `[furious][shouts]` | 省略号制造停顿 | `[shouts]` / `[whispers]` | `[gasps]` `[sighs]` |
  | Fish Audio S2（付费） | 句首方括号写自由文本，如 `[压着怒气，一字一顿]` | 写进同一个括号 | 同左 | 同左 | 同左 |

  使用规则：
  - 标签、语气词和停顿是表演标注，不是改台词：剧本原句一个字不改，标注按 `emotion` 插进送给 TTS 的文本；做字幕和 ASR 比对前先剥掉 `(…)`、`[…]`、`<#…#>` [官方 + 推断]。
  - 一句只放一个情绪；中途变情绪的句子（例如心虚转愤怒）拆成两段分别生成再拼接 [推断]。
  - **Qwen3-TTS**：instruct 只支持中文和英文，台词是日语时 instruct 也用中文写；要情绪控制用 1.7B，0.6B 明显弱；Base 模型不支持 instruct，可先用 VoiceDesign 生成各情绪样本，再用 Base 的 voice clone 复用 [官方]。
  - **IndexTTS2**（本地、音色与情绪分开给）：音色参考只要一段平静干声，情绪另用 `emo_audio_prompt`（可以是别人的声音）或 `emo_vector` 给，同一角色不必录五段情绪参考；`emo_vector` 顺序是 happy, angry, sad, afraid, disgusted, melancholic, surprised, calm；用文本情绪模式时 `emo_alpha` 从 0.6 起调。它能按指定时长生成，镜头只剩 2 秒可说时用这个功能，不靠后期变速 [官方]。社区实测单句可能要 2 分钟以上，本机速度未测，先测一句再批量 [社区]；权重是 bilibili 自定许可，商用前要核对 [官方]。
  - **ElevenLabs v3**：Stability 设 Creative 或 Natural，Robust 会削弱标签；音色用 IVC 或设计音色，PVC 在 v3 上效果差；多人对话可用 Text to Dialogue，标签写在各自那一轮里 [官方]。
  - **Fish Audio**：S2 用方括号自由文本，S1 用圆括号，两代写法不要混用；短句里不堆多个标签，也不写互相冲突的情绪 [官方]。
- 喊叫句（强度"强"、音量"大"）不能只调高音量：参考音频本身就要是喊出来的，或 instruct 里写"喊出来、声音撕裂、带气声"；用上表的引擎时，情绪（或说话方式）和一个非语言声标注都要有，只加 vol 只是更大声的平读 [推断]。
- **语言参数必须显式等于台词语言**：用户看完 EP001 的原话是"说话语调，口音很奇怪"。TTS 请求里的语言参数（MiniMax `language_boost`、Qwen3-TTS / CosyVoice 的 `language`、ElevenLabs 的 `language_code`、IndexTTS 按文本自动判的也要确认）一律显式设成 `dialogue[].lang`（= `drama.json` 的 `dialogue_lang`），不交给引擎"自动检测"——日语汉字多的句子会被当成中文念。H3 原生对白的语言参数就是 `<d>[Japanese]` 标签（G44 查）[官方 + 推断]。
- **克隆参考音频必须是同语言母语者**：参考音频的语言 = 台词语言，说话人是该语言母语者；用中文母语者的声音克隆去念日语，会带中文口音和中文声调。参考音频要是**对话口吻**，不是朗读文本（EP001 `natsuki_ref.txt` 是一段新闻朗读式的日语例句，克隆出来就是念稿腔）；最好是同一情绪、同一身份口吻的一两句真实对白 [自测]。参考音频来源、语言、是否母语者写进 `配音/参考/<角色>/README.md`。
- **读音**：易读错的词（EP001「売上」读成「冬揚げ」、「じいちゃん」读成「ちーちゃん」）写进 `drama.json` 的 `readings`，单句专名写进 `dialogue[].reading`（`{"夏樹": "なつき"}`，G44 查日语专名有没有写）[自测]。**配音前按 reading 校对**：送 TTS 之前逐句核对 reading 里的每个词在送出文本里读法对（支持读音字典的引擎把 reading 填进去；不支持的，把该词在送出文本里改写成假名/拼音，字幕仍用剧本原文）；配音后 ASR 比对时，reading 里的词自动算关键词（`speech_diff` 的 critical_changes），读错就不合格。MiniMax 的 `pronunciation_dict.tone` 用 `原文/读法` 斜杠对，读法可以是假名、带声调数字的拼音或 IPA（例 `売上/うりあげ`、`重/(chong2)`）；`providers.py` 的 MiniMax 语音通道用 job 参数 `pronunciation`（`{"売上": "うりあげ"}`）传这个字段、原词不在这句里就拒绝，用必填的 `language_boost` 传台词语言（拒收 auto），见 [providers.md](providers.md) §4 [官方]。
- H3 原生口型镜：情绪写进 `<d>` 前的说话方式（`shouts in panic`、`says coldly under her breath`），video-prompts-h3 §5。

**验收（ASR 之外必须加真人听审）**：文本一致不等于发音、音色、情绪或口型正确。听审人逐句听后回答五问，写进配音表并署名：

| 问 | 通过 | 不过 |
|---|---|---|
| 情绪与剧本 `emotion` 一致吗 | 惊慌听得出慌、冷笑听得出冷 | 所有句子一个腔调 |
| 喊叫句有力度吗 | 音量明显高于同角色平时说话（峰值高 6 dB 以上），有气声、音色变紧 | 只是音调高了、声音还是平的 |
| 语速与 `emotion` 一致吗 | 急的快、压着的慢 | 全部同一语速 |
| 像真人说话吗 | 有呼吸、停顿、句尾自然落下 | 播音腔、每个字等长、句尾上扬像念稿 |
| 口音和语调像母语者吗 | 目标语言母语者听不出外国口音；日语的高低音调（アクセント）对、中文声调对；句尾语调符合情绪（质问上扬、断言下沉、威胁压低） | 带另一种语言的口音或声调；日语每个音节等高像中文念法；该下沉的句尾上扬 |

**直接判不合格的两种 ASR 结果**：①专名（reading 里的词、人名地名）被识别成别的词（「夏樹」→「夏木」「なつみ」），说明读错了；②整句被识别成别的语言（日语台词 ASR 出来一个假名都没有，`speech_diff` 标"语种疑似不符"），说明口音严重不像母语者。两种都按 `emotion` 和 reading 重生成该句，不靠听感放行。

没有听音能力时，RMS 和语速只能提供排查线索，不能推断情绪通过或直接触发重生成；音频审查保留 pending，交有听音能力的环节继续。五问由真正听过的人（用户或用户指定的母语者）填，结论记成 `listen_ok` 并用 `--listener` 写明是谁听的；模型和子代理不写 listen_ok 的 true 或 false，也不凭 ASR 文本推断听感。ASR 比对记 `asr_ok`，口型对齐记 `sync_ok`，三项分开写（§5）；没听就是 `listen_ok: null`，显示为"未验证"。

## 11. 外部配音与对口型（模型无关）

适用于视频模型同轨台词不能用（音色漂移、语言不对、情绪平）、改用 §10 的 TTS 配音再对口型的镜头。EP001 的对口型链路出过三类问题：24→30→24fps 的重复帧跳动、两次非等比缩放、远景对口型失败，清晰度又掉了 5–7 个百分点 [自测]。

1. **配音先行**：每句先按 §10 生成单人干声（无底噪、无音乐、无电话滤波或混响），ASR 和听感五问都过了才送对口型；电话、大厅这类效果在混音时再加 [官方]。
2. **能不能做对口型**：脸高 ≥ 画高 1/5，正脸或偏转不超过约 30°，嘴部没有手、头发、道具遮挡。不满足就改成背对、侧后方或画外音（与起始帧通过条件、video-prompts-general §9 一致）[自测 + 社区]。
3. **帧率与尺寸**：先查对口型模型的内部帧率。LatentSync 1.6 内部按 25 fps、16 kHz 处理，素材是 24 fps 时自己先转成 25 fps 再送，拿回来按时间戳映射回原帧率，不让工具偷偷复制帧再抽帧 [官方]；尺寸用 pad / crop 调整，不做两次非等比缩放 [自测]。
4. **时长对齐**：音频比画面长时先剪短停顿或换镜，不用 loop / bounce 让画面来回播；音频比画面短时保留画面，多出来的部分闭嘴 [官方 + 推断]。台词原文不改。
5. **先对口型，再放大或补细节** [社区]。
6. **候选与参数起点**（用哪个由用户指定，SKILL.md 硬约束 1b；下表只用于列候选交用户定和定了之后的起点参数，不自选、不擅自换）：

   | 模型 | 用途 | 起点参数 | 注意 |
   |---|---|---|---|
   | LatentSync 1.6（本地，Apache-2.0） | 候选（本地） | `inference_steps` 20–50 取 25，`guidance_scale` 1.5，口型不跟时升到 2.0 | 官方写约 18 GB 显存、只写了 CUDA；Mac 上能不能跑、多慢，先测一镜 [官方] |
   | sync lipsync-2-pro（付费） | 候选（付费） | `temperature` 0.5，情绪强的句子 0.6–0.7；多人画面开遮挡检测并指定说话人 | 极端侧脸官方建议用 sync-3，换不换由用户定 [官方] |
   | MuseTalk 1.5 | 只做快速预览 | — | 社区报告口型不同步、发糊，不进成片 [社区] |

7. **对口型验收**（三项有一项不过就退回原片，改画外音或背对）[社区]：
   - 嘴部放大看 3 帧：牙齿和口腔内部有没有发糊、变成假牙；
   - 嘴部以外的整帧清晰度和原片同一帧比有没有明显下降；
   - 和身份图比有没有变脸；另外看 b / p / m 这类闭唇音的那一帧，嘴是不是真的闭上了。
