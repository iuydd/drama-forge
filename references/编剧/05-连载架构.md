# 05｜连载架构：持续满足，不靠无限拖欠

## 1. 三种长度，三种设计
**独立短片**：一个核心目标、一次主要转变、一个完整回报；结尾可留余味，不必设计追更钩子。

**短季**：几个阶段目标围绕一个终局问题。先确保本季闭合，再考虑续季。

**长连载**：需要不断产生不同问题的机制，同时保留成长与后果。不是把同一冲突切成更多集。

用户只要 3 集，不输出 60 集宇宙史；用户要 100 集，不能只列 100 个空标题。先写阶段功能和差异，再展开分集。

## 2. 四条可开关的长期线
- 目标线：当前想完成什么，为什么下一阶段值得投入。
- 成长/资源线：得到什么新方法、物品、权限或合作。
- 关系/声望线：谁理解主角、谁改变立场、谁能共同承担。
- 真相线：哪些问题被回答，新的答案改变什么。

不是每部都必须有神秘幕后组织。无谜团题材可把真相线改为探索线或关闭。关系不是附赠恋爱，群像和事业伙伴同样适用。

## 3. 五种长期引擎
| 引擎 | 每轮变化 | 保留的累积 | 易坏之处 |
|---|---|---|---|
| 阶段成长 | 新目标与能力应用 | 技能、资产、名望 | 换地图归零 |
| 案件/委托 | 不同难题、不同当事人 | 世界真相、关系、声誉 | 每案同一种误会 |
| 经营建设 | 新供给瓶颈与利益关系 | 设施、团队、信用 | 营收播报替代故事 |
| 关系演进 | 信任、边界、共同选择 | 已确认的感情与承诺 | 一句解释能解决的误会拖十集 |
| 任务与探索 | 新环境迫使旧能力新用 | 地图、知识、同伴 | 每扇门后又一扇门 |

可交织两种，但应有一个主轴。支线最好能反过来影响主线选择，不是填充时长。

## 4. 从结局往前设计
先写终局兑现：主角终于能够/选择/拒绝什么？观众从第一集期待的核心回报是否得到？

然后确定 3–6 个阶段的功能，而不是机械等分集数：
`证明承诺 → 扩大应用 → 遭遇不同性质的问题 → 重新组合已得成果 → 改变更大范围 → 兑现并留下可生活的世界`。

纯无敌可改为：`证明压倒实力 → 展示反差用法 → 世界适应 → 大规模影响 → 主角私人愿望实现`，无需安排“被打败后重新练级”。

每个阶段必须有局部完整感：一个问题真正结束，一项成果留下，一个新目标从结果中生出。

## 5. 分集卡不是剧情流水账
每集记录：
`集号 / 本集目标 / 观众核心期待 / 入口状态 / 阻力 / 主角决策 / 独特行动 / 关键回报 / 状态差量 / 结尾问题 / 接续集 / 伏笔种下或回收 / 制作风险`。

坏卡：“主角到了宗门，被长老看不起，然后准备测试。”
好卡：“主角决定以能保护矿工的低阶术法参加测试；证明同一术法可使坍塌静止，取得进入禁井的资格；回报已到手，但静止的石层里出现了昨天失踪者的灯。”

以上为结构演示，不要求复制设定。

## 6. 承诺账本
每个重要钩子、秘密、奖励或情绪承诺记录：
`promise_id / 提出集 / 观众在等什么 / 最早可兑现集 / 计划最迟兑现集 / 具体兑现方式 / 当前状态 / 已兑现比例 / 关联场景`。

承诺类型与默认检查：
- 现场动作：上一集已经开始的揭示、出手、开箱，下一集应尽早接上。
- 短期目标：几集内兑现，延期必须让观众得到实质新信息或部分成果。
- 阶段承诺：阶段结束前回收主体部分。
- 核心谜团：可以跨季，但每阶段应有真正改变理解的答案。

具体集数由项目设定，不声称“拖到第几集一定流失”。一个钩子不能在未取得任何进展时被相同姿势连续延期。

## 7. 观众期待矩阵
对每个阶段写三句话：
- 观众已经知道什么，所以会期待哪种兑现？
- 观众还不知道什么，但已有足够线索想知道？
- 即便观众猜到结果，过程里还有什么值得看？

只依赖“猜不到”的故事容易需要作弊。结果可预期，方法、表达、关系选择和世界后果仍可以精彩。

## 8. 中段不疲劳
连续性保留，兑现形式变化。可按需要轮换：实战、试验、交易、救援、公开验证、创造、关系决定、世界回响、休整成果。

休整不是灌水。用生活变化展示胜利有意义：以前要争抢的东西现在可以分给别人；原本必须低头的请求现在可以拒绝；曾经孤立的空间成为共同体。

审查最近 3–5 集，若主角目标、冲突方式、制胜方法、见证者与结尾结构大多相同，就在下一阶段更换至少两个因果维度。

## 9. 续写的固定顺序
1. 读 brief、锁定 bible、series-plan、project-state 和最近 3 集正文；必要时读关联旧集。
2. 提取上一集尚未完成的现场动作、到期承诺、人物知情变化。
3. 检查用户新增要求是否与 canon 冲突，记录改动影响。
4. 先写这批分集卡，再写正文；主角已有能力不需重新发现。
5. 对每集保存状态差量；完成修订和检查后登记 accepted。
6. 保存下一批入口，不写“后面自行继续”作为已完成。

无文件工具时输出可复制的交接块，含版本、完成范围、稳定事实、未结承诺、当前状态与下一步。不能假装有跨会话永久记忆。

## 10. 完结必须结算
核心目标、重要关系、主要奖励、规则主题和核心谜团应明确结算，允许有意留白但要区分“开放结局”与“没写完”。

好的续季入口可以来自赢后的新责任、新探索、另一人的选择，而不是宣布此前所有胜利都不算。主角的强大和成长值得在结局里被享受。

## 追加｜揭晓弧与连载主线

启用 15 时，单独记录一轮“误判—风向—证据—结算”的开始集、到期集与已保留收益。身份秘密可跨季，但局部任务必须有进展；已许诺即将核验的证据不得持续空转。上一轮确认能力，下一轮可以争归属、执行或社会影响，不要退回相同能力是否存在。必要时在 `reveal-arcs/` 保存结构化规划。
