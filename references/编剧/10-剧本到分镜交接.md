# 10｜剧本到分镜/AI 影像的交接

## 1. 分工
本 Skill 决定“发生什么、谁做什么、观众必须知道什么”。分镜/导演 Skill 决定具体机位、景别、镜头运动和镜头拆分。后续起始帧、视频与声音工具执行已锁定的计划。

不存在已经生成的图片或视频时，不给它们虚构路径和完成状态。上游剧本资产 ID 与下游实际生成资产文件应分开记录。

## 2. 必须移交
- 项目 brief、canon 版本、目标受众体验与篇幅。
- 角色/地点/道具稳定 ID 及可识别特征。
- 场景级时间轴、人物在场情况、动作先后、对白和声源。
- 每个爽点必须被看清的证据：例如刻度真的改变、权限真的开放、物品真的归主角。
- 前后连续性：物件状态、位置关系、谁知道什么、能力使用结果。
- 结尾必须停留的故事状态，与下一集入口。
- 难以制作的内容及不损失回报的替代方案。

不需要在剧本阶段列出大量无依据的摄影参数。

## 3. 连续性锁定表
`lock_id / 关联场景 / 不可改变项 / 原因 / 可变化范围`。

例如：维修之前道具的左角缺损，维修之后同一缺损消失；主角始终从同一侧接触；提示音发生在效果之后而非之前。观众看懂因果所依赖的点必须锁定。

已有导演机位锁定时，改剧本须指出哪个锁受影响，请求项目主编/用户确认或使用不破坏锁定的替代。下游执行不得临时改人物身份、道具归属或动作结果。

## 4. 制作复杂度是参数，不是扼杀脑洞
默认低至中等复杂度可优先：少量主要人物、可复用地点、稳定服装、明确道具、顺序动作、有限同时交互。用户要求史诗场面则保留规模，并标注风险。

常见风险及替代：
| 风险 | 保留叙事效果的替代 |
|---|---|
| 千人同步复杂动作 | 大空间声场、少量代表人物、广场前后状态变化 |
| 超长精确 UI 文字 | 后期图文叠加，剧本提供准确文本与时点 |
| 同帧多人抢夺小物件 | 用明确的交接顺序、接触前后状态表现 |
| 难以稳定的高速变形 | 建立前态、可辨识过渡、后态与验证，不删掉验证 |
| 大规模城市升级 | 同一空间可比的前后变化，加一处近距离生活收益 |

这些是制作规划选项，并非对所有当前模型能力的判断。实际能力、成本和镜头策略由下游工具测试。

## 5. 质量关卡
剧本审查通过不等于影像通过。下一阶段仍需检查分镜与时长、起始帧、单镜头视频、最终剪辑。失败尽量局部返工；若需改变叙事，回到有版本的剧本层修改，不让执行 Agent 擅自重写。

导出字段 `camera_status` 默认 `not_planned`。不可把“建议固定机位”写成“机位已锁定”。正式锁定需要真实的导演/分镜产物。
