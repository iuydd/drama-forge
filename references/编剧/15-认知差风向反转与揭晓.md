# 15｜认知差、风向反转与揭晓兑现

本模块把用户提出的“观众知道主角是对的或有身份，少数人不断找麻烦，墙头草让人以为马上就要翻盘，又出现新的反向变化”整理为可执行方法。**“认知差—风向反转—兑现”是本包的工作名称，不是经验证的心理学定律。**依据见 11 的 R11–R13；以下分类、参数和案例为本包创作设计。

## 1. 最重要的区分：反转的到底是什么

至少区分四层：

| 层次 | 例子 | 写作处理 |
|---|---|---|
| 事实 | 主角确实完成任务；身份真实；判断正确 | 一旦作为观众可信支点展示，就不能为了延长误会随意否定 |
| 人物认知 | 反派不信；专家部分相信；群众以为证据无效 | 可以反复变化，但要说明各自看到了什么 |
| 公开立场 | 某人已经相信，却因利益继续嘴硬；群众怕失去订单而退缩 | 不要把嘴硬写成真的忘记事实 |
| 权力与结果 | 主角有资格却尚未获准入场；已获认可但奖励待交付 | 是新的冲突维度，不能伪装成旧事实再次未证明 |

**观众知道主角会证明自己，仍然可以想看：怎么证明、何时证明、谁先意识到、谁会付出什么代价、这次胜利究竟比想象中大多少。**不必靠让主角随时可能输掉一切维持吸引力。

“主角有身份”和“主角有道理”是两条不同证据线：身份可以确认资格或背景，主角判断正确仍应有行动或事实支持。不是领导一到场就能把错误技术方案变正确。

## 2. 先选择观众的信息位置

- **观众领先**：观众知道真相，反派/群众不知道。主要卖兑现和反应，适合本模块。
- **观众部分领先**：观众确定主角有本事，但不知道实力上限或完整计划。既能等待证明，也能获得更大的发现。
- **观众与主角同步**：一起求证，适合悬疑。不能照搬全知型打脸节奏。
- **观众落后**：主角藏着关键计划。必须有公平伏笔，揭晓后能回看理解，不能临时补造经历。

默认本模块采用前两种。想做观众真正猜错的惊天反转，另外设计证据，不要误以为“群众被打脸”就等于“观众被惊到”。

## 3. 先立观众可信的支点

在早段让观众**亲眼看到一次可信证明**：主角独自完成了不可能的操作、身份由可信私人场景确认、判断获得可见结果，或规则已通过简单演示验证。

区别：
- “主角自称天下第一”：可能只是吹牛，属于承诺，不是事实证明。
- “观众已经看到主角解开无人可解的封印”：能力可信，外界仍可不知道。
- “观众看到主角确实获胜，公开登记却异常”：真相稳定，等待的是承认与解释。

复杂大阴谋可以晚揭晓，但当前爽感契约要有可相信的支点。不要同时隐藏主角是谁、要什么、能做什么、对手为何阻拦以及胜负判据。

## 4. 角色分工：不需要人人一样傻

| 角色功能 | 真正在推动什么 | 行为要求 |
|---|---|---|
| 挑衅者 | 把误判转成实际阻碍 | 能阻止入场、扣下署名、发起复核等，不只骂人 |
| 利益绑定者 | 明明动摇仍加码 | 输了会丢代理权、资源或面子，因而换理由而非失忆 |
| 半懂的专业者 | 让反证暂时显得可信 | 说对局部、漏掉关键条件，不能忽然什么都不懂 |
| 摇摆者 | 给观众提供“快揭晓了”的场内信号 | 每次转向绑定新信息或利益变化，并做一个动作 |
| 稳定见证者 | 保存道德/事实标尺 | 可以只信证据，也可以提前信任主角；不要随全体失忆 |
| 权威验证者 | 把结果变成公共事实 | 只能验证已发生的行动，不能包办主角本应完成的胜利 |
| 主角 | 主动选择兑现的方法与时机 | 不是被辱骂到最后等一个大人物救场 |

短篇可合并角色。一个地点三四人就能表现风向，不为“群众戏”强加几十个有脸角色。

反派可以傲慢、愚蠢、可笑。要求不是“每个反派都高智商”，而是**错误要有稳定来源**：阶层偏见、过时情报、局部经验、虚荣、身份冒领、利益捆绑。若已听懂最终证据，后续只能认输、嘴硬、谈条件或换策略，不能回到完全不知道。

## 5. 墙头草不是一句“众人震惊”，而是可见的风向指针

这里的“群众”指**剧中旁观者**，不是屏幕外真实观众。剧中群众可以判断错，屏幕外观众不必被迫跟着失忆。

他们可以承担四项功能：
1. **预告揭晓**：先有人收回嘲笑、改称呼、主动让路，让观众以为正式承认马上发生。
2. **放大假反证**：新证据被反派解释后，原本想靠近的人又停下，暂时延迟完整认可。
3. **把立场变成赌注**：转单、撤椅、归还物件、签下复核条件。最终翻转有东西可兑现。
4. **记录变化**：结算时，先前拿走的椅子被正式摆回；人群让开的不是临时通道，而是主角真的获得了席位。

不要让所有人同时左右转。给两三个人不同依据：认成绩的人、看权力的人、算利益的人。可以有一个始终支持的人，也可以有一个早早安静下来的人。

### 风向动作词库

撤回正在递出的名片；把预留席卡翻过来；从堵门改为扶门；关掉起哄扩音器；重新打开订单页面；把手机从嘲拍转为认真记录；称呼从“喂”变成职业头衔；把搬走的工作台搬回来；主动退还署名牌；让出操作位置；把自己的作品放到主角面前请教。

挑与利益、情境匹配的动作。群众不必都跪下，更不必每次喊同一句台词。

## 6. 一轮有效拉扯：保住事实，让形势有变化

基础单元：

`观众知道真相 → 对手基于误判设置障碍 → 主角行动 → 证据/信号出现 → 一部分人转向 → 新反证或新利益阻碍出现 → 主角采取不同动作 → 更强证据与实质兑现`

这不是每次都必须凑满的八拍公式。短集只用其中几拍；有时第一次出现证据就直接兑现，避免观众学会“只要来人就肯定还不揭晓”。

每次反向变化至少改变一项：**新信息、风险承担、公开范围、实际权限、人物选择、兑现规模。**若删掉这一轮，后面完全不受影响，它多半是在拖。

同时留下至少一项不会随风向清零的进展：已经救下的人、已拿到的物品、完成的测试、录下的证据、被一个可信人物确认的事实、主角夺回的操作权。

## 7. 三种“还没彻底翻盘”，不要混为一谈

**有效反转**：新的证据/选择使处境真正改变。例如证实主角完成工作，但发现别人已占有成果；下一步转为夺回归属，不再重复证明“会不会做”。

**有效延迟**：兑现条件尚未满足，但正在前进。例如现场修复已成功，复核会在本集结尾完成；中途真正恢复服务并拿回工作权限。

**空转打断**：权威连说三次“这位就是……”都被来电或新角色打断，主角一直什么也不做，公开认知也不变。默认删除或合并。

一次喜剧式打断可以好玩；连续拉扯也可以成立。不要把“不能空转”误写成“绝不允许延迟或多重反转”。重点是每轮有内容、有代价、有进展。

## 8. 十二种变化机制，不只“更大的领导来了”

| 机制 | 反向变化从哪里来 | 如何可信地兑现 |
|---|---|---|
| 证据真、解释错 | 数据真实，但对手把非常规成功解释成作弊 | 回到提前展示的胜负判据，公开验证另一种完成路径 |
| 成果真、归属错 | 众人承认作品优秀，却认错作者 | 创作过程、历史痕迹与当场复现共同证明 |
| 权限真、范围被误读 | 临时许可被当成全部身份 | 展示事先存在的更高权限或不同管辖范围，不临时升级 |
| 资格真、执行受阻 | 已证实有资格，对手转而卡交付 | 改为谈条件、履行约定或替代执行；不倒退成“不配” |
| 旧记录与新事实 | 名册过期、旧版本评分不适用 | 有来源的更新与实际验证配合，而非随口说系统错了 |
| 认错对象 | 来人举动被群众误解为支持冒领者 | 来人的完整行动与先前线索吻合，不靠故意省略主语作弊 |
| 反派强行加码 | 对手为避免当场认输主动提高复核条件 | 提前固定双方都接受的标准，主角在更大范围证明自己 |
| 成功标准太低 | 众人以为只是一次合格，其实达成了另一项成就 | 提前埋更高级标准；先兑现基础成功，再公布额外成就 |
| 群众先知、对手嘴硬 | 旁观者先看懂，挑衅者已经失去支持却未发现 | 用空出来的位置、撤走的同伴等行为让主角无需自夸 |
| 专家分歧 | 两名专业者依据不同范围的信息作判断 | 用一次有明确判据的测试统一范围，不只比头衔 |
| 主角主动暂停揭晓 | 主角先保护人、完成取证或履约 | 暂停有收益，主角继续行动，且在约定节点兑现 |
| 身份并非最大底牌 | 身份被确认，观众又发现能力/贡献比身份更重要 | 扩张认知而非撤销已确认身份，产生新的可见结果 |

只因换了名片、证件、电话、来人而重复同一轮，不算四种机制。批量创作应更换**疑点本身与证明方式**。

## 9. 反转阶梯：不要在同一个问题上无限打转

可用的阶梯：

`你有没有能力？ → 这件事是不是你做的？ → 你的方法为什么有效？ → 成果归谁？ → 谁必须兑现此前承诺？ → 这次成功会改变什么？`

不是每部都走六级，也不应让所有疑问同时出现。只在前一级真的解决后进入下一层。尤其不要已确认身份后又让同一批人集体质疑相同证件。

另一条适合强者的阶梯：

`观众知道能赢 → 对手不知 → 小范围证实 → 对手主动把舞台扩大 → 更广范围获知 → 名望与资源改变 → 对手改用知情后的新策略`

**人物可以低估主角的上限，不能无理由忘记主角已展示的下限。**

## 10. 控制拉扯长度：参数，不是平台定律

在 brief 的 `narrative_controls` 中选择：

| 参数 | 可选值 / 默认 | 意义 |
|---|---|---|
| `reveal_mode` | `auto / off / known_truth / partial_truth / mystery`；默认 auto，按任务选择 | 是否启用这套信息结构 |
| `reveal_intensity` | `light / balanced / high`；默认 balanced | 反复改判在整体中的比重 |
| `setback_budget_per_arc` | 默认 2 | 提醒一次小揭晓弧中有几轮真正受阻，不是绝对上限 |
| `payoff_deadline_episode` | 必须按具体承诺填写 | 何时让这一轮的旧问题结束 |
| `must_preserve_payoffs` | 状态/事实 ID 列表 | 后续拉扯不可无理由抹除哪些成果 |
| `crowd_scale` | `none / small / distributed / mass` | 按预算和题材表达公众反馈 |
| `humiliation_level` | `none / low / medium / high`；默认 low | 不把所有等待都写成辱骂 |

本包的 brief schema 支持可选 `narrative_controls` 对象，模板已附默认值。`auto` 表示按题材与用户要求选择，不自动强塞误判打脸。明确开写一轮揭晓弧时应填写具体兑现集；未启用时可为 null。详细规划另保存在 `reveal-arcs/`，不要把规划字段直接念成剧中对白。

默认一次小弧 0–2 轮实质受阻；高拉扯可超过 2 轮，但必须逐轮写清新增内容和保留回报。同一揭晓跨集时，前集仍应有实质进展。用户明确要一集接一集拉扯，可按要求增强；不要因此把整个系列锁死在同一场宴会或同一次身份核验。

隐藏身份可以贯穿全季，前提是每集另有局部成果，并且没有每集虚假承诺“马上正式揭晓”。

## 11. 主角为什么不马上说清：必须有可见答案

可选：说了暂时无效，直接测试更快；要先完成救援而非争头衔；需要让对手自己确认标准；只愿公开当前问题所需的信息；身份暴露会影响某个已建立的任务；在履行一个观众知道的约定；决定不参加羞辱性自证并用另一条路径达成目标。

关键是主动性：**不解释可以，不做事不可以。**不要让主角为了“装”而放任原本可以轻松避免的无辜伤害。也不需要给每个无敌主角强加苦衷；“这件事用本事完成比争论更省事”足够。

三项检查：为什么当前证明不足？为什么下一步能更好证明？为什么主角选择它而不是更简单的方案？三项说不通，就缩短拉扯。

## 12. 真正兑现必须有结算，不止一句头衔

完整结算至少包含：

**事实坐实 + 公开认知改变 + 主角得到具体结果。**

按题材可再加：对手承担此前主动加码的后果、盟友的信任得到回应、群众的行为回响、已许诺资源或自由真正到手。

让结算规模匹配等待：只等了十秒，可以是一个人让路；围绕一项关键成就拉了三集，不能只给旁白“大家服了”就结束。也不要对一个轻微误判安排不成比例的残酷报复。

结尾可以留在：“资格确认、奖励到账；这项资格让主角接触到一个新任务。”不要停在：“负责人刚要宣布名字——下集再说。”偶尔身份揭晓可以作为悬念，但下一集要按期给出答案。

## 13. 从这套机制派生不同题材

- **游戏/升级**：非常规首通被误判；重验后获得独立成就，物品与建造权限真的到手。
- **技艺/职场**：专业方案有效却被归给别人；公开复现并拿回署名、合作权或选择权。
- **修仙/玄幻**：众人只会用旧试炼衡量新方法；验证后不仅晋阶，还改变师门的修行路径。
- **悬疑/判断**：主角的解释先不被信；旧证据在新范围内被重读，验证结论后打开下一条线索。
- **经营/建设**：被认为会亏损的安排先表现为异常；交付结果证明其合理，客户实际选择主角。
- **亲情/关系**：一个人的贡献被误认成冷漠；事实逐步显现，回报是认真道歉和行为改变，不一定是财富身份。
- **喜剧/日常**：普通人误把真正懂行的人当外行；最后反应是尴尬、重新分工或真诚请教，不必上升为权力惩罚。
- **团队/群像**：功劳不属于某个明星而是被忽略的协作者；结算把名字与选择权还给真正完成工作的人。

也可以反向使用：所有人都以为主角藏着大身份，其实主角没有后台，只是真能做好。先与用户的情绪承诺一致，不能把其明确要求的“真强者”擅自改成骗子。

## 14. AI 的实际生成步骤

1. 用一句话写出：观众知道什么、哪几个人不知道、观众最想看到谁改变什么行为。
2. 定义事实真相与可靠早期证明；区分身份、能力、正误、归属和权利。
3. 先写最终兑现：证据、台词、动作、收益，以及旧问题在哪里结束。
4. 倒推必要阻碍；删除不改变后续的轮次。
5. 为每名旁观者写“初始看法—转向依据—可见行动—最终后果”，不要统一复制。
6. 在每轮标出主角行动、新信息、不可撤销进展和新的未决问题。
7. 写成正文，不把上述规划字段当对白念出来。
8. 接回系列状态：谁现在知道了什么、仍有哪些人未接触证据、对手之后必须如何改变策略。

结构化规划可用 `assets/templates/reveal-arc.json`；运行 `check-reveal` 检查引用、状态顺序、兑现保存和计划截止等显式字段。工具不理解“证据是否真正可信”，不能替代上述审稿。

## 15. 反例与修复

| 坏写法 | 改法 |
|---|---|
| “你算什么东西”循环六次 | 只留一次挑衅，后面用资格、归属、执行中的不同问题推进 |
| 群众每十秒整齐变脸 | 两三个人依据不同信息转向，用物件和决定表现 |
| 观众已经看见最终证据，作者又说那段不算 | 保留证据，改变它尚未解决的问题；或从一开始把证据可靠性设为疑问 |
| 主角一直沉默，等大人物证明自己 | 给主角实际任务与自证选择；权威只负责验证 |
| 首通奖励反复撤回、失效、重置 | 保留已得奖励，后续争论认证或新权益，而非取消旧胜利 |
| 每集来一个更大的官 | 改成复现、对照、交付、结果使用、对方亲自确认条件等不同证明方式 |
| 对方已经相信却仍写“完全不知” | 分开内心判断与公开嘴硬，动机写清，后续策略更新 |
| 大结算只写“众人震惊” | 身份牌归位、署名更正、奖励入账、选择权兑现，至少给一个结果 |
| 因为用户要爽而不让主角遇到任何有趣阻力 | 主角的事实优势保持稳定，方法、公开解释、收益规模仍可有变化 |
| 为了显得高级完全删除群众和打脸 | 保留用户想要的风向与兑现，只修掉空转，不否定题材乐趣 |

## 16. 与其他模块如何组合

它是增强器，不是所有剧必须套用的总结构。和升级组合时，新能力要实际使用；和社会认可组合时，认知要留下世界反馈；和无敌组合时，冲突从“打不打得赢”转向“怎样赢、谁知道、赢了改变什么”；和批量生成组合时，限制重复的指控—证据—围观—结算链。

最终自问：**观众是在期待一个越来越值得看的兑现，还是只是在等作者终于允许角色把一句话说完？**
