# 6 审片与剪辑：预演 → 审片 → 配音 → 剪辑 → 成片终验

阶段 G2、I、J 读本文件。SKILL.md 的五条硬规则优先于这里任何一条；本文件只写怎么执行。实拍踩过的错见 [错误表.md](错误表.md)，生产开工前读一遍。

## 1. 为什么这样审（2026-09-27 EP001）

60 镜全部机械门和审查通过，用户一看：三只手、同一人出现两次、身体穿过桌子、在场的人突然消失。原因是审片只看缩小的 2fps 网格接触表就放行。所以从现在起：

- **网格只用来找可疑处，不能用来放行。** 放行只认单张原图。
- **放行要两边都过**：主会话逐帧写审片记录，独立子代理看同一批帧只找硬伤；任一边报硬伤就不放行。
- **交付前从头看完粗剪**，三句话复述剧情。

## 2. 放行只分三档

起始帧、视频、成片都按这三档判，不再细分：

- **硬伤，必须处理**：人数错（多人、少人、同一人出现两次）、身份错（认不出是谁）、多手少手或手不连着身体、身体穿过桌椅门墙、在场的人凭空消失或已离场的人又出现、物件比例明显错、画面出字、必拍事实没拍到、关键动作没发生或方向反了、台词错或多出剧本外人声。
- **小瑕疵，记一句直接放行**：构图偏一点、景别差一档、光和细节不完美、背景陈设有出入但读得出是同一地方。记录里写「放行（小瑕疵：…）」。
- **其余不管**：不写，不开修订。

画质（清晰度、噪点、质感）不是重拍理由；但上面列的硬伤都是内容缺陷，不能当画质放过。

**失败两次就简化镜头**：同一镜连续两次硬伤，第三次不许原样重抽或只改提示词，改成模型画得出的拍法：少人、少手、多人改单人、桌面多手动作改单手插入镜或删掉用台词和反应带过、复杂机位改回已通过的机位。简化后仍失败，这一镜标 weak 继续往下做，最后单列汇报给用户。承担必拍事实或关键情节的镜不能 weak，只能改分镜或回剧本改事实（见 §5.3）。

## 3. G2 预演（视频提交前）

起始帧全部目检通过后、提交视频前（金丝雀镜除外），用起始帧拼一条带临时对白的粗剪：

```bash
python3 $S/review_tool.py animatic <项目> <EP> [--no-tts]
```

产出 `审查/<EP>-预演.mp4`、`.jpg`（1fps 接触表）、`.md`。每镜按计划取用时长排，台词按计划时点出现，音轨依次取已有配音 → 本地 `say` 临时读稿（文件名带 temp，不进成片）→ 估算时长静音；画面角标镜号、动作起止、反应拍、必拍事实 ID。

由没写这集分镜的子代理看预演，按时间看完后在 `<EP>-预演.md` 回答：

1. 三句话复述剧情；主角是谁、在哪、核心设定是什么、她要什么，开场 30 秒内能不能读出来。
2. 每条必拍事实在哪一镜第几秒看得到（「## 必拍事实」表一条一行）。只靠台词或看不到，都回 E 或 G 改。
3. 每个关键物品和新人物从哪来、每个事件的起因在哪一镜。
4. 每场是不是一个空间：在场的人要么在画里，要么清楚地在画外某侧；有没有突然换场景的感觉。
5. 有没有台词说不完就切走、重要信息后没有反应拍。
6. 闪回闪前能不能一眼分清时间，因果有没有读反。

答完把首行「结论：待填」改成 PASS 或 REVISE。`预演指纹` 和 `预演输入指纹` 两行不删不改；改过分镜或重出起始帧后脚本会判预演失效，要重跑 animatic 重看。预演查不了动作会不会真的生成出来，那由 §5 审片把关。

## 4. 审片工具

| 工具 | 用途 |
|---|---|
| `frame_dump.py <项目> <EP> [SID ...] [--fps 1]` | **放行依据**。把每镜所选 take 按每秒一帧导出单张图到 `审查/<EP>-frames/<SID>_t<N>/f_00.jpg…`，逐张看 |
| `review_tool.py sheets` | 2fps 网格接触表，只找可疑处 |
| `review_tool.py asr` | ASR 逐字比对剧本，标删、增、替换、否定和数量差异，列出 `extra_vocal_segments`（台词窗外的人声）和 `voice_mismatch`（音高与角色性别明显不符） |
| `review_tool.py motion` | 运动能量曲线，辅助定动作起止和镜内跳切 |
| `review_tool.py mark` | 把结论、取用区间、证据写进 `审查/<EP>-review.json` |

短暂接触（递物、抓手、碰撞）一秒一帧可能漏掉，可疑段用 `--fps 4` 对那一镜再导一次。

## 5. I 审片

### 5.1 主会话逐帧审

对每镜所选 take 跑 `frame_dump.py`，**逐张看单帧原图**，每镜写一条记录（模板见 §5.2）。每镜必答五件事：

1. **人数**：画里几个人，各是谁；有没有同一人出现两次。
2. **手**：每只看得见的手属于谁；有没有第三只手、没有身体的手。
3. **穿模**：身体、手、道具有没有穿过桌子、椅子、门、墙。
4. **在场者**：本场此刻该在的人是不是都在画里或清楚在画外某侧；有没有人在两帧之间凭空消失或出现；已离场的人有没有回来。和上一镜末帧逐人对账。
5. **出字**：画面里有没有字、乱码、烧入字幕。

另外核对：职责动作有没有发生、在第几秒；必拍事实（`must_show_ids`）逐条看到没有，数量类逐个数；说话时谁的嘴在动。

### 5.2 逐帧审片记录模板

写进 `审查/<EP>-审片.md`，一镜一段：

```markdown
### EP001-S05 · take 2 · 帧目录 审查/EP001-frames/EP001-S05_t2/（共 6 帧）
在场名单：林晚、林砚、母亲（母亲在画外左侧，f_00 可见其肩）
| 帧 | 人数 | 手（归属） | 穿模 | 在场者 | 出字 |
|---|---|---|---|---|---|
| f_00 | 2（林晚左、林砚右） | 4：林晚双手在碗边，林砚左手持筷、右手在桌沿 | 无 | 母亲肩在画左 ✓ | 无 |
| f_03 | 2 | 4，同上；林砚右手抬起 | 无 | ✓ | 无 |
职责动作：林砚放下筷子，2.1–2.8 秒
必拍事实：MS2 碗里只剩一个饺子 ✓（f_04 数得 1 个）
说话：0.5–2.0 秒只有林晚嘴在动，林砚侧脸闭嘴
结论：放行 / 放行（小瑕疵：景别偏宽一档） / 硬伤：f_03 林砚身后多出一只手 → 重拍
```

每帧都要有一行；「看过无问题」「9/9 过」这类套话按没审算。

### 5.3 独立审片子代理

主会话写完一批记录后，派一个没参与分镜和审片的子代理看**同一批帧目录**，只找硬伤。它不看主会话的记录、不看剧本和提示词（避免被"应该是什么"带偏），只拿每镜的在场名单。用 `isolated_agent.sh <项目> <任务书> reviewer` 派发，任务书模板：

```markdown
# 独立审片任务：<EP> 第 <N> 批

你是审片员。只看图，找会让观众一眼看出毛病的硬伤。不评价构图、光线、画质、表演。

## 要看的帧
逐个目录、逐张打开，不许只看部分帧或缩略图：
- 审查/<EP>-frames/<SID>_t<N>/  在场名单：<谁、谁（谁在画外哪侧）>
- ……

## 只找这五类
1. 人数：人数和在场名单不符；同一个人在同一帧出现两次。
2. 手：多出的手、没有身体的手、手数和人数对不上。
3. 穿模：身体或手穿过桌子、椅子、门、墙。
4. 消失：在场名单里的人在某帧之后不见了（也不在画外可辨处），或名单外的人出现。
5. 出字：任何文字、乱码、字幕。

## 输出（写到 审查/<EP>-独立审片-<N>.md）
每镜一行：`<SID> | 看了几帧 | 无硬伤` 或 `<SID> | 看了几帧 | 硬伤：f_xx 具体是什么、在画面哪个位置`。
拿不准的也写出来，标「存疑」。不写修改建议。
```

两边结果对账：任一边报硬伤或存疑，主会话回到那一帧原图再看，确认是硬伤就处理；两边都过才 mark ok。子代理的原稿不改，主会话的判断另写。

### 5.4 mark 与剪辑准入

```bash
python3 $S/review_tool.py mark <项目> <EP> <SID> --video-take 2 --visual pass --continuity pass \
  --asr-ok true --listen-ok null --sync-ok null --speaker-face-ok true --must-show MS2=pass \
  --action-window 2.1 2.8 --speech-window 0.5 2.0 \
  --evidence "逐帧记录见 审查/EP001-审片.md#S05；独立审片 -1.md 无硬伤" --verdict ok
```

脚本强制的准入（缺了 `cut.py` 正式剪辑会拒绝）：

- `ok` 要求 `must_show_check` 全部 pass（`unverified` 和缺项按 fail）、有台词的镜 `speaker_face_ok` 为 true、`asr_ok` 为 true，且账本里有收回这个文件的记录、生成后提示词和起始帧没改过。
- 有动作职责的镜要写 `--action-window`，有台词的镜要写 `--speech-window`，都是这个 take 上实测的秒数，不照抄计划。
- `weak` 要写 `--acceptance-reason`；必拍事实承担镜和关键情节镜不能 weak。
- 换 take、重拍、改镜头后旧结论自动失效。

**剧情事实缺陷不许的放行理由**：「台词能解释」「字幕交代了」「观众数不出来」「take 用完了」「用户说全自动」。缺失的关键动作也不能靠拉长镜头、补旁白、加字幕或面板顶替。只有三条路：重拍、改分镜（换承担镜、加插入镜）、回剧本改这条事实并同步台词。

### 5.5 重审范围

重拍一镜后要重审：这一镜；起始帧取自它末帧的全部下游镜；同场前后相邻镜的连续性；该集预演和成片终验。其余媒体没变的镜沿用原结论。

### 5.6 常见缺陷怎么处理

| 缺陷 | 首次 | 复现后 |
|---|---|---|
| 画面出字 | 换 take | 查起始帧、参考图是否带字 |
| 多人、少人、认错人、多手 | 换 take | 重出起始帧，人数写死 `exactly N`；两次失败按 §2 简化 |
| 关键动作没发生 | 不原样重投，先派攻击子代理找提示词漏洞（rules-detail 11d），改完再投 | 改分镜：插入镜或双人同框 |
| 开头干等、结尾回弹 | 收紧入出点 | 可用段短于台词加落点才重投 |
| 镜内自己硬切 | 入点跳过切点 | 切点后内容不能用才重投 |
| 口型落在别人脸上 | 重投 | 画内其他人背身或出画 |
| 无台词镜自编人声 | 标 mute，用底噪补 | — |

原样重投同一请求以 2 次为限，再多先诊断。每镜最多 `max_takes`（默认 3）个 take。

## 6. 声音

### 6.1 三项分开记

- `asr_ok`：ASR 与剧本逐字对得上。必须是当前文件实际跑出来的结果。审片 ASR 跑两遍：正常一遍，再关 VAD、`condition_on_previous_text=False` 一遍专查台词前后多出来的乱语；取用区间内任何剧本外的人声都算 false。专名、关键能力词识别有分歧记 false 并写原文，交母语者听。
- `listen_ok`：情绪、口音、句尾语调、说话人对不对。**模型听不到声音，只能由真人签**（用户或用户指定的母语者），mark 时带 `--listener <人名>`。执行代理和子代理一律写 null，汇报写「未听审」；不用"听感"推翻 ASR，也不从 ASR 文本推断听感。
- `sync_ok`：口型与声音对齐；没核就是 null。

null 一律显示为「未验证」，任何汇总都不能写成「通过」。入剪要求 `asr_ok` 为 true；`listen_ok`、`sync_ok` 为 false 时拦下，为 null 时放行但处处标未验证。只有三项都是 true 才能说「声音通过」。

### 6.2 配音与心声

配音引擎由用户指定，不自选。送 TTS 前：

- 语言参数显式等于台词语言（MiniMax `language_boost` 等），不交给自动检测。
- 克隆参考音频是同语言母语者的对话口吻录音，不是朗读稿。
- 专名按 `drama.json` 的 `readings` 和 `dialogue[].reading` 校对；读错或整句被识别成别的语言直接不合格。
- 每句按 `dialogue[].emotion`（情绪·强度·语速·音量）选情绪参考或写 instruct；喊叫句要真喊，不只调大音量。
- 配音表（放 `配音/`）每句写：对谁说、上一句是谁说了什么、说话人此刻知道什么、这句要对对方达成什么。台词文字以剧本为准。

**心声**：剧本 `[VO]` 心声在 shots.json 标 `"vo": true`，视频模型不生成（可灵原生音频也按此关掉）。用用户指定的 TTS 生成单人干声到 `配音/<SID>_<n>.wav`（MiniMax 走 `providers.py`，job 的 `language_boost` 必填、`pronunciation` 传读音）；`cut.py` 没有专门的配音轨，用本镜 `sfx: [{"file": "配音/<SID>_<n>.wav", "at": <源素材秒>, "gain_db": 0}]` 挂进去（路径相对项目根，`at` 落在取用区间外会被丢掉），字幕照常取 `dialogue`。心声镜的画面是说话人闭嘴的反应，`speaker_face_ok` 按「画内所有人嘴闭着」判。

外部配音再对口型时：先配音、ASR 过了再送；脸高 ≥ 画高 1/5、偏转不超过约 30°、嘴部无遮挡才做，否则改背对或画外音；对口型后放大嘴部看 3 帧，牙齿发糊、整帧变糊或变脸就退回原片。

## 7. J 剪辑

### 7.1 取用与出点

`cut.py <项目> <EP>` 读 shots.json、review.json 和 ASR 缓存，按 `cut_order`（没有就按镜序）剪。

| mode | 出点 |
|---|---|
| after_last_word（有台词默认） | 末词结束 + 0.5 秒，不短于 review 的 out |
| action（动作镜） | 包住实测动作结束 + 0.2 秒和末词 + 0.3 秒 |
| fixed | review 里的 in/out，必须来自帧上看到的时间 |
| full（无台词默认） | 素材 − 0.2 秒 |
| to_end（留白结尾） | 末词结束 + 0.02 秒 |

- 入点剪掉开口前和动作前的干等，但不得落在台词里，包括句首语气词；入点 ≤ 首音 − 0.15 秒，出点 ≥ 末音 + 0.3 秒。要删语气词是改台词，回剧本。
- 动作晚于台词时保动作：台词说完多留一两秒，或成片后用 ffmpeg 做 L-cut（cut.py 不支持，命令写进剪辑单）。
- 节奏下限（`drama.json.pace`）：对白镜 ≥ 台词说完 + 0.8 秒且 ≥ 2.5 秒；反应镜 ≥ 1.5 秒；插入/冲击镜更短要写 `fast_cut_reason`；同场平均镜长 ≥ 2.5 秒。剪辑单会标出过短镜。
- 剪辑只取舍不改写：可以缩短、删镜、调顺序、换 take，不改台词、镜头职责和起止状态。
- 先看整集用 `cut.py <项目> <EP> --draft`，输出 `审查/<EP>-草剪.mp4`，不查准入，永远不算成片。

### 7.2 删镜与改剪点前的因果自检

动刀前逐条过，结果写在剪辑单末尾一行：

1. 每条 `must_show` 删改后还有哪一镜承担、在成片第几秒看得到；没人承担就不删。
2. 被删的镜是不是后面某镜的起因或物品来源；是的话起因改由谁交代，交代不了就不删。
3. 出点不早于已审动作结束。
4. 因删镜消失的台词逐句列出，它的信息由哪一句接住。

`drop` 的 note 写理由：文件缺失（回 H 收回）、质量不可用（回 E）、叙事取舍（写清信息由哪一镜接住）。

### 7.3 字幕与叠加

- 字幕文字逐字取剧本，只用 ASR 的时间；成片里没说出来的字不许留在字幕上。
- 中文每行 ≤16 字、日文 ≤13 字，最多 2 行；超了在 shots.json 拆成两句 `dialogue`。中文阅读速度 ≤ 每秒 9 字；每条显示 0.83–7 秒。
- 金额、数字、日期、专名、带单位数量不断行。
- 画面里不出字，所有字都在叠加层：`text`、`panel`（系统面板，主题在 `drama.json.overlays.panel`：`tech` / `xianxia` / `scroll`，预览用 `cut.py --panel-demo /tmp/panel.png --theme tech`）、`stamp`（印章字）。叠字不压脸，尤其眼部；超过 2 行（面板 3 行）分屏。cut.py 装了 OpenCV 会自动避脸，没装时剪辑单写「未做避脸」，要人看。
- AI 生成标识默认不加，用户明确要求才在 `drama.json` 写 `ai_label`。

### 7.4 声音设计

- 每场一条底噪（`drama.json.beds`），同场跨剪辑点连续；没配时 cut.py 只垫一层房间音保底。
- `sound` 字段写到的关键动作音效都落成 `sfx`；`audio_from` 垫画外声时，同场喊话写 `hall` 或 `none`，只有电话用 `phone`，隔门墙用 `glass`。
- 配乐 cut.py 不做，成片后用 ffmpeg 另混，对白处 `sidechaincompress` 压低 8–12 dB，cue 表和整条命令写进剪辑单。
- 响度归一到 −16 LUFS；真峰 ≤ −1 dBTP，在 AAC 成片上实测。低于 −50 dBFS 的静音窗口 ≤ 5%。片尾停帧拖尾 ≤ 0.3 秒。
- 接镜色彩差明显时用 `hub_tool.py measure` 量、`审查/<EP>-grade.json` 写校正、`hub_tool.py grade` 出 `_graded` 版。

`剪辑单.md` 由 cut.py 自动写；cut.py 之外做过的每一步（L-cut、白光、配乐、调色）在末尾写一行带整条命令，让成片可复现。

## 8. 交付前：粗剪通看与成片终验

### 8.1 从头到尾看一遍粗剪（硬规则 5）

按时间线看完整集，写进 `审查/<EP>-成片终验.md` 的「复述」节：

1. **三句话复述剧情**。复述不出，或某处"突然换场景""台词莫名其妙"，回到出问题的阶段改，不把粗剪当成品交。
2. 只看画面加字幕，每个情节点写「看得到 / 只靠字幕 / 看不到」和成片第几秒；动作、事件、起因类只靠字幕或看不到，不能 PASS。
3. 每个关键物品、新人物的来源，每个事件的起因，在成片第几秒。

### 8.2 成片终验

```bash
python3 $S/hub_tool.py measure <项目> <EP> --write     # 时长、画幅、LUFS、真峰、静音占比，只报数字
python3 $S/final_qa.py <项目> <EP> [--video PATH]      # PASS 退出码 0，REVISE 退出码 2
```

`final_qa.py` 从最终 MP4 重新验：整片 ASR 与剧本逐句比对（字幕多于声音、疑似裁词、否定词和数字差异）、叠字断行与压脸、片尾停帧、响度与削波、关键能力词。写 `审查/<EP>-final-qa.json` 和 `.md`（脚本写，手改无效）。

模型再按模板 `assets/templates/成片终验.md` 写 `审查/<EP>-成片终验.md`，补脚本做不了的：

- 每条必拍事实按秒数抽一张单帧存 `审查/<EP>-final-qa/ms<ID>_<秒>.jpg`，写数出来的数或看见的动作。
- 每个剪辑点前后各一帧，查黑帧、白帧、半渲染帧、句中被切。
- 1fps 网格找可疑处，可疑格按秒数抽单帧看原图再判。
- 声音三项按 §6.1 写；真人听过后把 `listen_ok`、`sync_ok`、`listener`、`evidence`、`video_sha256` 写进 review.json 顶层 `final_qa` 再跑一次 final_qa.py。

**完成标准**：`final-qa.json` 结论 PASS、`delivery` 为 true（对 `成片/<EP>.mp4` 跑的）、sha256 等于当前成片，且 `成片终验.md` 首行「结论：PASS」。有排版、声音、切点、片尾类已知问题仍要交付时，写「结论：REVISE」并列已知问题表，附用户看过这张表后点到问题编号的原话（记进决策记录，`拍板人: 用户`）；拿不到就写「用户确认：待确认」，该集汇报为未交付。剧情事实类问题不能列进已知问题，只能回生产修。重剪、重调色后终验失效，要重跑。

汇报时分列「制作验收 / 声音验证 / 观众验证」：脚本 PASS 不代表真人听过或观众认可，没听审写未听审，没有观众反馈写观众未验证。
