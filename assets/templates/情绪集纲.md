# 情绪集纲

> 复制到 `项目开发/情绪集纲.md` 后填写。商业爽剧目标下，每集在扩写正文前先填齐这一行，创作者通过后再写剧本。
> 一集一行；每格写具体的动作、物件和人名，不写"关系紧张""矛盾升级"一类气氛词。方括号说明填写后删除。
> 方法见 references/story-engine.md（商业爽剧的情绪设计）。

## 主爽点与四问

- **主爽点类型**：【身份打脸 / 智斗复仇 / 能力碾压 / 资源升级 / 甜宠拉扯；只选一个主类型，辅类型另注】
- **观众替主角受什么气**：【具体到动作和物件】
- **观众盼着什么结果**：【当众打脸 / 夺回利益 / 让对方后悔 / 获得偏爱……写清落点是关系、位置还是认知】
- **主角凭什么能做到**：【身份 / 能力 / 证据 / 资源 / 信息差；观众何时先看见一角】
- **每轮兑现多少、留多少**：【填写】

## 填写检查

- 受气格能指出反派的可执行手段；写不出手段，就是主角在自己受气或作者在拖。
- 底牌格写清时点；观众先于反派知道是默认，反过来要注明放弃的是哪段期待。
- 主角行动格是动作不是功能："她放下笔说授权自己给"，不是"她夺回主动"。
- 反派失去格写不出来的集，说明整集只在受气：并入下一集，或补一次小兑现。
- 新问题格要从兑现本身长出来，不是新人物踹门。
- 交接事实格只写下一集第一场要用到的东西，含谁知道、谁还不知道。
- 能力规则、装置条款有变动，先改故事引擎或系列简报里的契约，再写进本表和剧本。

## 与 episode-map.jsonl 的对应

项目使用完整分集地图时按下表填，不重复维护两份：

| 情绪集纲 | episode-map 字段 |
|---|---|
| 受什么气 | `incoming_state` 与 `hook` |
| 底牌与谁先知道 | `information_release`（`audience_before` / `audience_after`） |
| 主角行动 | `objective` 与 `turn.trigger` |
| 反派失去什么 | `local_dramatic_result.state_change` |
| 兑现什么爽点 | `local_dramatic_result.goal_outcome` 与 `cost_paid` |
| 留下什么新问题 | `outgoing_pressure` |
| 交接事实 | `handoff_state` |
